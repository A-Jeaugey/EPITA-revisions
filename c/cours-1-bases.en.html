Part 1 Lecture 1: A New Language, Why C?

From Python to C

Interpreted or compiled
  • Interpreted language (Python, JavaScript, PHP): an interpreter reads the source code and runs it. No machine code is produced.
  • Compiled language (C, C++, Go, Rust): the source code is not run. The compiler uses it to produce machine code, an executable file that the processor launches directly.

C is low-level, fast and close to the hardware: it is used for operating systems, embedded systems, compilers and interpreters (Python's is written in C) and game engines. It gives you control of memory, but hides nothing.

A C program is a plain text file with the extension .c. The computer cannot run it as is: you have to compile it first.

hello.c 
#include <stdio.h>

int main(void)
{
    printf("Hello, C!\n");
    return 0;
}
Line by line
  • #include <stdio.h>: opens the input/output “toolbox”, where printf lives.
  • int main(void): the main function, the mandatory entry point of every program. It returns an int and takes no parameter (void).
  • printf("Hello, C!\n");: prints the text. \n is the newline: printf does not add one by itself. Every statement ends with ;.
  • return 0;: the program tells the system that it finished correctly.
  • The braces { } delimit a block: they replace Python's indentation.

Part 2 Lecture 1: Compiling and running · Practical 1

Compiling with gcc, reading an error

The cycle is always the same: write the file, compile, run. The practicals' command:

$ ls
hello.c
$ gcc -Wall -Wextra -Werror -std=c99 -o hello hello.c
$ ls
hello  hello.c
$ ./hello
Hello, C!
OptionEffect
-Wallenables the common warnings
-Wextraadds more (unused parameter, signed / unsigned comparison…)
-Werrorturns every warning into an error: the compilation fails
-std=c99follows the C99 standard (allows for (int i = 0; …))
-o hellonames the executable hello (otherwise: a.out)

The compiler guesses nothing. A ; is missing? The compilation stops, with a message giving the file, the line and the column:

#include <stdio.h>

int main(void)
{
    printf("Hello\n")
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 -o hello hello.c
hello.c:5:22: error: expected ';' before 'return'

With -Werror, simple slips become errors. A variable declared but never used, a parameter never read: the program no longer compiles.

#include <stdio.h>

int main(void)
{
    int lives = 3;
    printf("Hello\n");
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 -o hello hello.c
hello.c:5:9: error: unused variable 'lives' [-Werror=unused-variable]
cc1: all warnings being treated as errors

int heal(int hp, int amount)
{
    return hp + 10;
}

int main(void)
{
    return heal(1, 2) == 11 ? 0 : 1;
}

$ gcc -Wall -Wextra -Werror -std=c99 heal.c
heal.c:1:22: error: unused parameter 'amount' [-Werror=unused-parameter]
cc1: all warnings being treated as errors
In the graded practical
  • “The code MUST compile! Otherwise you will not receive a grade.” One variable left over after a trial is enough to lose everything.
  • Compile often, with exactly these options. Read the first error first: the following ones often come from it.
  • Error messages are your allies: they tell you where to look.
What gcc does, in three steps
  • Preprocessor: handles the lines starting with #. #include copies in the contents of the header file.
  • Compilation: translates each .c file into machine code. Syntax and type errors show up here.
  • Linking: assembles the compiled files and the standard library into a single executable. A function that is declared but defined nowhere gives undefined reference to (part 6).

Variables, types, printf

A variable has a type, written before its name, and this type never changes. You can declare and initialize it in one go, or in two steps.

int a = 5;    // declaration + initialization

int b;        // declaration
TypeForExample
intintegerint hp = 120;
chara character (a small integer)char c = 'A';
floatfloating-point numberfloat x = 2.5f;
 
#include <stdio.h>

int main(void)
{
    int level = 7;
    char grade = 'B';
    float speed = 2.5f;

    printf("level = %d\n", level);
    printf("grade = %c, code %d\n", grade, grade);
    printf("speed = %f\n", speed);
    printf("speed = %.1f\n", speed);
    printf("%d%%\n", 50);
    return 0;
}

Integer division

Between two ints, / gives the integer quotient and % the remainder. Even stored in a float, 3 / 4 is 0: the division is done first. Convert one operand first: (float)3 / 4, or write floating-point literals with f.

int a = 7;
int b = 2;
printf("%d %d\n", a / b, a % b);

float wrong = 3 / 4;
float right = (float)3 / 4;
printf("%.2f %.2f\n", wrong, right);
printf("%.2f\n", 3.0f / 4.0f);

$ ./div
3 1
0.00 0.75
0.75
Traps
  • The format must match the type: printf("%d\n", x) with x a float does not compile with the practicals' options (error: format '%d' expects argument of type 'int', but argument 2 has type 'double').
  • 'A' (single quotes) is a character, "A" (double quotes) is a string: they are not the same thing.
  • An uninitialized local variable holds an indeterminate value, and gcc does not always report it. Initialize your counters and your sums.
  • Do not compare two computed floats with ==: floating-point numbers are approximations. The practicals ask you to test intervals.

Part 4 Lecture 1: Conditions, switch · Practical 2: Control Flow

Conditions and switch

True and false are integers
  • 0 means false; any nonzero value means true.
  • A comparison (==, !=, <, <=, >, >=) is exactly 1 or 0.
  • AND: &&, OR: ||, NOT: !. The right-hand side of a && is not evaluated if the left-hand side is false.
int a = 5;
printf("%d %d %d\n", a == 5, a != 5, a > 3);
printf("%d %d\n", !0, !7);

$ ./truth
1 0 1
1 0

An if / else if / else chain runs the first branch whose condition is true, and only that one. The order of the tests is therefore part of the rule: put the special or urgent cases first.

#include <stdio.h>

void describe_hp(int hp, int max_hp)
{
    if (hp <= 0)
    {
        printf("KO\n");
    }
    else if (hp * 4 <= max_hp)
    {
        printf("critical\n");
    }
    else if (hp < max_hp)
    {
        printf("wounded\n");
    }
    else
    {
        printf("full\n");
    }
}

int main(void)
{
    describe_hp(0, 80);
    describe_hp(20, 80);
    describe_hp(50, 80);
    describe_hp(80, 80);
    return 0;
}

$ ./ladder
KO
critical
wounded
full
A yes / no function returns exactly 0 or 1

A comparison is already 0 or 1: you can return the expression itself.

#include <stdio.h>

int can_attack(int hp, int stamina)
{
    return hp > 0 && stamina >= 10;
}

int main(void)
{
    printf("%d\n", can_attack(5, 12));
    printf("%d\n", can_attack(0, 50));
    printf("%d\n", can_attack(5, 3));
    return 0;
}

$ ./yesno
1
0
0

switch chooses according to the value of an integer, when each value has a meaning (an action code, a status). Each case ends with break (or return); default handles all the other values.

#include <stdio.h>

void announce(int action)
{
    switch (action)
    {
    case 0:
        printf("Wait\n");
        break;
    case 1:
        printf("Attack\n");
        break;
    case 2:
        printf("Defend\n");
        break;
    default:
        printf("Unknown action\n");
        break;
    }
}

int main(void)
{
    announce(1);
    announce(2);
    announce(7);
    return 0;
}

$ ./switch
Attack
Defend
Unknown action
Three traps that gcc rejects with the practicals' options

Forgetting a break: execution carries on into the next case (the lecture shows it). With -Wextra -Werror, it does not even compile.

#include <stdio.h>

int main(void)
{
    int c = 1;
    switch (c)
    {
    case 1:
        printf("one\n");
    case 2:
        printf("two\n");
        break;
    }
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 sw.c
sw.c:9:9: error: this statement may fall through [-Werror=implicit-fallthrough=]
cc1: all warnings being treated as errors

= instead of ==: if (hp = 0) assigns 0 to hp (the condition is always false).

#include <stdio.h>

int main(void)
{
    int hp = 5;
    if (hp = 0)
    {
        printf("dead\n");
    }
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 hp.c
hp.c:6:9: error: suggest parentheses around assignment used as truth value [-Werror=parentheses]
cc1: all warnings being treated as errors

An if without braces over two lines: only the first line depends on the if. Course style: always braces, each on its own line.

#include <stdio.h>

int main(void)
{
    int hp = 50;

    if (hp <= 0)
        printf("KO\n");
        printf("Game over\n");
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 ko.c
ko.c:7:5: error: this 'if' clause does not guard... [-Werror=misleading-indentation]
cc1: all warnings being treated as errors
Independent ifs are not a chain

Two ifs in a row are both tested: several blocks can run. For a priority rule (“if…, else if…”), you need else if.

LoopWhen to use it

Counting iterations the practicals' model

How many days to save goal coins at per_day coins a day? Edge cases first: nothing to do, or impossible (otherwise, infinite loop).

#include <stdio.h>

int days_to_save(int goal, int per_day)
{
    if (goal <= 0)
    {
        return 0;
    }
    if (per_day <= 0)
    {
        return -1;
    }

    int days = 0;
    int saved = 0;
    while (saved < goal)
    {
        saved += per_day;
        days++;
    }
    return days;
}

int main(void)
{
    printf("%d\n", days_to_save(100, 30));
    printf("%d\n", days_to_save(90, 30));
    printf("%d\n", days_to_save(0, 5));
    printf("%d\n", days_to_save(50, 0));
    return 0;
}

$ ./days
4
3
0
-1

Without a loop: (goal + per_day - 1) / per_day rounds the division up (100 / 30 gives 3.33, so 4 days).positive integers

Traps
  • A variable declared in a block only exists in that block (its scope). The i of for (int i = 0; …) no longer exists after the loop.
  • A zero step, or a step in the wrong direction, makes an infinite loop: test these cases before the loop.
  • < or <=? Check the first and the last iteration by hand.

Part 6 Lecture 1: Functions, Header Files · Practicals 1 and 2: includes/, answers/

Functions, prototypes, header files

A function has a return type, a name, typed parameters and a body. void: it returns nothing. Parameters are copies: changing a parameter does not change the caller's variable. To “change” a value, you return the new one.

#include <stdio.h>

void reset(int x)
{
    x = 0;
    printf("in reset: %d\n", x);
}

int heal(int hp, int amount, int max_hp)
{
    hp = hp + amount;
    if (hp > max_hp)
    {
        return max_hp;
    }
    return hp;
}

int main(void)
{
    int hp = 30;

    reset(hp);
    printf("after reset: %d\n", hp);
    hp = heal(hp, 50, 60);
    printf("after heal: %d\n", hp);
    return 0;
}

$ ./copy
in reset: 0
after reset: 30
after heal: 60
Every non-void function returns something, in every case 
int sign(int x)
{
    if (x > 0)
        return 1;
    else if (x < 0)
        return -1;
}

int main(void)
{
    return sign(3) == 1 ? 0 : 1;
}

$ gcc -Wall -Wextra -Werror -std=c99 sign.c
sign.c:7:1: error: control reaches end of non-void function [-Werror=return-type]
cc1: all warnings being treated as errors

A function must be declared before it is called. Its declaration, or prototype, is its first line followed by a ;: int add(int a, int b);. Without it:

#include <stdio.h>

int main(void)
{
    printf("%d\n", add(3, 4));
    return 0;
}

int add(int a, int b)
{
    return a + b;
}

$ gcc -Wall -Wextra -Werror -std=c99 main.c
main.c:5:20: error: implicit declaration of function 'add' [-Werror=implicit-function-declaration]
cc1: all warnings being treated as errors

When the program grows, you split it into several files: the declarations in a .h header file (the toolbox), the definitions in a .c, and every file that uses them includes the header.

tools.h 
#ifndef TOOLS_H
#define TOOLS_H

int clamp(int value, int low, int high);

#endif
tools.c 
#include "tools.h"

int clamp(int value, int low, int high)
{
    if (value < low)
    {
        return low;
    }
    if (value > high)
    {
        return high;
    }
    return value;
}
main.c 
#include <stdio.h>
#include "tools.h"

int main(void)
{
    printf("%d\n", clamp(120, 0, 100));
    printf("%d\n", clamp(-5, 0, 100));
    printf("%d\n", clamp(42, 0, 100));
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 main.c tools.c -o clamp
$ ./clamp
100
0
42
To remember for the practicals
  • #include <stdio.h>: standard header; #include "tools.h": local header, yours.
  • The header guard #ifndef / #define / #endif prevents including the same header twice. It is required in every .h.
  • In practical 2, each function has its header includes/name.h and its file answers/name.c, which includes its own header. The given prototypes are copied exactly.
  • Give all the .c files to gcc: forgetting tools.c gives a linking error, undefined reference to `clamp'.
