Partie 1 CM 1 : A New Language, Why C?

Du Python au C

Interprété ou compilé
  • Langage interprété (Python, JavaScript, PHP) : un interpréteur lit le code source et l'exécute. Aucun code machine n'est produit.
  • Langage compilé (C, C++, Go, Rust) : le code source n'est pas exécuté. Le compilateur s'en sert pour produire du code machine, un fichier exécutable que le processeur lance directement.

Le C est bas niveau, rapide, proche du matériel : on s'en sert pour les systèmes d'exploitation, l'embarqué, les compilateurs et interpréteurs (celui de Python est écrit en C), les moteurs de jeu. Il donne le contrôle de la mémoire, mais ne cache rien.

Un programme C est un simple fichier texte, d'extension .c. L'ordinateur ne peut pas l'exécuter tel quel : il faut d'abord le compiler.

hello.c 
#include <stdio.h>

int main(void)
{
    printf("Hello, C!\n");
    return 0;
}
Ligne par ligne
  • #include <stdio.h> : ouvre la « boîte à outils » des entrées-sorties, où se trouve printf.
  • int main(void) : la fonction main, point d'entrée obligatoire de tout programme. Elle renvoie un int et ne prend aucun paramètre (void).
  • printf("Hello, C!\n"); : affiche le texte. \n est le retour à la ligne : printf n'en ajoute pas tout seul. Chaque instruction finit par ;.
  • return 0; : le programme dit au système qu'il s'est bien terminé.
  • Les accolades { } délimitent un bloc : elles remplacent l'indentation de Python.

Partie 2 CM 1 : Compiling and running · TP 1

Compiler avec gcc, lire une erreur

Le cycle est toujours le même : écrire le fichier, compiler, exécuter. La commande des TP :

$ ls
hello.c
$ gcc -Wall -Wextra -Werror -std=c99 -o hello hello.c
$ ls
hello  hello.c
$ ./hello
Hello, C!
OptionEffet
-Wallactive les avertissements courants
-Wextraen ajoute d'autres (paramètre inutilisé, comparaison signé / non signé…)
-Werrortransforme tout avertissement en erreur : la compilation échoue
-std=c99suit la norme C99 (permet for (int i = 0; …))
-o hellonomme l'exécutable hello (sinon : a.out)

Le compilateur ne devine rien. Il manque un ; ? La compilation s'arrête, avec un message qui donne le fichier, la ligne et la colonne :

#include <stdio.h>

int main(void)
{
    printf("Hello\n")
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 -o hello hello.c
hello.c:5:22: error: expected ';' before 'return'

Avec -Werror, de simples maladresses deviennent des erreurs. Une variable déclarée mais jamais utilisée, un paramètre jamais lu : le programme ne compile plus.

#include <stdio.h>

int main(void)
{
    int lives = 3;
    printf("Hello\n");
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 -o hello hello.c
hello.c:5:9: error: unused variable 'lives' [-Werror=unused-variable]
cc1: all warnings being treated as errors

int heal(int hp, int amount)
{
    return hp + 10;
}

int main(void)
{
    return heal(1, 2) == 11 ? 0 : 1;
}

$ gcc -Wall -Wextra -Werror -std=c99 heal.c
heal.c:1:22: error: unused parameter 'amount' [-Werror=unused-parameter]
cc1: all warnings being treated as errors
Au TP noté
  • « The code MUST compile! Otherwise you will not receive a grade. » Une variable oubliée après un essai suffit à tout perdre.
  • Compile souvent, avec exactement ces options. Lis la première erreur d'abord : les suivantes en découlent souvent.
  • Les messages d'erreur sont tes alliés : ils disent où regarder.
Ce que fait gcc, en trois étapes
  • Préprocesseur : traite les lignes en #. #include recopie le contenu du fichier d'en-tête.
  • Compilation : traduit chaque fichier .c en code machine. Les erreurs de syntaxe et de type arrivent ici.
  • Édition de liens : assemble les fichiers compilés et la bibliothèque standard en un seul exécutable. Une fonction déclarée mais définie nulle part donne undefined reference to (partie 6).

Variables, types, printf

Une variable a un type, écrit avant son nom, et ce type ne change jamais. On peut la déclarer et l'initialiser d'un coup, ou en deux temps.

int a = 5;    // declaration + initialization

int b;        // declaration
TypePourExemple
intentierint hp = 120;
charun caractère (un petit entier)char c = 'A';
floatnombre à virgulefloat x = 2.5f;
 
#include <stdio.h>

int main(void)
{
    int level = 7;
    char grade = 'B';
    float speed = 2.5f;

    printf("level = %d\n", level);
    printf("grade = %c, code %d\n", grade, grade);
    printf("speed = %f\n", speed);
    printf("speed = %.1f\n", speed);
    printf("%d%%\n", 50);
    return 0;
}

$ ./types

La division entière

Entre deux int, / donne le quotient entier et % le reste. Même rangé dans un float, 3 / 4 vaut 0 : la division est faite avant. Convertis d'abord un opérande : (float)3 / 4, ou écris des littéraux à virgule avec f.

int a = 7;
int b = 2;
printf("%d %d\n", a / b, a % b);

float wrong = 3 / 4;
float right = (float)3 / 4;
printf("%.2f %.2f\n", wrong, right);
printf("%.2f\n", 3.0f / 4.0f);

$ ./div
3 1
0.00 0.75
0.75
Pièges
  • Le format doit correspondre au type : printf("%d\n", x) avec x un float ne compile pas avec les options des TP (error: format '%d' expects argument of type 'int', but argument 2 has type 'double').
  • 'A' (apostrophes) est un caractère, "A" (guillemets) une chaîne : ce n'est pas la même chose.
  • Une variable locale non initialisée contient une valeur indéterminée, et gcc ne le signale pas toujours. Initialise tes compteurs et tes sommes.
  • Ne compare pas deux float calculés avec == : les nombres à virgule sont approchés. Les TP demandent de tester des intervalles.

Partie 4 CM 1 : Conditions, switch · TP 2 : Control Flow

Conditions et switch

Vrai et faux sont des entiers
  • 0 signifie faux ; toute valeur non nulle signifie vrai.
  • Une comparaison (==, !=, <, <=, >, >=) vaut exactement 1 ou 0.
  • ET : &&, OU : ||, NON : !. Le deuxième membre d'un && n'est pas évalué si le premier est faux.
int a = 5;
printf("%d %d %d\n", a == 5, a != 5, a > 3);
printf("%d %d\n", !0, !7);

$ ./truth
1 0 1
1 0

Une chaîne if / else if / else exécute la première branche dont la condition est vraie, et elle seule. L'ordre des tests fait donc partie de la règle : on met les cas particuliers ou urgents en premier.

#include <stdio.h>

void describe_hp(int hp, int max_hp)
{
    if (hp <= 0)
    {
        printf("KO\n");
    }
    else if (hp * 4 <= max_hp)
    {
        printf("critical\n");
    }
    else if (hp < max_hp)
    {
        printf("wounded\n");
    }
    else
    {
        printf("full\n");
    }
}

int main(void)
{
    describe_hp(0, 80);
    describe_hp(20, 80);
    describe_hp(50, 80);
    describe_hp(80, 80);
    return 0;
}

$ ./ladder
KO
critical
wounded
full
Une fonction oui / non renvoie exactement 0 ou 1

Une comparaison vaut déjà 0 ou 1 : on peut renvoyer l'expression elle-même.

#include <stdio.h>

int can_attack(int hp, int stamina)
{
    return hp > 0 && stamina >= 10;
}

int main(void)
{
    printf("%d\n", can_attack(5, 12));
    printf("%d\n", can_attack(0, 50));
    printf("%d\n", can_attack(5, 3));
    return 0;
}

$ ./yesno
1
0
0

switch choisit selon la valeur d'un entier, quand chaque valeur a un sens (un code d'action, un statut). Chaque case finit par break (ou return) ; default traite toutes les autres valeurs.

#include <stdio.h>

void announce(int action)
{
    switch (action)
    {
    case 0:
        printf("Wait\n");
        break;
    case 1:
        printf("Attack\n");
        break;
    case 2:
        printf("Defend\n");
        break;
    default:
        printf("Unknown action\n");
        break;
    }
}

int main(void)
{
    announce(1);
    announce(2);
    announce(7);
    return 0;
}

$ ./switch
Attack
Defend
Unknown action
Trois pièges que gcc refuse avec les options des TP

Oublier un break : l'exécution continue dans le case suivant (le CM le montre). Avec -Wextra -Werror, ce n'est même pas compilé.

#include <stdio.h>

int main(void)
{
    int c = 1;
    switch (c)
    {
    case 1:
        printf("one\n");
    case 2:
        printf("two\n");
        break;
    }
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 sw.c
sw.c:9:9: error: this statement may fall through [-Werror=implicit-fallthrough=]
cc1: all warnings being treated as errors

= au lieu de == : if (hp = 0) affecte 0 à hp (condition toujours fausse).

#include <stdio.h>

int main(void)
{
    int hp = 5;
    if (hp = 0)
    {
        printf("dead\n");
    }
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 hp.c
hp.c:6:9: error: suggest parentheses around assignment used as truth value [-Werror=parentheses]
cc1: all warnings being treated as errors

Un if sans accolades sur deux lignes : seule la première ligne dépend du if. Style du cours : toujours des accolades, chacune sur sa ligne.

#include <stdio.h>

int main(void)
{
    int hp = 50;

    if (hp <= 0)
        printf("KO\n");
        printf("Game over\n");
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 ko.c
ko.c:7:5: error: this 'if' clause does not guard... [-Werror=misleading-indentation]
cc1: all warnings being treated as errors
Des if indépendants ne sont pas une chaîne

Deux if à la suite sont testés tous les deux : plusieurs blocs peuvent s'exécuter. Pour une règle par priorité (« si…, sinon si… »), il faut else if.

Compter des tours le modèle des TP

Combien de jours pour économiser goal pièces à per_day pièces par jour ? Les cas limites d'abord : rien à faire, ou impossible (sinon, boucle infinie).

#include <stdio.h>

int days_to_save(int goal, int per_day)
{
    if (goal <= 0)
    {
        return 0;
    }
    if (per_day <= 0)
    {
        return -1;
    }

    int days = 0;
    int saved = 0;
    while (saved < goal)
    {
        saved += per_day;
        days++;
    }
    return days;
}

int main(void)
{
    printf("%d\n", days_to_save(100, 30));
    printf("%d\n", days_to_save(90, 30));
    printf("%d\n", days_to_save(0, 5));
    printf("%d\n", days_to_save(50, 0));
    return 0;
}

$ ./days
4
3
0
-1

Sans boucle : (goal + per_day - 1) / per_day arrondit la division au-dessus (100 / 30 donne 3,33, donc 4 jours).entiers positifs

Pièges
  • Une variable déclarée dans un bloc n'existe que dans ce bloc. Le i de for (int i = 0; …) n'existe plus après la boucle.
  • Un pas nul ou dans le mauvais sens fait une boucle infinie : teste ces cas avant la boucle.
  • < ou <= ? Vérifie le premier et le dernier tour à la main.

Fonctions, prototypes, fichiers d'en-tête

Une fonction a un type de retour, un nom, des paramètres typés et un corps. void : elle ne renvoie rien. Les paramètres sont des copies : modifier un paramètre ne change pas la variable de l'appelant. Pour « changer » une valeur, on renvoie la nouvelle.

#include <stdio.h>

void reset(int x)
{
    x = 0;
    printf("in reset: %d\n", x);
}

int heal(int hp, int amount, int max_hp)
{
    hp = hp + amount;
    if (hp > max_hp)
    {
        return max_hp;
    }
    return hp;
}

int main(void)
{
    int hp = 30;

    reset(hp);
    printf("after reset: %d\n", hp);
    hp = heal(hp, 50, 60);
    printf("after heal: %d\n", hp);
    return 0;
}

$ ./copy
in reset: 0
after reset: 30
after heal: 60
Toute fonction non void renvoie quelque chose, dans tous les cas 
int sign(int x)
{
    if (x > 0)
        return 1;
    else if (x < 0)
        return -1;
}

int main(void)
{
    return sign(3) == 1 ? 0 : 1;
}

$ gcc -Wall -Wextra -Werror -std=c99 sign.c
sign.c:7:1: error: control reaches end of non-void function [-Werror=return-type]
cc1: all warnings being treated as errors

Une fonction doit être déclarée avant d'être appelée. Sa déclaration, ou prototype, c'est sa première ligne suivie d'un ; : int add(int a, int b);. Sans elle :

#include <stdio.h>

int main(void)
{
    printf("%d\n", add(3, 4));
    return 0;
}

int add(int a, int b)
{
    return a + b;
}

$ gcc -Wall -Wextra -Werror -std=c99 main.c
main.c:5:20: error: implicit declaration of function 'add' [-Werror=implicit-function-declaration]
cc1: all warnings being treated as errors

Quand le programme grandit, on le range en plusieurs fichiers : les déclarations dans un fichier d'en-tête .h (la boîte à outils), les définitions dans un .c, et chaque fichier qui s'en sert l'inclut.

tools.h 
#ifndef TOOLS_H
#define TOOLS_H

int clamp(int value, int low, int high);

#endif
tools.c 
#include "tools.h"

int clamp(int value, int low, int high)
{
    if (value < low)
    {
        return low;
    }
    if (value > high)
    {
        return high;
    }
    return value;
}
main.c 
#include <stdio.h>
#include "tools.h"

int main(void)
{
    printf("%d\n", clamp(120, 0, 100));
    printf("%d\n", clamp(-5, 0, 100));
    printf("%d\n", clamp(42, 0, 100));
    return 0;
}

$ gcc -Wall -Wextra -Werror -std=c99 main.c tools.c -o clamp
$ ./clamp
100
0
42
À retenir pour les TP
  • #include <stdio.h> : en-tête standard ; #include "tools.h" : en-tête local, à toi.
  • La garde #ifndef / #define / #endif empêche d'inclure deux fois le même en-tête. Elle est exigée dans chaque .h.
  • Au TP 2, chaque fonction a son en-tête includes/nom.h et son fichier answers/nom.c, qui inclut son propre en-tête. Les prototypes donnés se recopient à l'identique.
  • Tous les .c se donnent à gcc : oublier tools.c donne une erreur d'édition de liens, undefined reference to `clamp'.
