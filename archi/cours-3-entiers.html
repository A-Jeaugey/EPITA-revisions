Partie 1 cours § III.1

Bits, mots et octets

Un bit (contraction de binary digit) est la plus petite unité d’information qu’un ordinateur peut manipuler : il vaut 0 ou 1. Un mot est un groupe d’un ou plusieurs bits manipulé comme un tout. Sa taille, son nombre de bits, est fixe.

Chaque bit ajouté double le nombre de possibilités : un mot de n bits possède 2n combinaisons.

Tableau 3.1 — Nombre de combinaisons d’un mot (cours, p. 17)
Taille du motCombinaisons
1 bit2 : 0 et 1
2 bits4 : 00, 01, 10, 11
3 bits8 : 000, 001, …, 110, 111
4 bits16 : 0000, 0001, …, 1111
8 bits (un octet)256
16 bits65 536
n bits2n

Un octet est un mot de 8 bits : 256 combinaisons. Les microprocesseurs actuels manipulent des octets ou des groupes d’octets. La taille d’un « mot » dépend du contexte : pour un microprocesseur 68000, un mot fait 16 bits et un mot long 32 bits ; pour un ARM 32 bits, un mot fait 32 bits et un demi-mot 16 bits. Hors contexte, la taille d’un mot doit être précisée.

Le bit le plus à gauche est le bit de poids fort, ou MSB (Most Significant Bit). Le bit le plus à droite est le bit de poids faible, ou LSB (Least Significant Bit). Les bits d’un mot de n bits sont numérotés de 0 (le LSB) à n − 1 (le MSB).

Un mot en lui-même ne représente rien. Que vaut l’octet 1111 1111 ? Le nombre 255, le nombre −1, le nombre 0,72, le caractère ‘X’, une instruction, une couleur : tout dépend du contexte, c’est-à-dire de l’encodage choisi. Ce chapitre étudie deux encodages des entiers, non signé (partie 3) et signé (parties 4 à 6), puis trois autres codes (partie 8).

Par commodité, on écrit souvent un mot sous sa forme hexadécimale, un chiffre par paquet de 4 bits (chapitre 1, partie 8) : 1111 11112 = FF16. Un paquet de 4 bits s’appelle un quartet (en anglais nibble) ; le cours n’emploie pas ce mot, mais tu le croiseras ailleurs.

À retenir
  • Un mot de n bits : 2n combinaisons, bits numérotés de 0 (LSB, à droite) à n − 1 (MSB, à gauche).
  • Un octet : 8 bits, 256 combinaisons, deux chiffres hexadécimaux.
Piège : on compte à partir de 0

Dans un octet, le MSB est le bit 7, pas le bit 8 : la numérotation commence à 0. Pour la même raison, 8 bits donnent 256 combinaisons mais la plus grande valeur non signée est 28 − 1 = 255 : la première combinaison, 0000 0000, code 0.

Complément à un et complément à deux

Le complément à un d’un mot s’obtient en inversant chacun de ses bits : chaque 0 devient 1, chaque 1 devient 0.

Le complément à deux s’obtient en inversant chacun de ses bits, puis en additionnant 1 : c’est le complément à un plus un. Le cours le note C2 (…). Le résultat garde la taille du mot : une retenue qui sortirait à gauche est perdue. L’exemple du cours, un mot de 10 bits :

mot : 11 1001 10002
complément à un : 00 0110 01112
00 0110 01112 + 12 = 00 0110 10002
C2 (11 1001 10002) = 00 0110 10002

Dans le registre ci-dessous, appuie sur « Complément à deux » : il pose les deux étapes. Appuie une seconde fois : tu retrouves le mot de départ, car le complément à deux du complément à deux redonne le mot.

La méthode rapide du cours. On conserve les bits de poids faible, du LSB jusqu’au premier 1 inclus, et on inverse tous les autres.

Pourquoi ça marche

Dans le complément à un, les 0 situés à droite du premier 1 sont devenus des 1, et ce premier 1 est devenu un 0. Ajouter 1 remet ces 1 à 0 en propageant une retenue, qui s’arrête sur ce 0 et le remet à 1. Les bits situés à gauche ne bougent pas : ils restent inversés.

Piège : le premier 1 est conservé
  • Le premier 1 en partant de la droite reste un 1 : C2 (1011 1100) = 0100 0100. Inverser aussi ce 1 donne 0100 0011, qui est le complément à un.
  • Le complément à deux de 0000 0000 est 0000 0000 : 1111 1111 + 1 = 1 0000 0000, et la retenue sortante est perdue.

Le complément à deux sert surtout à encoder les entiers signés : c’est la partie 4.

Partie 3 cours § IV.1

Les entiers non signés

C’est l’encodage le plus naturel : le mot est l’écriture binaire du nombre, complétée à gauche par des 0 jusqu’à la taille du mot. Le nombre 1012 sur 8 bits non signés donne le mot 0000 0101.

Un mot de n bits possède 2n combinaisons, et la première code 0 : il représente les entiers de 0 à 2n − 1. Sur 8 bits, de 0 à 255.

Encoder : divisions successives

Les restes des divisions successives par 2 (chapitre 1, partie 6), lus de bas en haut, donnent 11 0010. On complète à gauche jusqu’à 8 bits :

5010 = 0011 00102

Décoder : la somme des poids

On additionne les poids des bits à 1 (chapitre 1, partie 5). Le mot de 6 bits du cours :

10 01102 = 32 + 4 + 2 = 3810

Le dépassement non signé. Les opérations se font sur des mots de taille fixe. Quand le résultat exact sort de l’intervalle 0 … 2n − 1, il ne peut pas être encodé correctement : c’est un dépassement non signé. L’exemple du cours, une addition sur 8 bits (les deux opérandes et le résultat sont sur 8 bits) :

Le résultat exact demande 9 bits : 1 0000 01002 = 260. Ce neuvième bit est la retenue : il ne tient pas dans le mot, il est ignoré. Le mot résultat est 0000 01002 = 4. Un programme C qui additionne deux variables unsigned char valant 250 et 10 affiche d’ailleurs 250 + 10 = 4.

L’incrémentation est cyclique. Ajouter 1 à 1111 1111 (255) donne 0000 0000 (0) : on repart au début. Retirer 1 à 0 donne 255. Sur 8 bits non signés :

255 + 1 = 0
0 − 1 = 255
250 + 10 = 4
4 − 10 = 250

La roue de la partie 4 montre ce cycle sur 4 bits. Le cours remarque aussi que le dépassement non signé s’appelle souvent retenue (carry) pour une addition et emprunt (borrow) pour une soustraction.

À retenir : repérer un dépassement non signé
  • Addition : dépassement non signé si et seulement si l’addition posée produit une retenue sortante, un (n + 1)e bit.
  • Soustraction a − b : dépassement non signé si et seulement si a < b en non signé. Le résultat exact serait négatif : la soustraction posée emprunte au-delà du MSB.
Piège : le mot s’écrit quand même

Après un dépassement, les 8 bits du résultat existent : 0000 0100. À l’examen, on écrit ce mot dans la colonne « Résultat binaire », et « ERREUR » seulement dans la colonne de la valeur décimale concernée.

Les entiers signés : plage et encodage

Pour les entiers signés, le cours étudie l’encodage le plus utilisé : le complément à deux. Les 2n combinaisons sont partagées en deux moitiés. Les mots dont le MSB vaut 0 codent les entiers positifs, ceux dont le MSB vaut 1 codent les entiers négatifs : le MSB s’appelle donc le bit de signe.

Un mot de n bits représente les entiers de −2n−1 à 2n−1 − 1 : de −8 à 7 sur 4 bits, de −128 à 127 sur un octet. La roue montre les 16 mots de 4 bits, avec la valeur non signée à l’intérieur et la valeur signée à l’extérieur.

Dans ce système, le complément à deux d’un mot représente l’opposé du nombre. Exemple du cours : 310 = 00112 et C2 (00112) = 11012 = −310.

Encoder un entier signé. Un entier positif s’encode comme un non signé. Pour un entier négatif :

  1. Convertir sa valeur absolue en binaire, sur n bits.

  2. Prendre le complément à deux de ce mot.

−17 sur 8 bits :
1710 = 0001 00012
−17 = C2 (0001 00012) = 1110 11112

À retenir
  • Sur n bits, on code 2n entiers non signés, et autant d’entiers signés.
  • Plus grand non signé : 2n − 1. Plus grand signé : 2n−1 − 1. Plus petit signé : −2n−1.
Piège : la plage n’est pas symétrique
  • −128 tient sur 8 bits signés (1000 0000), +128 non. On ne peut donc pas encoder −128 par « valeur absolue, puis complément à deux » : 128 n’est pas un positif sur 8 bits signés. Le calcul mécanique C2 (1000 0000) = 1000 0000 redonne quand même le bon mot.
  • Sujet 2021 : 8 192 = 213 demande 15 bits en signé, car 14 bits vont jusqu’à 213 − 1 = 8 191. Mais −8 192 = −213 tient sur 14 bits : c’est la plus petite valeur.
  • Complète à n bits avant le complément à deux. Sur 5 bits, C2 (1 0001) = 0 1111, et compléter ensuite par des 0 donnerait 0000 1111, c’est-à-dire 15. Sur 8 bits, il faut C2 (0001 0001) = 1110 1111.

Décoder un mot signé

La méthode dépend du bit de signe, le MSB :

  1. Bit de signe à 0 : l’entier est positif. On le décode comme un non signé, par la somme des poids.

  2. Bit de signe à 1 : l’entier est négatif. On prend le complément à deux du mot, on le convertit en décimal, et on place le signe moins devant.

L’exemple du cours, le mot de 6 bits 10 01102 : son bit de signe vaut 1.

C2 (10 01102) = 01 10102
01 10102 = 16 + 8 + 2 = 2610
10 01102 = −2610

Le même mot vaut 10 01102 = 3810 en non signé (partie 3) : le cours oppose exprès les deux lectures.

Pour contrôler (hors méthode du cours)
  • Un mot négatif de n bits vaut sa valeur non signée moins 2n : 38 − 26 = −26.
  • Autrement dit, le MSB pèse −2n−1 au lieu de +2n−1 : −32 + 4 + 2 = −26. Le registre de la figure 1 le rappelle quand tu cliques sur un bit.

En hexadécimal (TD 2, exercice 3). Le premier chiffre hexadécimal contient le bit de signe : un mot de 8 bits est négatif quand son premier chiffre vaut 8 ou plus (de 8 à F). Les mots qui codent les entiers positifs vont de 00 à 7F, ceux qui codent les négatifs de 80 à FF.

Soustraction par le complément à deux, dépassement signé

Puisque le complément à deux représente l’opposé, une soustraction peut être remplacée par une addition : a − b = a + C2 (b), à condition d’ignorer la retenue. L’exemple du cours, 115 − 62 sur 8 bits : 11510 = 0111 00112, 6210 = 0011 11102 et C2 (6210) = 1100 00102.

Les deux calculs donnent le même mot de 8 bits, 0011 01012 = 5310. L’addition produit une retenue, un neuvième bit : on l’ignore. Ainsi 115 − 62 = 115 + (−62) = 53.

Le dépassement signé. Comme pour les non signés, un résultat peut sortir de la plage −2n−1 … 2n−1 − 1 : c’est un dépassement signé. L’exemple du cours :

Le mot obtenu, 1000 0010, a un bit de signe à 1 : 1000 00102 = −126, alors que le résultat attendu, 130, est trop grand pour un octet signé (127 au plus). Le résultat erroné est négatif, alors que les deux opérandes sont positifs. Un programme C avec des variables signed char affiche 120 + 10 = -126. L’incrémentation reste cyclique, mais la coupure est entre 127 et −128 (le trait violet de la roue) :

127 + 1 = −128
120 + 10 = −126
−126 − 10 = 120

La règle des signes (TD 2, exercice 3). Le cours ne donne pas de règle pour repérer un dépassement signé ; le TD la fait construire, en comparant les signes des opérandes et du résultat. « Positif » veut dire MSB à 0, « négatif » MSB à 1.

La règle à retenir
  • Addition : dépassement signé seulement si les deux opérandes ont le même signe et que le résultat a l’autre signe (P + P = N, N + N = P). Deux opérandes de signes contraires ne dépassent jamais.

Retenue sans dépassement signé · sujet 2017

1000 1100 + 0111 1110 = 1 0000 1010

Retenue sortante : en non signé, 140 + 126 = 266 > 255, ERREUR. En signé, −116 + 126 = 10 : juste, le mot 0000 1010 vaut 10.

Dépassement signé sans retenue · sujet 2023

0110 1001 + 0110 1110 = 1101 0111

Pas de retenue : en non signé, 105 + 110 = 215, juste. En signé, P + P = N : 215 > 127, ERREUR.

Piège principal : la retenue ne dit rien du signé
  • La retenue sortante signale le dépassement non signé d’une addition, et seulement lui. Pour le signé, regarde les signes.
  • Dans une soustraction faite par a + C2 (b), la retenue ne signale même pas le dépassement non signé. Sujet 2023 : 1101 0011 − 1001 1111 devient 1101 0011 + 0110 0001 = 1 0011 0100, avec une retenue, alors que 211 − 159 = 52 est juste. Le dépassement non signé d’une soustraction, c’est a < b.

L’extension de signe

L’extension de signe augmente le nombre de bits d’un entier signé sans changer sa valeur : on recopie le bit de signe vers la gauche. Pour passer de 8 à 16 bits, le bit de signe du mot de 8 bits (le bit 7) est recopié dans tous les nouveaux bits, du bit 8 au bit 15.

Piège : compléter avec des 0

Compléter un négatif avec des 0 change sa valeur : 0000 0000 1000 11012 = 141, alors que 1111 1111 1000 11012 = −115. Les 0 à gauche conviennent à un non signé (partie 3) ou à un positif, dont le bit de signe vaut justement 0.

L’extension de signe n’est tombée dans aucun des 10 sujets. Elle est au programme du chapitre 1, donc du test Moodle 2.

Partie 8 cours § V

Autres codes : BCD, Gray, ASCII

Il existe beaucoup d’autres encodages, chacun pour un usage. Le cours en présente trois.

BCD

Le BCD (Binary-Coded Decimal, décimal codé en binaire) sert surtout à afficher des nombres en décimal. Chaque chiffre décimal est encodé séparément sur 4 bits : 3 76810 = 0011 0111 0110 1000BCD.

Décimal3768 BCD0011011101101000
Piège : le BCD n’est pas le binaire

En binaire naturel, 3 76810 = 1110 1011 10002 : rien à voir. En BCD, un paquet ne dépasse jamais 1001 (9) : les paquets 1010 à 1111 n’y sont pas utilisés.

Code Gray ou binaire réfléchi

Le code Gray est une autre façon d’encoder les entiers non signés. Sa propriété principale : un seul bit change d’une représentation à la suivante. C’est pourquoi on l’utilise dans certains algorithmes et applications particulières, dans la correction d’erreurs et dans les tableaux de Karnaugh, que le cours étudiera plus tard.

ASCII

L’ASCII (American Standard Code for Information Interchange) encode des caractères. Les trois exemples du cours :

  • ‘0’ = 3016 = 0011 00002
  • ‘A’ = 4116 = 0100 00012
  • ‘a’ = 6116 = 0110 00012

Le cours ne donne pas la table. Les chiffres s’y suivent dans l’ordre, de ‘1’ = 3116 à ‘9’ = 3916, de même que les majuscules (‘B’ = 4216) et les minuscules (‘b’ = 6216).

Piège : le caractère ‘0’ n’est pas l’entier 0

Le caractère ‘0’ est le mot 0011 0000, soit 3016 = 48 ; l’entier 0 sur 8 bits est 0000 0000. De même, ‘A’ et ‘a’ diffèrent de 6116 − 4116 = 2016 = 32.
