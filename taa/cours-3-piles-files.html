Partie 1

La pile : dernier entré, premier sorti

Pense à une pile d’assiettes. Tu poses une assiette sur le dessus. Tu reprends celle du dessus. Celles du dessous restent coincées tant que tu n’as pas retiré celles qui sont au-dessus.

Une pile range des éléments de la même façon. C’est une structure LIFO (Last In, First Out) : le dernier entré est le premier sorti. Les entrées et les sorties se font du même côté, par le dessus.

On ne voit que le sommet

Le seul élément accessible est celui du dessus : le sommet. Une pile vide n’a pas de sommet.

On ne retire que le sommet

C’est l’opération dépiler. Impossible de dépiler une pile vide.

On ajoute au-dessus

C’est l’opération empiler : l’élément ajouté devient le nouveau sommet.

Essaie. Empile, dépile, demande le sommet. Sous la pile, le banc écrit le même état sous forme de terme : chaque empiler ajoute une couche autour de la pile précédente.

La pile où l’on a empilé a, puis b, puis c s’écrit empiler(empiler(empiler(pilevide, a), b), c). Le sommet c est dans l’appel empiler le plus extérieur. Le fond, a, est le plus enfoui, tout contre pilevide. Garde cette image : elle explique toute la différence avec la file (partie 5).

À quoi ça sert ? La fiche de synthèse donne trois usages :

  • inverser l’ordre des éléments : ce qui entre dans l’ordre a, b, c ressort dans l’ordre c, b, a (vérifie-le dans le banc en haut de page) ;
  • évaluer des expressions ;
  • simuler la pile des appels, pour rendre itératif un algorithme récursif.
À retenir
  • Pile = LIFO : dernier entré, premier sorti. On entre et on sort du même côté.
  • Seul le sommet est accessible. On ajoute avec empiler, on retire avec dépiler.
  • Dans un terme, le sommet est l’élément de l’appel empiler le plus extérieur.
Piège

dépiler ne rend pas l’élément retiré : il rend la pile privée de son sommet (dépiler : pile → pile). Pour connaître l’élément, c’est sommet, qui ne change rien à la pile. Dans certains langages, une seule fonction fait les deux : pas ici.

À l’examen

Les sujets de TAA de 2023 et de 2024 ne contenaient ni pile ni file : leurs exercices portaient sur les listes. Mais d’après le Moodle, les MiMos piles et files de la semaine du 19 octobre sont « supposés connus dès le lundi qui suit » : ils peuvent donc tomber à l’examen de la semaine du 26 octobre. Sache écrire les deux types de tête, préconditions et axiomes compris, et calculer un terme à la main.

Le type abstrait pile

Voici la définition complète, telle que le Moodle la donne. Tu y retrouves les six mots-clés du chapitre 1. Les couleurs donnent le rôle de chaque opération.

opération interneobservateurconstante
types
    pile
utilise
    booléen, élément
opérations
    pilevide : → pile
     empiler : pile × élément → pile
     dépiler : pile → pile
      sommet : pile → élément
     estvide : pile → booléen
préconditions
    dépiler(p) est-défini-ssi estvide(p) = Faux
     sommet(p) est-défini-ssi estvide(p) = Faux
axiomes
    dépiler(empiler(p, e)) = p
    sommet(empiler(p, e)) = e
    estvide(pilevide) = Vrai
    estvide(empiler(p, e)) = Faux
avec
    pile p
    élément e

La fiche de synthèse écrit sorte Pile à la place de types pile : les deux désignent le type que l’on définit.

sommet et dépiler n’ont pas de sens sur une pile vide : ce sont des opérations partielles. Leurs préconditions les limitent aux piles telles que estvide(p) = Faux. Les deux autres opérations sont là « comme toujours » : une pour initialiser, pilevide, et une pour savoir si la structure contient des éléments, estvide.

Comment on trouve les quatre axiomes

Les axiomes disent ce que font les opérations internes ; pour le savoir, on leur applique les observateurs (fiche « Types abstraits »). Toute pile se fabrique avec pilevide et empiler(p, e) : la pile qui contient a puis b, c’est empiler(empiler(pilevide, a), b).

On applique donc les observateurs estvide et sommet, et l’opération dépiler qui défait ce que fait empiler, à ces deux formes. Six cases : chacune donne un axiome, ou rien si une précondition l’interdit.

À toi : devine chaque case, puis clique pour vérifier.

pilevideempiler(p, e)
estvide estvide(pilevide) = Vrai estvide(empiler(p, e)) = Faux
sommet rien : la précondition l’interdit sommet(empiler(p, e)) = e
dépiler rien : la précondition l’interdit dépiler(empiler(p, e)) = p

Quatre cases remplies, quatre axiomes. Aucun n’a de condition : dans empiler(p, e), le sommet est toujours e, quelle que soit la pile p en dessous.

À retenir
  • Deux opérations partielles, dépiler et sommet : définies si et seulement si estvide(p) = Faux.
  • Quatre axiomes sans condition : dépiler(empiler(p, e)) = p, sommet(empiler(p, e)) = e, estvide(pilevide) = Vrai, estvide(empiler(p, e)) = Faux.
  • Aucun axiome pour sommet(pilevide) ni dépiler(pilevide) : les préconditions les interdisent.
Piège

N’ajoute pas de condition estvide(p) = Faux devant les axiomes de la pile. dépiler(empiler(p, e)) = p est vrai même si p est vide : dépiler(empiler(pilevide, a)) = pilevide. La précondition porte sur l’argument de dépiler, ici empiler(p, e), qui n’est jamais vide.

Partie 3

Évaluer un terme de pile

On te donne un terme ; tu le calcules avec les seuls axiomes. Prends sommet(dépiler(dépiler(empiler(empiler(empiler(pilevide, a), b), c)))). On empile a, b, c, on dépile deux fois, puis on demande le sommet. Intuitivement, c’est a. Les axiomes doivent le confirmer.

  1. Lis de l’intérieur vers l’extérieur. L’opération la plus enfouie a été faite en premier : trois empiler, puis deux dépiler, puis sommet.
  2. Repère « dépiler d’un empiler ». Le dépiler le plus intérieur s’applique à empiler(empiler(empiler(pilevide, a), b), c). L’axiome dépiler(empiler(p, e)) = p l’annule : il reste empiler(empiler(pilevide, a), b).
  3. Recommence. Le second dépiler s’applique maintenant à empiler(empiler(pilevide, a), b) : il reste empiler(pilevide, a).
  4. Conclus. sommet(empiler(pilevide, a)) = a, par l’axiome sommet(empiler(p, e)) = e.
Pourquoi de l’intérieur

Les axiomes de la pile ne parlent que de pilevide et de empiler(p, e). Aucun ne commence par sommet(dépiler(…)) ou dépiler(dépiler(…)). Il faut donc d’abord faire disparaître les dépiler intérieurs, jusqu’à retomber sur un empiler.

Vérifie dans l’atelier. Le préréglage « empiler après dépiler » se conclut en une seule étape : sommet(empiler(p, e)) = e s’applique tout de suite, sans calculer la pile p (ici dépiler(empiler(empiler(pilevide, a), b)), qui est bien définie). Tu peux aussi écrire tes propres termes.

À retenir
  • « dépiler d’un empiler » s’annule : dépiler(empiler(p, e)) = p.
  • « sommet d’un empiler » donne l’élément empilé : sommet(empiler(p, e)) = e.
  • estvide vaut Vrai sur pilevide et Faux sur n’importe quel empiler.
Piège

Un dépiler ou un sommet appliqué à une pile vide rend tout le terme indéfini, même si le reste se calcule. Vérifie les préconditions au fur et à mesure : dans le préréglage « indéfini », le premier dépiler laisse pilevide, et le second n’a plus le droit de s’appliquer.

Pour t’entraîner sans fin : le générateur de termes à réduire de la page Entraînement.

Partie 4

La file : premier entré, premier sorti

Pense à une file d’attente. En l’absence de tout resquilleur, la première personne arrivée est la première à sortir. Les nouveaux se placent au bout.

Une file est une structure FIFO (First In, First Out) : le premier entré est le premier sorti. Les entrées et les sorties se font chacune à une extrémité : on entre par la queue (le dernier), on sort par la tête (le premier).

On ne voit que le premier

Le seul élément accessible est le premier. Une file vide n’a pas de premier.

On ne retire que le premier

C’est l’opération défiler, possible seulement si la file n’est pas vide.

On ajoute en queue

C’est l’opération enfiler : l’élément se place à la fin, derrière tous les autres.

Essaie. Enfile, défile, demande le premier, et regarde le terme sous la file.

Dans le terme enfiler(enfiler(enfiler(filevide, a), b), c), l’élément enfilé en premier, a, est le plus enfoui, tout contre filevide. Or c’est lui, le premier de la file. C’est l’inverse de la pile, où l’élément accessible est à l’extérieur du terme.

À quoi ça sert ? D’après la fiche de synthèse :

  • conserver l’ordre des éléments : ce qui entre dans l’ordre a, b, c ressort dans l’ordre a, b, c ;
  • implémenter les « buffers », des files d’attente : imprimante, clavier… ;
  • parcourir en largeur les arbres, les graphes…

  • File = FIFO : premier entré, premier sorti.
  • On ajoute en queue avec enfiler, on retire en tête avec défiler ; seul le premier est accessible.
  • Dans un terme, le premier est l’élément de l’appel enfiler le plus enfoui.
Piège

Le premier de la file n’est pas le dernier élément écrit dans le terme. Dans enfiler(enfiler(enfiler(filevide, a), b), c), le premier est a, pas c : c vient d’arriver, il attend derrière les autres.

Partie 5

Le type abstrait file : des axiomes conditionnels

La signature de la file a exactement la forme de celle de la pile : seuls les noms changent. Les préconditions aussi : défiler et premier sont partielles, car une file vide n’a ni premier ni élément à retirer.

types
    file
utilise
    booléen, élément
opérations
    filevide : → file
     enfiler : file × élément → file
     défiler : file → file
     premier : file → élément
     estvide : file → booléen
préconditions
    défiler(f) est-défini-ssi estvide(f) = Faux
    premier(f) est-défini-ssi estvide(f) = Faux
Coquille de la fiche

Dans la fiche de synthèse « Les files », le type défini est écrit sorte Pile. Il faut lire sorte File, comme dans tous les profils qui suivent.

Le premier est au fond du terme

Pile : le sommet est dehors

empiler(empiler(empiler(pilevide, a), b), c)

Le sommet est dans l’appel empiler le plus extérieur. Dans empiler(p, e), le sommet est toujours e, quelle que soit p.

File : le premier est au fond

enfiler(enfiler(enfiler(filevide, a), b), c)

Le premier est dans l’appel enfiler le plus enfoui, celui qui touche filevide. Dans enfiler(f, e), e vient d’arriver : il n’est le premier que si f est vide.

Pourquoi des conditions pour la file, et pas pour la pile

Pour la pile, l’élément concerné par sommet et dépiler est toujours e, le dernier empilé : le résultat ne dépend pas de p, une seule formule suffit.

Pour la file, ce qui sort de enfiler(f, e) dépend de f. Si f est vide, e est seul : c’est le premier, et défiler le retire. Sinon, le premier est quelque part au fond de f, et e n’y change rien. Deux cas, donc deux axiomes pour premier et deux pour défiler, chacun précédé de sa condition : estvide(f) = Vrai ⇒ … ou estvide(f) = Faux ⇒ ….

À toi : remplis le même tableau que pour la pile, puis vérifie.

filevideenfiler(f, e)
estvide estvide(filevide) = Vrai estvide(enfiler(f, e)) = Faux, sans condition
premier rien : la précondition l’interdit deux cas : e si estvide(f) = Vrai ; premier(f) si estvide(f) = Faux
défiler rien : la précondition l’interdit deux cas : filevide si estvide(f) = Vrai ; enfiler(défiler(f), e) si estvide(f) = Faux

Ce qui donne les six axiomes du Moodle. Les quatre axiomes conditionnels sont surlignés.

axiomes
    estvide(f) = Vrai ⇒ premier(enfiler(f, e)) = e
    estvide(f) = Faux ⇒ premier(enfiler(f, e)) = premier(f)
    estvide(f) = Vrai ⇒ défiler(enfiler(f, e)) = filevide
    estvide(f) = Faux ⇒ défiler(enfiler(f, e)) = enfiler(défiler(f), e)
    estvide(filevide) = Vrai
    estvide(enfiler(f, e)) = Faux
avec
    file f
    élément e

Lire défiler(enfiler(f, e)) = enfiler(défiler(f), e)

C’est l’axiome le plus délicat du chapitre. Il s’applique quand f n’est pas vide, et se lit en trois temps :

  1. Mets e de côté. Dans enfiler(f, e), e est le dernier arrivé : comme f n’est pas vide, ce n’est pas lui qui sort.
  2. Défile f. Le premier de toute la file est le premier de f : défiler(f) le retire.
  3. Remets e au bout. enfiler(défiler(f), e) : e reprend sa place, en queue.

Sur la file a, b, c, le défiler descend ainsi d’un niveau à chaque étape, jusqu’à l’appel enfiler qui touche filevide. Là, c’est le cas « f vide » qui s’applique, et a disparaît :

  1. défiler(enfiler(enfiler(enfiler(filevide, a), b), c))
  2. enfiler(défiler(enfiler(enfiler(filevide, a), b)), c)
    f = enfiler(enfiler(filevide, a), b) n’est pas vide : on met c de côté et on défile f.
  3. enfiler(enfiler(défiler(enfiler(filevide, a)), b), c)
    Même cas un niveau plus bas : f = enfiler(filevide, a) n’est pas vide, on met b de côté.
  4. enfiler(enfiler(filevide, b), c)
    Enfin f = filevide : défiler(enfiler(filevide, a)) = filevide. Il reste la file b, c.
À retenir
  • Six axiomes : quatre conditionnels (premier et défiler sur enfiler(f, e), selon que f est vide ou non) et deux sans condition pour estvide.
  • Les deux conditions estvide(f) = Vrai et estvide(f) = Faux couvrent tous les cas : aucun trou, aucune contradiction.
  • La raison : dans le terme, le premier entré est le plus enfoui.
Piège

défiler(enfiler(f, e)) = f, c’est l’axiome de la pile. Pour la file, il n’est juste que si f est vide (et alors f = filevide). Dès que f contient un élément, c’est le premier de f qui sort, pas e.

Partie 6

Évaluer un terme de file

La méthode est celle de la pile, avec un réflexe de plus : avant d’appliquer un axiome à enfiler(f, e), calcule estvide(f) pour choisir le bon cas.

  1. Repère le motif. premier(enfiler(f, e)) ou défiler(enfiler(f, e)). Comme pour la pile, réduis d’abord les défiler intérieurs qui ne sont pas de cette forme.
  2. Calcule estvide(f). Faux si f s’écrit enfiler(…), Vrai si f est filevide. Si f contient un défiler, réduis-le d’abord.
  3. Applique l’axiome du bon cas. Cas vide : e pour premier, filevide pour défiler. Cas non vide : premier(f), ou enfiler(défiler(f), e).
  4. Recommence jusqu’à la forme finale. premier et défiler descendent ainsi jusqu’au fond du terme.

Pile et file sur les mêmes éléments

Mets a, b, c, dans cet ordre, dans une pile et dans une file, puis compte les étapes de calcul (refais-les dans les deux ateliers).

Pile

empiler(empiler(empiler(pilevide, a), b), c)
  • sommet = c : 1 étape.
  • dépiler → empiler(empiler(pilevide, a), b) : 1 étape.
  • Ordre de sortie : c, b, a.

File

enfiler(enfiler(enfiler(filevide, a), b), c)
  • premier = a : 3 étapes.
  • défiler → enfiler(enfiler(filevide, b), c) : 3 étapes.
  • Ordre de sortie : a, b, c.

La pile répond en une étape, parce que son élément accessible est à l’extérieur du terme. La file doit descendre jusqu’au fond : une étape par élément traversé.

À retenir
  • Sur une file écrite avec des enfiler autour de filevide, premier donne l’élément de l’appel enfiler le plus intérieur.
  • défiler supprime cet appel le plus intérieur et garde les autres dans le même ordre.
  • Un premier ou un défiler sur une file vide rend le terme indéfini, comme pour la pile.
Piège

La condition porte sur f, et f peut être un terme compliqué. Dans premier(enfiler(défiler(enfiler(filevide, a)), b)), f = défiler(enfiler(filevide, a)) : il faut le réduire pour voir qu’il vaut filevide. Donc estvide(f) = Vrai, et le premier est b (préréglage « f à réduire d’abord »).

Partie 7

Les ensembles : seule la présence compte

Bonus

Dans le planning des MiMos du Moodle, les ensembles sont présentés comme un « bonus ». Le plan officiel de l’ECUE s’arrête d’ailleurs aux types séquentiels : listes, piles et files. Garde ces deux dernières parties pour quand les piles et les files sont solides.

Dans une liste, une pile ou une file, l’ordre des éléments est fondamental. Dans un ensemble, il n’a aucune importance. Une seule chose compte : un élément est présent ou non.

Ajouter a puis b, ou b puis a, donne le même ensemble. Ajouter a une seconde fois ne change rien.

La base : l’ensemble vide et l’appartenance

types
    ensemble
utilise
    élément, booléen
opérations
    ensemblevide : → ensemble
             _∈_ : élément × ensemble → booléen
axiomes
    x ∈ ensemblevide = faux

_∈_ s’écrit entre ses deux arguments : x ∈ e. Chaque _ marque la place d’un argument, comme pour _^_ au chapitre 1. Dans tous les axiomes qui suivent, x et y sont des éléments et e est un ensemble.

Ajouter, supprimer, compter

On doit aussi pouvoir ajouter et supprimer un élément. La fiche fait un choix : ces opérations sont sans effet en cas d’erreur. Ajouter un élément déjà présent ne fait rien ; supprimer un élément absent non plus. ajouter et supprimer sont donc définies partout : pas de précondition.

S’y ajoute l’observateur card, le nombre d’éléments de l’ensemble, lui aussi défini partout.

opérations
      ajouter : élément × ensemble → ensemble
    supprimer : élément × ensemble → ensemble
         card : ensemble → entier
axiomes
    x = y ⇒ (x ∈ ajouter(y, e)) = vrai
    x ≠ y ⇒ (x ∈ ajouter(y, e)) = (x ∈ e)
    x = y ⇒ (x ∈ supprimer(y, e)) = faux
    x ≠ y ⇒ (x ∈ supprimer(y, e)) = (x ∈ e)
    card(ensemblevide) = 0
    x ∈ e = vrai ⇒ card(ajouter(x, e)) = card(e)
    x ∈ e = faux ⇒ card(ajouter(x, e)) = card(e) + 1
    x ∈ e = vrai ⇒ card(supprimer(x, e)) = card(e) − 1
    x ∈ e = faux ⇒ card(supprimer(x, e)) = card(e)

Les axiomes de ∈ séparent deux cas, comme ceux du vecteur au chapitre 1 : l’élément testé est celui qu’on vient d’ajouter ou de supprimer (x = y), ou c’en est un autre (x ≠ y), que l’opération ne concerne pas.

Ceux de card séparent « déjà présent » et « absent » : c’est là que se voit le choix « sans effet en cas d’erreur ».

Coquilles des sources
  • Sur la page du Moodle, l’axiome de card(supprimer(x, e)) pour un élément absent est écrit avec x ∈ = faux : il manque l’ensemble. Lis x ∈ e = faux.
  • Dans la fiche PDF, les deux premiers axiomes de card sont collés sur une seule ligne. Ce sont bien deux axiomes : card(ensemblevide) = 0, puis celui de card(ajouter(x, e)).

Choisir un élément

Pour appliquer un même traitement à tous les éléments, on énumère : on choisit un élément, on le traite, puis on recommence sur l’ensemble obtenu en supprimant l’élément traité. Il faut pour cela une opération de choix.

opérations
    choisir : ensemble → élément
préconditions
    choisir(e) est-défini-ssi e ≠ ensemblevide
axiomes
    choisir(e) ∈ e = vrai

choisir est partielle : dans un ensemble vide, il n’y a rien à choisir. Son unique axiome dit seulement que l’élément choisi appartient à l’ensemble, pas lequel. C’est pourquoi l’atelier ci-dessous ne l’utilise pas : il n’y a rien à calculer.

À retenir
  • Ensemble : un élément est présent ou absent ; l’ordre et les répétitions ne comptent pas.
  • ajouter et supprimer n’ont pas de précondition : sans effet en cas d’erreur.
  • card n’augmente que si l’élément ajouté était absent, et ne diminue que si l’élément supprimé était présent.
  • choisir est partielle : définie si et seulement si e ≠ ensemblevide.
Piège

card(ajouter(x, e)) ne vaut pas toujours card(e) + 1 : si x est déjà dans e, le cardinal ne bouge pas (préréglage « a ajouté deux fois »). Teste d’abord x ∈ e.

Partie 8

Les multi-ensembles : quand les répétitions comptent

Un multi-ensemble, ou famille, est un ensemble qui accepte les occurrences multiples d’un élément. Ajouter a deux fois donne deux a. L’ordre, lui, ne compte toujours pas.

On garde les mêmes opérations, mais leur comportement change. Ajouter un élément déjà présent augmente le nombre d’éléments. Supprimer un élément ne le fait pas forcément disparaître : il peut en rester d’autres occurrences. D’où une opération de plus, nboccurrences, qui compte les occurrences d’un élément.

types
    multiensemble
utilise
    élément, booléen, entier
opérations
    multiensemblevide : → multiensemble
              ajouter : élément × multiensemble → multiensemble
            supprimer : élément × multiensemble → multiensemble
                  _∈_ : élément × multiensemble → booléen
                 card : multiensemble → entier
        nboccurrences : élément × multiensemble → entier
axiomes
    (x ∈ multiensemblevide) = faux
    x = y ⇒ (x ∈ ajouter(y, me)) = vrai
    x ≠ y ⇒ (x ∈ ajouter(y, me)) = (x ∈ me)
    nboccurrences(x, me) ≤ 1 ⇒ (x ∈ supprimer(x, me)) = faux
    x ≠ y ⇒ (x ∈ supprimer(y, me)) = (x ∈ me)

    card(multiensemblevide) = 0

Le point clé est card(ajouter(x, me)) = card(me) + 1 : la condition a disparu, puisque chaque ajout compte. À l’inverse, l’axiome de ∈ sur supprimer en gagne une : après la suppression, x n’est absent que s’il avait au plus une occurrence avant.

Les axiomes de nboccurrences suivent le schéma de ∈ : soit l’opération touche x lui-même (x = y, ou supprimer(x, me)), soit elle touche un autre élément (x ≠ y) et le compte de x ne bouge pas. Pour la suppression de x lui-même, deux cas : s’il n’y en avait aucune, il n’y en a toujours aucune ; s’il y en avait au moins une, il y en a une de moins.

Remarque

La fiche ne donne pas d’axiome pour x ∈ supprimer(x, me) quand x a au moins deux occurrences dans me. Son texte règle pourtant le cas : la suppression d’un élément « n’implique pas qu’il disparaisse de l’ensemble (s’il en existe plusieurs occurrences) ». x est donc encore présent.

À retenir
  • Multi-ensemble (famille) = ensemble qui accepte les occurrences multiples.
  • nboccurrences : élément × multiensemble → entier compte les occurrences d’un élément.
  • Chaque ajouter augmente card de 1, sans condition.
  • supprimer retire une seule occurrence : x reste présent s’il en avait plusieurs.
Piège

Ne recopie pas les axiomes de l’ensemble. x ∈ e = vrai ⇒ card(ajouter(x, e)) = card(e) est faux pour un multi-ensemble : card(ajouter(a, ajouter(a, multiensemblevide))) vaut 2, pas 1 (préréglage « a ajouté deux fois », dans les deux ateliers).
