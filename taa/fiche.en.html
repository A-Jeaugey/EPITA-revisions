Detailed methods

In the exam

Written, on the exam paper: 30 min and 10 points in October 2024; 1 h announced this year. Expect course questions, axioms to write for a new operation on a list, and a “mystery” operation to apply to a list.

Answer in the boxes, in pen: the presentation is marked.

Abstract type

Definition = a signature (types + operations) + a system of axioms.

Keywords, in order: types · uses · operations · preconditions · axioms · with.

Signature

Operation = name + profile: argument types × … → result type.

Infix: _^_ : integer × integer → integer, written 4^2.

Constant: no argument; it returns a defined type (emptystack : → stack).

Hierarchy

Defined type: new, in types. Predefined type: already exists, in uses.

Internal operation: result of a defined type.

Observer: at least one argument of a defined type and a result of a predefined type.

Preconditions

Domain of the partial operations: op(x) is-defined-iaoi condition. Empty structure, rank out of bounds…

Total operation: no precondition, and say so (e.g. concatenate).

Auxiliary operation: used to write the domain of another one (ispresent for search).

Axioms

Apply the observers to the internal operations. An axiom = an equality between two terms of the same type, possibly under a condition: condition ⇒ t1 = t2.

Consistency: no contradictory axioms. Completeness: enough axioms to compute every defined term.

with: the type of each variable.

Recursive list

types
    list, box
uses
    element
operations
    emptylist : → list
         cons : element x list → list
         tail : list → list
         head : list → box
     contents : box → element
        first : list → element
         next : box → box
preconditions
    tail(λ), head(λ), first(λ) : λ ≠ emptylist
axioms
    first(λ) = contents(head(λ))
    tail(cons(e, λ)) = λ
    first(cons(e, λ)) = e
    next(head(λ)) = head(tail(λ))

{e1, e2, e3} = cons(e1, cons(e2, cons(e3, emptylist))).

New recursive operation

  1. One axiom for emptylist, one (or several, with conditions on e) for cons(e, λ).
  2. The cons case calls the operation again on λ: the list gets shorter each time.
  3. Preconditions only if the empty list makes no sense.

concatenate(emptylist, λ2) = λ2
concatenate(cons(e, λ), λ2) = cons(e, concatenate(λ, λ2))

Iterative list

operations
      access : list x integer → box
         nth : list x integer → element
      length : list → integer
      delete : list x integer → list
      insert : list x integer x element → list
preconditions
    access(λ, k), delete(λ, k) : λ ≠ emptylist
                         & 1 ≤ k ≤ length(λ)
    insert(λ, k, e) : 1 ≤ k ≤ length(λ) + 1
axioms
    length(emptylist) = 0
    length(delete(λ, k)) = length(λ) - 1
    length(insert(λ, k, e)) = length(λ) + 1
    1 ≤ i < k ⇒ nth(delete(λ, k), i) = nth(λ, i)
    k ≤ i ≤ length(λ) - 1 ⇒ … = nth(λ, i + 1)
    1 ≤ i < k ⇒ nth(insert(λ, k, e), i) = nth(λ, i)
    k = i ⇒ nth(insert(λ, k, e), i) = e
    k < i ≤ length(λ) + 1 ⇒ … = nth(λ, i - 1)
    contents(access(λ, k)) = nth(λ, k)
    next(access(λ, k)) = access(λ, k + 1)

Mystery operation

  1. Check the precondition with the given arguments (otherwise: undefined).
  2. Compute the length of the result.
  3. For each rank i, find its case and read the rank it gives in λ (i + y − x + 1…).
  4. Check the edges: first rank, last rank, empty list.

Stack · LIFO

types
    stack
operations
    emptystack : → stack
          push : stack x element → stack
           pop : stack → stack
           top : stack → element
       isempty : stack → boolean
preconditions
    pop(s), top(s) : isempty(s) = false
axioms
    pop(push(s, e)) = s
    top(push(s, e)) = e
    isempty(emptystack) = true
    isempty(push(s, e)) = false

Queue · FIFO

preconditions
    dequeue(q), first(q) : isempty(q) = false
axioms
    isempty(q) = true ⇒ first(enqueue(q, e)) = e
    isempty(q) = false ⇒ first(enqueue(q, e)) = first(q)
    isempty(q) = true ⇒ dequeue(enqueue(q, e)) = emptyqueue
    isempty(q) = false ⇒
            dequeue(enqueue(q, e)) = enqueue(dequeue(q), e)
    isempty(emptyqueue) = true
    isempty(enqueue(q, e)) = false

The first one in is the most deeply buried in the term: you need conditions.

Sets

x ∈ emptyset = false; x = y ⇒ (x ∈ add(y, s)) = true; x ≠ y ⇒ (x ∈ add(y, s)) = (x ∈ s).

card: + 1 only if the added element was absent. choose(s): defined if s ≠ emptyset.

Multiset: nboccurrences : element × multiset → integer; card(add(x, ms)) = card(ms) + 1.

Rewriting a term

Find a piece with the exact shape of an axiom’s left-hand side, replace it, start again. Check the ⇒ conditions; a partial operation outside its domain makes the term undefined.

top(pop(push(push(emptystack, a), b))) → top(push(emptystack, a)) → a.

Traps

  • Observer ≠ “returns a boolean”: top, length, contents are observers.
  • Inventing a precondition on a total operation, or forgetting the one of a partial operation.
  • Forgetting a case (emptylist, or one of the rank ranges): incomplete axioms.
  • Rank shift: after insert, you read i − 1; after delete, i + 1.
  • Two sides of an axiom with different types.
  • Stack and queue: LIFO versus FIFO.
