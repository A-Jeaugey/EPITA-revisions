Partie 1

Pourquoi un type abstrait

Il y a deux façons de concevoir un algorithme. La première : coder tout de suite avec les types du langage (tableaux, enregistrements…) et leurs fonctions. L’algorithme est alors collé à ce langage, et difficile à transcrire dans un autre.

La seconde : définir d’abord un type abstrait. On donne au type un nom, on liste ce qu’on peut faire avec lui et les propriétés que ces opérations respectent, sans rien dire du langage ni de la machine. Si un problème a besoin d’une pile, tu raisonnes avec « empiler » et « dépiler », sans te demander si la pile est un tableau ou une chaîne de cellules en mémoire.

À retenir

La définition d’un type algébrique abstrait (ou type abstrait de données) se compose de deux parties :

  • une signature : les types et les opérations ;
  • un système d’axiomes : les propriétés de ces opérations.

Toute la suite du cours suit le même plan. Voici le squelette d’une définition, avec ses six mots-clés dans l’ordre :

types
    les types qu’on définit
utilise
    les types qui existent déjà
opérations
    nom : types des arguments → type du résultat
préconditions
    le domaine des opérations partielles
axiomes
    les propriétés des opérations
avec
    le type de chaque nom utilisé dans les axiomes
Pourquoi c’est utile

Les axiomes suffisent pour calculer. Dans l’atelier en haut de page, le terme sommet(dépiler(empiler(empiler(pilevide, a), b))) se réduit à a rien qu’en appliquant deux axiomes, sans aucune pile en mémoire.

Partie 2

La signature : des types et des opérations

La signature d’un type abstrait est composée des types et des opérations.

Les types sont des noms d’ensembles de valeurs : ceux que l’on veut définir. On les liste après le mot-clé types, par exemple pile, liste, graphe.

Chaque opération est définie par son nom et son profil : les types de ses arguments, puis, après la flèche, le type de son résultat.

opérations
    supprimer : liste x entier → liste
     longueur : liste → entier
         ieme : liste x entier → élément
          _^_ : entier x entier → entier
         Faux : → booléen
OpérationArgumentsRésultatOn l’écrit
supprimerune liste, un entierune listesupprimer(λ, i)
longueurune listeun entierlongueur(λ)
_^_deux entiersun entier4^2 : chaque _ marque la place d’un argument (notation infixe)
Fauxaucunun booléenFaux : c’est une constante
À retenir
  • La définition d’une opération = son nom + son profil.
  • Le profil se lit « types des arguments → type du résultat ». Le symbole × sépare les arguments.
  • Une constante est une opération sans argument : rien avant la flèche. Elle renvoie une valeur du type défini : pilevide : → pile dans le type pile, Faux : → booléen dans le type booléen.
À l’examen

Partiel 2023 : « Quel type de données retourne une constante ? » Réponse attendue : un type défini. Une copie qui répondait « prédéfini » a eu 0 : l’exemple Faux : → booléen de la fiche est la constante du type booléen lui-même.

Piège

Le profil ne dit pas ce que fait l’opération. empiler : pile × élément → pile et dépiler : pile → pile renvoient toutes les deux une pile : ce sont les axiomes qui disent laquelle ajoute et laquelle retire.

Partie 3

La hiérarchie : types définis et prédéfinis

Un type abstrait s’appuie presque toujours sur d’autres types. Une liste contient des éléments, se mesure avec des entiers, se teste avec des booléens. On distingue donc deux sortes de types :

Type défini

Il est nouveau, « en conception ». C’est celui qu’on est en train d’écrire. Il est listé dans types.

Ex. : liste, place dans le type liste.

Type prédéfini

Il existe déjà, « déjà conçu ». On s’en sert sans le redéfinir. Il est listé dans utilise, avant les opérations.

Ex. : entier, booléen, élément.

types
    liste, place
utilise
    entier, élément

Ici, la liste itérative définit deux types à la fois : la liste et la place (la case qui contient un élément). Elle utilise les entiers (pour les rangs) et les éléments (ce qu’on range), qui existent déjà.

À retenir

Défini = dans types, c’est le nouveau. Prédéfini = dans utilise, il existe déjà. Cette distinction sert à classer les opérations (partie suivante).

La partie utilise fait partie de la signature : les corrigés d’examen citent trois zones pour la signature, types, utilise et opérations. Les préconditions, les axiomes et la partie avec n’en font pas partie.

Partie 4

Opérations internes et observateurs

Une fois les types classés, le profil d’une opération suffit à dire son rôle.

Opération interne

Elle renvoie un résultat de type défini. Elle fabrique ou modifie une donnée du type.

empiler : pile × élément → pile

Observateur

Il a au moins un argument de type défini et renvoie un résultat de type prédéfini. Il interroge la donnée sans la changer.

sommet : pile → élément

opération interneobservateurconstante
types
    pile
utilise
    booléen, élément
opérations
    pilevide : → pile
     empiler : pile x élément → pile
     dépiler : pile → pile
      sommet : pile → élément
     estvide : pile → booléen

À toi : classe chaque opération. Indice : regarde d’abord le type du résultat, puis s’il y a un argument de type défini.

Pièges classiques
  • « Observateur » ne veut pas dire « renvoie un booléen ». sommet renvoie un élément et c’est un observateur.
  • Un type défini peut ne pas être le type « principal ». Dans la liste itérative, place est défini : accès : liste × entier → place est donc une opération interne, alors que contenu : place → élément est un observateur.
  • Une constante comme pilevide n’a pas d’argument : elle ne peut pas être un observateur, qui a besoin d’un argument de type défini. Elle renvoie le type défini : c’est une opération interne sans argument.
À l’examen

Questions de cours vues aux partiels : « Quelles sont les spécifications du profil d’un observateur ? », « La définition d’une opération est composée de ? ». Réponds avec les mots du cours : un argument de type défini au moins, un résultat de type prédéfini ; un nom et un profil.

Partie 5

Opérations partielles et préconditions

Certaines opérations n’ont pas de sens partout. Le sommet d’une pile vide n’existe pas. On ne supprime pas le 5e élément d’une liste qui en a 3. Ces opérations sont partielles : elles ne sont définies que sur une partie de leurs arguments.

Les préconditions donnent ce domaine de définition, avec la formule est-défini-ssi (« est défini si et seulement si »). On les écrit avant les axiomes.

préconditions
    dépiler(p) est-défini-ssi estvide(p) = Faux
    sommet(p) est-défini-ssi estvide(p) = Faux
    supprimer(λ, i) est-défini-ssi estvide(λ) = Faux & 1 ≤ i ≤ longueur(λ)
Méthode : une opération est-elle partielle ?
  1. Cherche un argument pour lequel le résultat n’a aucun sens : structure vide, rang hors des bornes, case jamais remplie.
  2. S’il y en a un, écris la précondition qui l’exclut, avec les opérations du type (estvide, longueur, ≠ listevide…).
  3. Sinon, l’opération est totale : pas de précondition, et dis-le.

Pour écrire une précondition, on a parfois besoin d’une opération qui n’existe pas encore. Pour chercher un élément dans une liste, il faut d’abord savoir s’il y est : on ajoute est-présent à la signature, rien que pour écrire le domaine de rechercher. Une opération qui sert à spécifier le domaine de définition d’une autre s’appelle une opération auxiliaire.

opérations
    est-présent : élément x liste → booléen
     rechercher : élément x liste → place
préconditions
    rechercher(e, λ) est-défini-ssi est-présent(e, λ) = vrai
À l’examen

Partiel 2019 : « l’opération qui sert à spécifier le domaine de définition d’une autre » est une opération auxiliaire ; « une opération qui n’est pas définie partout » est une opération partielle (2021, 2022). est-présent et rechercher sont tombés en 2018 et en 2020.

Piège

N’invente pas de précondition. empiler marche sur toute pile. Concaténer deux listes marche même si l’une est vide : au partiel 2023, la bonne réponse à « préconditions de concaténer ? » était aucune.

Une précondition non respectée rend le terme indéfini. Essaie : l’atelier s’arrête dès qu’une opération partielle reçoit une pile vide.

Partie 6

Les axiomes : appliquer les observateurs aux opérations internes

Le profil dit ce qu’une opération prend et rend, pas ce qu’elle fait. Ce sont les axiomes qui donnent les propriétés. Pour savoir ce que fait une opération interne, on lui applique les observateurs : « si j’empile e, que vaut le sommet ? la pile est-elle vide ? ».

En pratique, on fait un tableau : chaque observateur (et chaque opération qui défait, comme dépiler) appliqué à chaque façon de fabriquer une pile (pilevide, empiler(p, e)). Chaque case donne un axiome, ou rien si une précondition l’interdit.

pilevideempiler(p, e)
estvideestvide(pilevide) = Vraiestvide(empiler(p, e)) = Faux
sommetinterdit (précondition)sommet(empiler(p, e)) = e
dépilerinterdit (précondition)dépiler(empiler(p, e)) = p
 
axiomes
    dépiler(empiler(p, e)) = p
    sommet(empiler(p, e)) = e
    estvide(pilevide) = Vrai
    estvide(empiler(p, e)) = Faux
avec
    pile p
    élément e

Un axiome peut avoir une condition, écrite avant ⇒ : l’égalité n’est vraie que si la condition l’est. C’est indispensable quand le résultat dépend d’un cas. Pour la liste itérative, le i-ème élément après une suppression dépend de la place de i par rapport à k :

axiomes
    1 ≤ i < k ⇒ ième(supprimer(λ, k), i) = ième(λ, i)
    k ≤ i ≤ longueur(λ) - 1 ⇒ ième(supprimer(λ, k), i) = ième(λ, i + 1)
    longueur(supprimer(λ, k)) = longueur(λ) - 1
À retenir
  • Les axiomes définissent ce que font les opérations internes : on leur applique leurs observateurs.
  • Chaque cas possible doit donner une valeur ; les cas interdits par une précondition n’ont pas d’axiome.
  • La partie avec donne le type de chaque nom utilisé (pile p, élément e).
Piège

Un axiome est une égalité entre deux termes du même type. sommet(empiler(p, e)) = p est faux deux fois : la valeur est fausse, et les types ne collent pas (un élément d’un côté, une pile de l’autre).

Partie 7

Lire et réécrire un terme

Un terme est une suite d’opérations emboîtées : empiler(empiler(pilevide, a), b) est la pile où l’on a empilé a puis b. Il se lit de l’intérieur vers l’extérieur : l’opération la plus à l’intérieur a été faite en premier.

Pour calculer un terme, on le réécrit : on cherche un morceau qui a exactement la forme du côté gauche d’un axiome, on le remplace par le côté droit, et on recommence jusqu’à ce qu’aucun axiome ne s’applique.

  1. Repère le motif. dépiler(empiler(p, e)) s’applique à tout morceau de la forme « dépiler d’un empiler », quels que soient la pile p et l’élément e.
  2. Associe les variables. Dans dépiler(empiler(empiler(pilevide, a), b)), p vaut empiler(pilevide, a) et e vaut b.
  3. Remplace. Le côté droit est p : le morceau devient empiler(pilevide, a).
  4. Vérifie les conditions et les préconditions. Un axiome avec ⇒ ne s’applique que si sa condition est vraie ; une opération partielle hors de son domaine rend le terme indéfini.
Piège

Un axiome s’applique à un morceau qui a exactement sa forme. sommet(dépiler(empiler(empiler(pilevide, a), b))) n’est pas de la forme sommet(empiler(…)) : il faut d’abord réduire le dépiler qui est à l’intérieur.

Partie 8

Consistance, complétude et deux exemples complets

L’ensemble des axiomes d’un type doit respecter deux propriétés :

Consistance

Pas d’axiomes contradictoires : on ne doit jamais pouvoir prouver deux résultats différents pour le même terme.

Ajouter sommet(empiler(p, e)) = premier(p) à côté de sommet(empiler(p, e)) = e rendrait la pile inconsistante.

Complétude

Avoir écrit assez d’axiomes : tout terme bien défini doit pouvoir être calculé.

Sans estvide(pilevide) = Vrai, on ne saurait pas calculer estvide(pilevide).

Exemple 1 : le type Booléen

C’est l’exercice d’application du Moodle : écrire les axiomes de non, _ et _ et _ ou _. On applique chaque opération aux deux constantes vrai et faux ; pour et et ou, il suffit de regarder le premier argument.

types
    booléen
opérations
       vrai : → booléen
       faux : → booléen
        non : booléen → booléen
    _ et _ : booléen x booléen → booléen
    _ ou _ : booléen x booléen → booléen
axiomes
    non(vrai) = faux
    non(faux) = vrai
    vrai et b = b
    faux et b = faux
    vrai ou b = vrai
    faux ou b = b
avec
    booléen b

Six axiomes, et c’est complet : tout terme booléen se réduit à vrai ou à faux. Vérifie-le dans l’atelier.

Exemple 2 : le type Vecteur (annexe du Moodle)

Un vecteur a des bornes et des cases qu’on remplit une à une. On y retrouve tout le chapitre : une opération partielle (ième) et des axiomes conditionnels qui séparent « même case » et « autre case ».

types
    vecteur
utilise
    entier, booléen, élément
opérations
             vect : entier x entier → vecteur
        modifième : vecteur x entier x élément → vecteur
             ième : vecteur x entier → élément
    estinitialisé : vecteur x entier → booléen
         bornesup : vecteur → entier
         borneinf : vecteur → entier
préconditions
    ième(v, i) est-défini-ssi borneinf(v) ≤ i ≤ bornesup(v) & estinitialisé(v, i) = vrai
axiomes
    borneinf(v) ≤ i ≤ bornesup(v) ⇒ ième(modifième(v, i, e), i) = e
    borneinf(v) ≤ i ≤ bornesup(v) & borneinf(v) ≤ j ≤ bornesup(v) & i ≠ j
                ⇒ ième(modifième(v, i, e), j) = ième(v, j)
    estinitialisé(vect(i, j), k) = Faux
    borneinf(v) ≤ i ≤ bornesup(v) ⇒ estinitialisé(modifième(v, i, e), i) = Vrai
    borneinf(v) ≤ i ≤ bornesup(v) & borneinf(v) ≤ j ≤ bornesup(v) & i ≠ j
                ⇒ estinitialisé(modifième(v, i, e), j) = estinitialisé(v, j)
    borneinf(vect(i, j)) = i
    borneinf(modifième(v, i, e)) = borneinf(v)
    bornesup(vect(i, j)) = j
    bornesup(modifième(v, i, e)) = bornesup(v)
avec
    vecteur v
    entier i, j, k
    élément e
Le schéma « même case, autre case »

Après modifième(v, i, e), la case i contient e et toutes les autres cases j ≠ i sont inchangées. Ce découpage en deux cas revient dans presque tous les axiomes d’accès par position.

Coquille de la page Moodle

L’avant-dernier axiome sur estinitialisé y est écrit avec init(v, j), une opération qui n’existe pas. Il faut lire estinitialisé(v, j), comme ci-dessus.
