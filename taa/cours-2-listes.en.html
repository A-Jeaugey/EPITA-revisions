A list is read by its head or by its rank.

A list stores elements in boxes, one after the other. You can describe it in two ways: recursive, where only the first element is accessible, or iterative, where each element has a rank. This chapter writes and reads the axioms of both, as in the exam.

Part 1

List and box: contents and next

The linear list is the simplest way to organize data. The elements are stored one after the other in boxes, so you can process them one by one, in order.

Key point: the order of the elements does not depend on the elements themselves, but on their box in the list. Nothing forces a list to be sorted, and two boxes can hold the same element. {c, a, b} and {a, b, c} contain the same elements, but they are not the same lists.

A list therefore defines two types at once: list and box, the cell that holds an element. Two operations work on boxes:

types
    list, box
uses
    element
operations
    contents : box → element
        next : box → box

contents : box → element

Gets the element of a box.

contents(p): what is stored in the box p.

next : box → box

Moves to the next box. The result is a box, not an element.

The next element is therefore written contents(next(p)).

Key points
  • A list stores its elements in boxes: the order comes from the boxes, not from the values.
  • Two defined types, list and box; element is predefined.
  • contents reads a box, next moves to the next box.
  • A list is described in two ways, recursively or iteratively: it is still the same data, only the way you use it changes.

The erratum of the video on next

The MiMo video on iterative lists contains an error about the next operation. The Moodle erratum restates its profile, next : box → box, and shows its use on a list li of four pictures: a lightning bolt, a sun, a cloud, a moon. Here they are written by name.

p2 ← access(li, 2)
e ← contents(next(p2))
  1. p2 ← access(li, 2): access(li, 2) gives the box of the 2nd element. p2 is therefore the box that holds the sun. (access belongs to the iterative list, part 5.)
  2. next(p2): the next box, the 3rd.
  3. e ← contents(next(p2)): you read what this box holds. e is cloud, the 3rd element of li.
Traps
  • next returns a box, not an element. Writing next(p2) = cloud mixes types: it is contents(next(p2)) that equals cloud.
  • The course sheet presents contents and next as “the internal box operations”. With the rule from chapter 1, next is indeed internal (it returns a box, a defined type), but contents is an observer (it returns an element, a predefined type).

The recursive list: emptylist, cons, tail, head, first

First way to describe a list: by how you build it. A list is

  • either empty: emptylist;
  • or made of an element, the head, followed by a list: cons(e, λ).

The definition is recursive: what follows the head is again a list. Here is the complete type given on the Moodle, with the box operations from part 1.

internal operationobserverconstant

The four axioms, in the order of the Moodle. The workshops number them A1 to A4.

A1

first(λ) = contents(head(λ))

The first element is the contents of the head box.

A2

tail(cons(e, λ)) = λ

Adding e at the head and then removing the head gives back λ.

A3

first(cons(e, λ)) = e

The first element of cons(e, λ) is e.

A4

next(head(λ)) = head(tail(λ))

The box that follows the head is the head of the rest of the list.

Key points
  • A recursive list is either emptylist or cons(e, λ): an element followed by a list.
  • Only the head element is immediately accessible: first(λ), and its box head(λ). To reach the others, you remove the head with tail.
  • tail, head and first make no sense on the empty list: their precondition is λ ≠ emptylist.

Build lists and watch: cons always adds at the head, and only the head can be read.

Traps
  • cons takes the element first: cons(e, λ), never cons(λ, e). Its profile is element × list → list.
  • tail returns a list, first an element. first(tail(λ)) makes sense: it is the 2nd element. tail(first(λ)) does not: tail expects a list.

Part 3

Writing and evaluating a recursive list

A list is written between braces, in the order of its elements: {e1, e2, e3}. With the operations of the type, this list is written cons(e1, cons(e2, cons(e3, emptylist))).

The term is read from the inside out: you start from the empty list, and each cons adds an element at the head.

ListTerm
emptyemptylist
{e3}cons(e3, emptylist)
{e2, e3}cons(e2, cons(e3, emptylist))
{e1, e2, e3}cons(e1, cons(e2, cons(e3, emptylist)))
Key points
  • {e1, e2, e3} = cons(e1, cons(e2, cons(e3, emptylist))): one cons per element, in the order of the list, and emptylist at the very bottom.
  • The last element added is the head: e3 was added first, e1 last.
  • The k-th element is obtained with k − 1 tail, then first: the 3rd element of λ is first(tail(tail(λ))).

Evaluating a term

To compute a term, you rewrite it with the axioms, as in chapter 1. Here two axioms do all the work: A2, tail(cons(e, λ)) = λ, and A3, first(cons(e, λ)) = e. Each applies to a piece of the form “tail of a cons” or “first of a cons”.

If a tail or a first lands on emptylist, the precondition is violated: the term is undefined.

Your turn, with λ = {b, a, c}. Answer in your head, then open the answer.

Write λ with cons and emptylist.

cons(b, cons(a, cons(c, emptylist)))

What is first(tail(λ))?

a: A2 removes b, then A3 reads the new head.

What is tail(tail(tail(λ)))?

emptylist: the three tail remove the three elements.

And first(tail(tail(tail(λ))))?

Undefined: it is first(emptylist), which violates the precondition λ ≠ emptylist.

Why it is useful

Every non-empty list can be rebuilt from its two pieces: cons(first(λ), tail(λ)) = λ. Indeed, a non-empty list is written cons(e, λ′), and A3 and A2 give back e and λ′. You will use this in part 4.

Trap

emptylist is not an element, and a one-element list is not that element. cons(a, emptylist) is the list {a}; first(cons(a, emptylist)) is the element a.

Part 4

Defining a new operation on a recursive list

Typical exam exercise in 2023 and 2024: add an operation to the recursive list, giving its preconditions if there are any and its axioms.

The method comes from the definition itself: a list has only two forms, emptylist or cons(e, λ). So you write one axiom for each form. In the cons(e, λ) case, you can use the operation itself on λ, which has one element fewer: the axiom is recursive.

  1. The profile. Find the types of the arguments and of the result. If the operation returns a type the list does not use yet (integer, boolean), add it to uses.
  2. The preconditions. Ask yourself whether the operation makes sense on the empty list. If it does: no precondition, and say so. If not: … is-defined-iaoi λ ≠ emptylist.
  3. The emptylist case. Give the value directly, unless the precondition rules it out.
  4. The cons(e, λ) case. Express the result with e and with the operation applied to λ.
  5. Check on an example. Rewrite the operation on a list of two or three elements: you must get the right result.

Example 1: length

The recursive list has no operation that counts its elements. Let us add length : list → integer. The result is an integer: integer joins uses. The empty list has a length, 0: no precondition.

Case emptylist

No element.

length(emptylist) = 0

Case cons(e, λ)

One element more than λ.

length(cons(e, λ))
= length(λ) + 1

uses
    element, integer
operations
    length : list → integer
preconditions
    none
axioms
    length(emptylist) = 0
    length(cons(e, λ)) = length(λ) + 1
with
    list λ
    element e

Example 2: concatenate (exam of 30 October 2023)

The paper dealt with the recursive list without boxes. It added concatenate : list × list → list, which puts λ2 after λ, and asked for the axioms, with the preconditions if there are any.

Two lists as arguments: you split the first one. The result starts with the elements of λ, so if λ starts with e, the result does too. The second list is simply copied at the end.

Case emptylist

Nothing to put in front: λ2 remains.

concatenate(emptylist, λ2)
= λ2

Case cons(e, λ)

e stays at the head, followed by the concatenation of the rest of the list with λ2.

concatenate(cons(e, λ), λ2)
= cons(e, concatenate(λ, λ2))

operations
    concatenate : list x list → list
preconditions
    none
axioms
    concatenate(emptylist, λ2) = λ2
    concatenate(cons(e, λ), λ2) = cons(e, concatenate(λ, λ2))
with
    list λ, λ2
    element e
Why two axioms are enough

Every list is either emptylist or cons(e, λ): the two axioms cover all the cases (completeness) and do not contradict each other (consistency). Each use of the recursive axiom removes one element from the first list, so you always end up in the emptylist case. An axiom concatenate(λ, emptylist) = λ is not needed: it can be deduced from the other two (try “empty λ2” in the workshop).

In the workshop, the axioms of length are L1 and L2, those of concatenate C1 and C2; A2 and A3 are those of part 2. Change the terms to test other lists.

Key points: the method by cases
  • One axiom for emptylist, one axiom for cons(e, λ).
  • The cons(e, λ) case uses the operation on λ: that is the recursion.
  • A precondition only if the operation makes no sense on the empty list, like first or tail. Otherwise, write “none”.
Traps
  • Do not invent a precondition: length and concatenate make sense on empty lists.
  • If you write the non-empty case with first and tail, restrict it to non-empty lists: λ ≠ emptylist ⇒ concatenate(λ, λ2) = cons(first(λ), concatenate(tail(λ), λ2)). Without the condition, the axiom would also apply to emptylist, where first is not defined.
  • Add integer or boolean to uses if the operation needs it.

The iterative list: rank, access, nth, length

Second way to describe the same data: by ranks. This time, all the elements are accessible, by their rank. The type integer is used to represent ranks: the first element has rank 1, the last has rank length(λ).

types
    list, box
uses
    integer, element
operations
    emptylist : → list
       access : list x integer → box
     contents : box → element
          nth : list x integer → element
       length : list → integer
       delete : list x integer → list
       insert : list x integer x element → list
         next : box → box
OperationWhat it gives, on λ = {a, b, c}
access(λ, i)the box of the i-th element of λ
access(λ, 2): the box that holds b
nth(λ, i)the i-th element of λ
nth(λ, 2) = b
length(λ)the number of elements
length(λ) = 3
delete(λ, k)deletes the k-th element of λ
part 6
insert(λ, k, e)inserts e at rank k in λ
part 6

An iterative list is described by its length and by its elements, rank by rank. The course sheet defines λ = {e1, e2, e3} this way:

length(λ) = 3
nth(λ, 1) = e1
nth(λ, 2) = e2
nth(λ, 3) = e3

For now, one precondition and three axioms, numbered I1 to I3 in the workshop below:

preconditions
    access(λ, k) is-defined-iaoi λ ≠ emptylist & 1 ≤ k ≤ length(λ)
axioms
    length(emptylist) = 0
    contents(access(λ, k)) = nth(λ, k)
    next(access(λ, k)) = access(λ, k + 1)
with
    list λ
    integer k

The second axiom links the two readings: the contents of the k-th box is the k-th element. The third says that the box that follows the k-th is the (k + 1)-th. Together, they prove the erratum of part 1: contents(next(access(li, 2))) rewrites to nth(li, 3), the 3rd element.

Key points
  • All the elements are accessible by their rank, from 1 to length(λ).
  • access returns a box, nth an element: contents(access(λ, k)) = nth(λ, k).
  • An iterative list is known as soon as you know its length and nth(λ, i) for each rank i from 1 to length(λ). This is how a result is described in parts 6 and 7.
Traps
  • Ranks start at 1, not 0. The last element is nth(λ, length(λ)).
  • access is an internal operation (box is a defined type); nth and length are observers.
  • nth(λ, i) only makes sense for 1 ≤ i ≤ length(λ): no axiom speaks about the other ranks, even though the course sheet gives it no precondition.

Part 6

insert and delete: the ranks shift

Inserting or deleting an element in the middle of the list moves all those that follow. The axioms describe this shift rank by rank: for each rank i of the result, they say which element of λ is there.

First, the preconditions:

preconditions
    delete(λ, k) is-defined-iaoi λ ≠ emptylist & 1 ≤ k ≤ length(λ)
    insert(λ, k, e) is-defined-iaoi 1 ≤ k ≤ length(λ) + 1

delete(λ, k)

You can only delete an element that exists: k goes from 1 to length(λ). An empty list has nothing to delete.

insert(λ, k, e)

k can go up to length(λ) + 1: inserting at that rank means adding e at the end. You can also insert into an empty list, at rank 1.

Then the axioms. The first two give the length of the result; the others, its i-th element, with one case per range of ranks.

axioms
    length(delete(λ, k)) = length(λ) − 1
    length(insert(λ, k, e)) = length(λ) + 1

    1 ≤ i < k ⇒ nth(delete(λ, k), i) = nth(λ, i)
    k ≤ i ≤ length(λ) − 1 ⇒ nth(delete(λ, k), i) = nth(λ, i + 1)

    1 ≤ i < k ⇒ nth(insert(λ, k, e), i) = nth(λ, i)
    k = i ⇒ nth(insert(λ, k, e), i) = e
    k < i ≤ length(λ) + 1 ⇒ nth(insert(λ, k, e), i) = nth(λ, i − 1)
with
    list λ
    integer i, k
    element e

Reading the shifts

For each axiom, ask yourself the same question: the element that is at rank i of the result, at which rank was it in λ?

  1. Before k (1 ≤ i < k): nothing moved. The element is at the same rank: nth(λ, i).
  2. After a deletion (k ≤ i): the elements that followed rank k moved forward by one rank. The one that is now at rank i was just behind, at rank i + 1: nth(λ, i + 1).
  3. After an insertion: at rank k is the new element e. Beyond it (k < i), the elements moved back by one rank: the one that is at rank i was at rank i − 1, hence nth(λ, i − 1).
  4. The bounds: the last case stops at the length of the result. After delete, there is one element fewer: i goes up to length(λ) − 1. After insert, one more: i goes up to length(λ) + 1.

On λ = {a, b, c, d, e}, with k = 2:

Rank idelete(λ, 2) = {a, c, d, e}insert(λ, 2, x) = {a, x, b, c, d, e}
1nth(λ, 1) = a (i < k)nth(λ, 1) = a (i < k)
2nth(λ, 3) = c (k ≤ i)x (i = k)

Choose the operation and the rank k: the colors follow the cases of the axioms.

Key points
  • In the axioms, i is always a rank of the result.
  • Before k: same rank. After k: i + 1 for delete (the elements move forward), i − 1 for insert (they move back).
  • The bound of the last case is the length of the result: length(λ) − 1 after delete, length(λ) + 1 after insert.
Traps
  • The shifts seem backwards: delete removes an element, and yet the axiom says i + 1. That is normal: you go and look for the element further along in λ.
  • For delete, there is no separate i = k case: it is included in k ≤ i, because the element that followed takes the vacated spot.
  • insert accepts rank k = length(λ) + 1: it is an addition at the end. delete rejects it: that rank does not exist in λ.

Your turn, with λ = {a, b, c, d}.

What is nth(delete(λ, 3), 3)?

d: case k ≤ i ≤ length(λ) − 1 (3 ≤ 3 ≤ 3), so nth(λ, 4).

What is nth(insert(λ, 1, x), 4)?

c: case k < i ≤ length(λ) + 1 (1 < 4 ≤ 5), so nth(λ, 3).

What is length(insert(delete(λ, 1), 2, x))?

4: the deletion gives 4 − 1 = 3, the insertion 3 + 1 = 4.

Is insert(λ, 6, x) defined?

No: the precondition requires 6 ≤ length(λ) + 1, that is 6 ≤ 5, which is false.

Reading a mystery operation

Another exam exercise: an unknown operation on the iterative list, given only by its precondition and its axioms. You must compute its result on a concrete list. No need to guess what it does: the axioms are enough, exactly as for insert and delete.

Here is an operation mystery, written the way an exam would write it:

operations
    mystery : list x integer x integer → list
preconditions
    mystery(λ, x, y) is-defined-iaoi 1 ≤ x ≤ y ≤ length(λ)
axioms
    1 ≤ x ≤ y ≤ length(λ) ⇒ length(mystery(λ, x, y)) = length(λ) + y − x + 1
    1 ≤ x ≤ y ≤ length(λ) & 1 ≤ i ≤ y ⇒ nth(mystery(λ, x, y), i) = nth(λ, i)
    1 ≤ x ≤ y ≤ length(λ) & y < i ≤ length(λ) + y − x + 1
                ⇒ nth(mystery(λ, x, y), i) = nth(λ, i − y + x − 1)
with
    list λ
    integer x, y, i
  1. The precondition. Replace x, y and length(λ) with their values. If it is false, the result is undefined: you are done.
  2. The length of the result first. Compute it with the length axiom. It tells you how many ranks to fill.
  3. Each rank by its case. For i from 1 to that length, find the axiom whose condition contains i, then compute the rank to read in λ.
  4. Read and write. Read the elements in λ and write the result between braces. Count: there must be as many elements as the length.

Example: mystery(λ, 2, 3) with λ = {a, b, c, d, e}

Precondition: 1 ≤ 2 ≤ 3 ≤ 5, true. Length: 5 + 3 − 2 + 1 = 7. The seven ranks i remain to be filled. In the second case, the rank read in λ is i − y + x − 1, that is i − 3 + 2 − 1 = i − 2:

iCaseRank read in λElement
11 ≤ i ≤ y1a
21 ≤ i ≤ y2b
31 ≤ i ≤ y3c
4y < i ≤ 74 − 2 = 2b
5y < i ≤ 75 − 2 = 3c
6y < i ≤ 76 − 2 = 4d
7y < i ≤ 77 − 2 = 5e

Result: mystery(λ, 2, 3) = {a, b, c, b, c, d, e}. The piece from x to y, here b and c, is copied right after itself: mystery duplicates this piece. Finding this meaning is not required, but it is a good check.

Your turn: choose other arguments, write your answer, then check it or step through the calculation. One of the pairs does not satisfy the precondition.

Key points: the method
  1. The precondition, with the values.
  2. The length of the result: the number of ranks to fill.
  3. For each rank i, the case that contains it, then the rank to read in λ.
  4. The result between braces, with the right length.
Traps
  • The cases are about the rank i of the result, not that of λ.
  • Compute the formulas with the values: for x = 2 and y = 3, i − y + x − 1 is i − 2.
  • The axioms may repeat the precondition (1 ≤ x ≤ y ≤ length(λ) & …). It does not depend on i: check it only once, at the start.
  • With x = y, the piece has a single element: the formulas still apply.

Part 8

Recursive or iterative?

The course sheet says it from the start: there are several ways to describe a list, but it is still the same data, only the way you use it changes. The workshop at the top of the page shows it: for each element, it gives both notations.

Recursive list

A list is empty, or an element followed by a list. Only the head element is immediately accessible.

Operations: emptylist, cons, tail, head, first. A new operation is defined by cases: emptylist and cons(e, λ).

Iterative list

All the elements are accessible, by their rank. A list is known by its length and its nth.

Operations: emptylist, access, nth, length, insert, delete. A result is described by its length and one case per range of ranks.

The same question, two notations

Which one to use?

  • First look at the operations the question gives you. If they are cons, tail, first, reason by cases emptylist / cons(e, λ). If they are nth, length, insert, describe the result by its length and its nth.
  • The recursive description is natural for processing that walks through the list from the head: counting, concatenating, removing some elements.
  • The iterative description is required as soon as a rank matters: reading the k-th element, inserting or deleting in the middle.

  • Recursive and iterative describe the same list; only the way you use it changes.
  • Recursive: only the head is accessible, you reason by cases emptylist / cons(e, λ).
  • Iterative: everything is accessible by rank, you reason with the length and with ranges of ranks.
Trap

Do not mix the two sets of operations in the same answer. If the paper gives you the recursive list, nth and length do not exist, unless you define them yourself as in part 4.
