A list is an array or a chain.

In TAA, the list was an abstract type: operations and axioms, with no memory. Here we really store it in memory. There are two ways: in an array (static implementation) or in records linked by pointers (dynamic implementation). The choice changes the cost of each operation. In Python the list is already provided: what remains is to use it well.

From abstract type to memory

The two lists of TAA are not handled in the same way:

  • the recursive list is only worked on through its head: emptylist, cons (add at the head), head / first, tail (the rest);
  • the iterative list is worked on through positions: length, nth(λ, k), insert and delete at the k-th position.

When a language already provides a list (Caml lists, Python list, ArrayList and LinkedList in Java), we use it. Otherwise we have to choose a memory representation and write the operations ourselves. That is the subject of this course.

Homework trap no. 1

An algorithm written “for i ← 1 to length(λ)” becomes in Python for i in range(len(L)), which makes i go from 0 to len(L) - 1. Copying the algorithm’s bounds gives an index error or skips an element.

Recursive list in an array

Representation static

A record that contains the array of elements and an integer: the position of the head. The elements are stored one after another; the head is the last one stored.

“Static”: the memory for the whole array is reserved at creation. The number of elements is therefore limited; enlarging is possible but costly (copying into a bigger array).

Costs sheet § 1.2.2
  • Access to the k-th element is immediate.
  • Inserting or deleting forces us to move (with a loop) all the elements from the target position to the end.
  • For a list of length n: at most n − 1 assignments. The worst case is insertion or deletion at the first position.

We shift e one cell to the right, then write c in cell 2, and the length goes from 2 to 3.shift first, from the end

Deleting at the 2nd position does the opposite: we shift the following elements to the left, then the length decreases by 1. Deleting the last position: we only decrease the length.

Traps
  • Shifting to the right starting from the beginning: each cell overwrites the next one. To insert, we shift starting from the end.
  • Inserting into a full array (length = LMax): impossible without enlarging it.

Recursive linked list

Representation dynamic, linked

Each element is in a record with two fields: the value and a pointer to the next record (null for the last one). The list is a pointer to the first record, or the null pointer if it is empty.

Removing the head: we move the head pointer to the next element, then free the memory of the detached record.

Summary of the video: with the array as with linking, the operations of recursive lists take constant time, which does not depend on the size of the list (except when enlarging the array). Using a recursive list therefore does not change the complexity of an algorithm.

Traps
  • Writing L ← new before new↑.next ← L: new points to itself, the list is lost.
  • Forgetting to free the deleted record.

Iterative linked list

An iterative list can also be implemented by linking. What we gain: no more shifting of values. What we lose: direct access.

  • nth(λ, k): from the first element, we follow k − 1 links. For the 4th element: 3 links.
  • Insert at the k-th position: we create the record, traverse up to the previous one, the new one points to the old k-th, then the previous one points to the new one. At the first position, it is the head pointer that changes.
  • Delete the k-th position: the pointer of the previous one takes the address of the next one, then we free the record. We therefore have to keep access to the previous one during the traversal.
  • Length: we have to traverse everything, unless we store it.

Improvements mentioned in the video
  • Store the length: the list becomes a record ⟨head pointer, length⟩. We immediately reject an impossible operation, such as deleting the 8th element of a list of 5. The length increases by 1 at each addition and decreases by 1 at each deletion.
  • Circular list: the next of the last one is the first one, and the list points to the last one: we have access to both ends.
  • Double linking: each element also points to its previous one; the list keeps a head pointer, an end pointer and the length.

The Python list is an array that enlarges itself: L[i] is a direct access, L.append(x) adds at the end without shifting, and inserting at the beginning shifts everything. These are exactly the costs of the “array” column.

def count(x, L):
    cpt = 0
    for i in range(len(L)):
        if L[i] == x:
            cpt += 1
    return cpt

Tutorial 1, ex. 1.1 (1): “for i ← 1 to length(λ)” becomes range(len(L)).

def is_present(x, L):
    i = 0
    while i < len(L) and L[i] != x:
        i += 1
    return i < len(L)

Tutorial 1, ex. 1.1 (2): “return (i <= length(λ))” becomes i < len(L).

Delete in place Tutorial 1, ex. 1.2

Precondition: 1 ≤ k ≤ length(λ). The axioms say: before k, nothing moves; from k on, the i-th becomes the old (i + 1)-th; the length decreases by 1. This is the deletion with shift from part 3.

def delete(L, k):          # k: algo position, from 1 to len(L)
    if not (1 <= k <= len(L)):
        raise Exception("invalid position")
    for i in range(k - 1, len(L) - 1):
        L[i] = L[i + 1]       # shift to the left
    L.pop()                   # the length decreases by 1

>>> L = [10, 20, 30, 40, 50]
>>> delete(L, 2)
>>> L
[10, 30, 40, 50]

def new_list(n, val):
    L = []
    for i in range(n):
        L.append(val)
    return L

Tutorial 1, ex. 2.1: new_list(5, 42) gives [42, 42, 42, 42, 42]; [val] * n does the same thing.

Python traps
  • M = L does not copy: both names refer to the same list. After M.append(4), L has changed too.
  • L[len(L)] raises IndexError: the last index is len(L) - 1.
  • L.append(x) returns None: L = L.append(x) loses the list.
