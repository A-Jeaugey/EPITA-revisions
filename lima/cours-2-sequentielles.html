Chercher un élément, une case après l’autre.

La recherche séquentielle compare la clé cherchée à chaque élément, du premier au dernier, jusqu’à la trouver ou sortir de la liste. C’est la plus simple des recherches, elle marche sur toutes les listes, et elle coûte jusqu’à n comparaisons. Sur une liste triée, on peut s’arrêter dès qu’on a dépassé la clé ; sur une liste non triée, on peut rapprocher de la tête les éléments souvent cherchés.

  • Parties 6
  • Cours MiMos de la semaine du 16 novembre

Le vocabulaire des recherches

Pour manipuler des données (les modifier, les supprimer…), il faut d’abord les trouver. Chaque élément est représenté par une clé ; on cherche un élément par sa clé, le plus vite possible, qu’il soit présent ou non.

Définitions
  • Une recherche est associative quand le critère ne porte que sur la valeur de la clé de l’élément cherché. (Chercher « les éléments présents depuis plus de six mois » ne serait pas associatif.)
  • Une recherche est positive quand la clé cherchée est présente dans la collection.
  • Une recherche est négative quand la clé cherchée est absente.
Comment on compte

L’opération fondamentale est la comparaison de la clé cherchée x à une clé de la liste. Les complexités s’expriment en fonction de n, la longueur de la liste.

Remarque de la vidéo

C’est la recherche négative qui doit être la plus rapide : un utilisateur supporte encore moins d’attendre quand la recherche échoue.

Recherche séquentielle dans une liste non triée

Principe

def rechercher(L, x):
    i = 0
    while i < len(L) and L[i] != x:
        i += 1
    return i < len(L)

La deuxième version en Python : les indices vont de 0 à len(L) - 1, donc « i ≤ longueur » devient i < len(L).

Complexité
  • Négative : n comparaisons, dans tous les cas.
  • Positive : n au pire (x est le dernier) ; sur un grand nombre de recherches, n / 2 en moyenne.

La liste peut être implémentée en tableau ou en chaîné : on la parcourt dans l’ordre, sans accès direct.

La recherche auto-adaptative

Pour une recherche positive, le coût est la position de l’élément. On ne connaît pas à l’avance quels éléments seront les plus demandés ; alors on les fait avancer vers la tête au fur et à mesure qu’on les cherche. Les éléments souvent recherchés finissent en début de liste.

Chercher 4 dans [12, 2, 31, 4, 25]

Agressive : [4, 12, 2, 31, 25]. Molle : [12, 2, 4, 31, 25].résultats obtenus en exécutant le code ci-dessous

def search_aggressive(L, x):
    for i in range(len(L)):
        if L[i] == x:
            for j in range(i, 0, -1):
                L[j] = L[j - 1]   # décalages
            L[0] = x
            return True
    return False

def search_soft(L, x):
    for i in range(len(L)):
        if L[i] == x:
            if i > 0:             # un échange
                L[i - 1], L[i] = L[i], L[i - 1]
            return True
    return False
À retenir
  • La recherche auto-adaptative ne s’applique pas aux listes triées : elle change l’ordre des éléments.
  • Elle améliore les recherches positives. Une recherche négative coûte toujours n.
  • Conclusion de la fiche : toutes les recherches séquentielles s’implémentent en contigu ou en chaîné, sauf l’agressive en contigu (décalages coûteux).

Recherche séquentielle dans une liste triée

Principe

La liste est triée en ordre croissant. Tant qu’il reste des éléments et que l’élément courant n’a pas dépassé x, on avance. On a trouvé x si on n’a pas parcouru toute la liste et si l’élément où l’on s’est arrêté est x.

Le gain : une recherche négative s’arrête dès qu’on dépasse x, au lieu d’aller jusqu’au bout.

Chercher 4 : −11, −2, 1, puis 4. Positive, 4 comparaisons.

Chercher 18 : −11, −2, 1, 4, 15 sont plus petits ; 63 dépasse 18 : on s’arrête. Négative, 6 comparaisons au lieu de 7.plus loin, tout est encore plus grand

Complexité

Positive ou négative, c’est la même : n au pire (x est le dernier, ou plus grand que le dernier), n / 2 en moyenne. Implémentable en contigu ou en chaîné. Pas de recherche auto-adaptative sur une liste triée.

Piège

La note de la fiche : la première version fait 2 comparaisons par tour de boucle (x ≥ … puis x = …), la deuxième une seule, plus une égalité à la fin. La deuxième est meilleure.

Complexité linéaire

Même si la recherche dans une liste triée est un peu plus efficace, toutes ces recherches sont en O(n). Sur un grand nombre d’éléments, la fiche conseille des recherches plus efficaces : la recherche dichotomique (semaine du 23 novembre) et la recherche par interpolation (semaine du 30 novembre), au programme du DM 2.

Parcours de listes en Python (TD 1)

Le DM porte aussi sur « TD : parcours des listes en Python ». Deux formes de parcours reviennent : le parcours complet (for, on regarde tout) et le parcours interrompu (while avec deux conditions, on s’arrête dès que la réponse est connue).

Histogramme TD 1, ex. 2.2

Une liste de 256 compteurs, un par code ASCII : H[ord(c)] compte les c. On parcourt la chaîne une seule fois.

def histogram(s):
    H = [0] * 256
    for c in s:
        H[ord(c)] += 1
    return H

def nb_different(s):
    cpt = 0
    for v in histogram(s):
        if v != 0:
            cpt += 1
    return cpt

def most_frequent(s):
    H = histogram(s)
    imax = 0
    for i in range(1, 256):
        if H[i] > H[imax]:
            imax = i
    return chr(imax), H[imax]

>>> nb_different("character")
6
>>> most_frequent("character")
('a', 2)
>>> most_frequent("abracadabra")
('a', 5)
Position dans une liste triée TD 1, ex. 3.1

La recherche séquentielle sur liste triée (partie 4), qui renvoie la position du premier x, ou −1.

def search_sorted(x, L):
    i = 0
    while i < len(L) and L[i] < x:
        i += 1
    if i < len(L) and L[i] == x:
        return i
    return -1

>>> search_sorted(5, [1, 3, 5, 5, 8]), search_sorted(4, [1, 3, 5, 8])
(2, -1)

def replace(L, k, new_v):
    i = 0
    while i < len(L) and L[i][0] < k:
        i += 1
    if i < len(L) and L[i][0] == k:
        L[i] = (k, new_v)   # tuple : on remplace le couple

TD 1, ex. 3.2 : L[i][1] = new_v lève TypeError, un tuple est immuable.

def is_sorted(L):
    i = 1
    while i < len(L) and L[i - 1] <= L[i]:
        i += 1
    return i >= len(L)

TD 1, ex. 3.3 : on s’arrête au premier couple de voisins mal rangé. is_sorted([]) et is_sorted([4]) valent True.

Pièges
  • Dans while i < len(L) and L[i] != x, le test d’indice vient en premier : and s’arrête au premier faux, donc L[i] n’est jamais lu hors de la liste.
  • Après la boucle, on ne sait pas encore pourquoi elle s’est arrêtée : on reteste i < len(L) avant de lire L[i].
  • Un parcours interrompu se fait avec while (ou un return dans le for) : un for qui va jusqu’au bout fait des comparaisons inutiles.
