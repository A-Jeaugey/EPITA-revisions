Cut the list in half, then in half again.

On a sorted list stored in an array, we can look straight at the middle: if x is not there, we know which side to search, and half of the list disappears with each comparison. That is binary search, in log₂(n). Interpolation does better when the keys are well spread: it aims at the likely position of x, the way you open a dictionary near the start to look up “aardvark”.

Part 1 sheet § 1 · video “Binary search”

The principle: divide and conquer

Two conditions
  • The list must be sorted.
  • It must use the contiguous representation (static, an array): we can reach any position directly. On a linked list, reaching the middle would require a traversal: binary search is not applicable.
Principle

Let mid be the middle position of the list.

  • If x = nth(L, mid): the search is positive.
  • If x < nth(L, mid): we carry on in the lower half (to the left of mid).
  • If x > nth(L, mid): we carry on in the upper half (to the right of mid).

If we reach an empty sublist, the search is negative.

Part 2 sheet § 1, “The algorithm” · Tutorial 1 ex. 4.1

The algorithm: recursive, iterative, Python

We work between two bounds, left and right. Called with 1 and length(L), the function returns the position of x if the search is positive, 0 otherwise.

function binary_search(list L, element x,
                       integer left, right) : integer
begin
  if left > right then
    return 0
  else
    mid ← (left + right) div 2
    if x = nth(L, mid) then
      return mid
    else if x < nth(L, mid) then
      return binary_search(L, x, left, mid-1)
    else
      return binary_search(L, x, mid+1, right)
    end if
  end if
end
/* iterative version */
left ← 1
right ← length(L)
while left <= right do
  mid ← (left + right) div 2
  if x = nth(L, mid) then
    return mid
  else if x < nth(L, mid) then
    right ← mid - 1
  else
    left ← mid + 1
  end if
end while
return 0
def binary_search(L, x):
    left, right = 0, len(L) - 1
    while left <= right:
        mid = (left + right) // 2
        if L[mid] == x:
            return mid
        elif x < L[mid]:
            right = mid - 1
        else:
            left = mid + 1
    return -1

In Python, indices start at 0: “absent” can no longer be 0, so we return −1. // is integer division (div).

Recursive or iterative?

The recursive version is tail-recursive: nothing is left to do when the calls return. Turning it into a loop is immediate: the stopping condition becomes the while condition, and the calls become updates of left or right. The complexity is the same; the iterative version only saves machine time (and many compilers already run a tail recursion as a loop).

Traps
  • Forgetting the −1 or the +1: with right = mid instead of right = mid - 1, the loop may never end.
  • The condition is left <= right (a sublist of one element still exists when left = right).
  • The sheet also writes mid ← left + (right − left) div 2: same result, without overflowing the integer range in languages where that can happen.

Part 3 sheet, “Decision tree and complexity”

The decision tree, the complexity

The decision tree represents every possible run on a list of n elements. Each internal node holds the interval [left, right] and the middle index; we go left if x is smaller, right if it is larger. The leaves are the cases where the bounds cross: negative search.

Read in the in-order of the tree, the middles give every position 1, 2, …, n: no element can escape the search.

Complexity sheet
  • Each internal node costs 2 comparisons (x = … ? then x < … ?).
  • Negative search: 2h + 1 comparisons, h being the depth of the node where we stop.
  • Positive search: 2(H + 1) comparisons at worst, H being the height of the tree.
  • The tree is balanced: its height is ⌈log₂(n)⌉. The complexity is logarithmic, in every case.

Linear search: O(n). Binary search: O(log₂(n)). But binary search requires a sorted, contiguous list.

Part 4 sheet, “Variant: searching for the first occurrence”

Finding the first occurrence

If x appears several times, binary search stops on one of them, not necessarily the first. For the first one: when x ≤ nth(L, mid), instead of stopping, we carry on to the left while keeping mid (right ← mid). We stop when left = right.

function binary_search_first(list L,
          element x, integer left, right) : integer
/* list not empty at the start */
mid ← (left + right) div 2
while left < right do
  if x <= nth(L, mid) then
    right ← mid
  else
    left ← mid + 1
  end if
  mid ← (left + right) div 2
end while
if nth(L, left) = x then
  return mid
else
  return 0
end if
def first_occurrence(L, x):    # L not empty
    left, right = 0, len(L) - 1
    while left < right:
        mid = (left + right) // 2
        if x <= L[mid]:
            right = mid
        else:
            left = mid + 1
    if L[left] == x:
        return left
    return -1

>>> L = [1, 2, 2, 2, 5, 7]
>>> binary_search(L, 2), first_occurrence(L, 2)
(2, 1)
Traps
  • The loop is left < right (not ≤) and we write right = mid (not mid − 1): mid may be the first occurrence, it must not be excluded.
  • On exit, left = right = mid: we check that the cell really contains x.

Part 5 sheet § 2 · video “Linear interpolation search”

Linear interpolation search

Same principle as binary search, same conditions (sorted, contiguous list). Only the choice of the examined position changes: instead of the middle, we estimate the likely position of x, assuming the values are spread linearly between nth(L, left) and nth(L, right) (intercept theorem).

The formula sheet § 2
\[\text{slope} = \frac{\text{right} - \text{left}}{\text{nth}(L, \text{right}) - \text{nth}(L, \text{left})}\]
\[p = \text{left} + \big(x - \text{nth}(L, \text{left})\big) \times \text{slope}\]

In the binary search algorithm, we replace mid ← (left + right) div 2 with

p ← left + (x - nth(L, left)) * (right - left)
        div (nth(L, right) - nth(L, left))

when left < right.

Example 20 regular keys: 10, 20, …, 200 (positions 1 to 20)

Search for 130: p = 1 + (130 − 10) × (20 − 1) div (200 − 10) = 1 + 120 × 19 div 190 = 1 + 12 = 13. Cell 13 contains 130: found at the first try.binary search examines 10, 15, 12, then 13

Limits sheet
  • We need a good interpolation function: ideally, the keys are spread uniformly.
  • Computing p costs more than a middle: a loss of time that is not always negligible.
  • The list has to be very large for log₂(log₂(n)) to be really smaller than log₂(n).
