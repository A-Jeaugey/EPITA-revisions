Algo LiMa · Cours 3 · au DM 2

Couper la liste en deux, puis encore en deux.

Sur une liste triée rangée dans un tableau, on peut regarder directement au milieu : si x n’y est pas, on sait de quel côté chercher, et la moitié de la liste disparaît à chaque comparaison. C’est la dichotomie, en log₂(n). L’interpolation fait mieux quand les clés sont bien réparties : elle vise la place probable de x, comme on ouvre un dictionnaire au début pour chercher « cacahuète ».

Partie 1 fiche § 1 · vidéo « Recherche dichotomique »

Le principe : diviser pour régner

Deux conditions
  • La liste doit être triée.
  • Elle doit être en représentation contiguë (statique, un tableau) : on accède directement à n’importe quelle place. Sur une liste chaînée, atteindre le milieu demanderait un parcours : la dichotomie n’est pas applicable.
Principe

Soit m la place du milieu de la liste.

  • Si x = ième(L, m) : la recherche est positive.
  • Si x < ième(L, m) : on continue sur la moitié inférieure (à gauche de m).
  • Si x > ième(L, m) : on continue sur la moitié supérieure (à droite de m).

Si on arrive à une sous-liste vide, la recherche est négative.

L’algorithme : récursif, itératif, Python

On travaille entre deux bornes g (gauche) et d (droite). Appelée avec 1 et longueur(L), la fonction renvoie la position de x si la recherche est positive, 0 sinon.

fonction dichotomie(liste L, élément x,
                    entier g, d) : entier
debut
  si g > d alors
    retourne 0
  sinon
    m ← (g + d) div 2
    si x = ième(L, m) alors
      retourne m
    sinon si x < ième(L, m) alors
      retourne dichotomie(L, x, g, m-1)
    sinon
      retourne dichotomie(L, x, m+1, d)
    fin si
  fin si
fin
/* version itérative */
g ← 1
d ← longueur(L)
tant que g <= d faire
  m ← (g + d) div 2
  si x = ième(L, m) alors
    retourne m
  sinon si x < ième(L, m) alors
    d ← m - 1
  sinon
    g ← m + 1
  fin si
fin tant que
retourne 0
def binary_search(L, x):
    g, d = 0, len(L) - 1
    while g <= d:
        m = (g + d) // 2
        if L[m] == x:
            return m
        elif x < L[m]:
            d = m - 1
        else:
            g = m + 1
    return -1

En Python, les indices commencent à 0 : « absent » ne peut plus être 0, on renvoie −1. // est la division entière (div).

Récursif ou itératif ?

La version récursive est terminale : rien à faire au retour des appels. La transformer en boucle est immédiat : la condition d’arrêt devient la condition du tant que, et les appels deviennent la modification de g ou de d. La complexité est la même ; la version itérative gagne seulement du temps machine (et beaucoup de compilateurs exécutent déjà une récursion terminale comme une boucle).

Pièges
  • Oublier le −1 ou le +1 : avec d = m au lieu de d = m - 1, la boucle peut tourner sans fin.
  • La condition est g <= d (une sous-liste d’un élément existe encore quand g = d).
  • La fiche écrit aussi m ← g + (d − g) div 2 : même résultat, sans dépasser la capacité des entiers dans les langages où c’est possible.

L’arbre de décision, la complexité

L’arbre de décision représente toutes les exécutions possibles sur une liste de n éléments. Chaque nœud interne porte l’intervalle [g, d] et l’indice du milieu ; on descend à gauche si x est plus petit, à droite s’il est plus grand. Les feuilles sont les cas où les bornes se croisent : recherche négative.

Les milieux, lus dans l’ordre infixe de l’arbre, donnent toutes les positions 1, 2, …, n : aucun élément ne peut échapper à la recherche.

Complexité fiche
  • Chaque nœud interne coûte 2 comparaisons (x = … ? puis x < … ?).
  • Recherche négative : 2h + 1 comparaisons, h étant la profondeur du nœud où l’on s’arrête.
  • Recherche positive : 2(H + 1) comparaisons au pire, H étant la hauteur de l’arbre.
  • L’arbre est équilibré : sa hauteur est ⌈log₂(n)⌉. La complexité est logarithmique, dans tous les cas.

Séquentielle : O(n). Dichotomie : O(log₂(n)). Mais la dichotomie exige une liste triée et contiguë.

Trouver la première occurrence

Si x apparaît plusieurs fois, la dichotomie s’arrête sur l’une d’elles, pas forcément la première. Pour la première : quand x ≤ ième(L, m), au lieu de s’arrêter, on continue à gauche en gardant m (d ← m). On s’arrête quand g = d.

fonction dichotomie_prems(liste L,
          élément x, entier g, d) : entier
/* liste non vide au départ */
m ← (g + d) div 2
tant que g < d faire
  si x <= ième(L, m) alors
    d ← m
  sinon
    g ← m + 1
  fin si
  m ← (g + d) div 2
fin tant que
si ième(L, g) = x alors
  retourne m
sinon
  retourne 0
fin si
def first_occurrence(L, x):    # L non vide
    g, d = 0, len(L) - 1
    while g < d:
        m = (g + d) // 2
        if x <= L[m]:
            d = m
        else:
            g = m + 1
    if L[g] == x:
        return g
    return -1

>>> L = [1, 2, 2, 2, 5, 7]
>>> binary_search(L, 2), first_occurrence(L, 2)
(2, 1)
Pièges
  • La boucle est g < d (pas ≤) et on écrit d = m (pas m − 1) : m peut être la première occurrence, il ne faut pas l’exclure.
  • À la sortie, g = d = m : on vérifie que la case contient bien x.

La recherche par interpolation linéaire

Même principe que la dichotomie, mêmes conditions (liste triée, contiguë). Seul change le choix de la place examinée : au lieu du milieu, on estime la place probable de x en supposant les valeurs réparties linéairement entre ième(L, g) et ième(L, d) (théorème de Thalès).

La formule fiche § 2
\[\text{pente} = \frac{d - g}{\text{ième}(L, d) - \text{ième}(L, g)} \qquad p = g + \big(x - \text{ième}(L, g)\big) \times \text{pente}\]

Dans l’algorithme de la dichotomie, on remplace m ← (g + d) div 2 par

p ← g + (x - ième(L, g)) * (d - g) div (ième(L, d) - ième(L, g))

lorsque g < d.

Exemple 20 clés régulières : 10, 20, …, 200 (positions 1 à 20)

Chercher 130 : p = 1 + (130 − 10) × (20 − 1) div (200 − 10) = 1 + 120 × 19 div 190 = 1 + 12 = 13. La case 13 contient 130 : trouvé du premier coup.la dichotomie examine 10, 15, 12, puis 13

Limites fiche
  • Il faut une bonne fonction d’interpolation : l’idéal est une répartition uniforme des clés.
  • Le calcul de p coûte plus cher qu’un milieu : perte de temps pas forcément négligeable.
  • Il faut une liste très grande pour que log₂(log₂(n)) soit vraiment plus petit que log₂(n).
