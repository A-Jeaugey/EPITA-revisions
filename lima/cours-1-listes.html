Une liste, c’est un tableau ou une chaîne.

En TAA, la liste était un type abstrait : des opérations et des axiomes, sans mémoire. Ici on la range vraiment en mémoire. Deux façons : dans un tableau (implémentation statique) ou en enregistrements reliés par des pointeurs (implémentation dynamique). Le choix change le coût de chaque opération. En Python, la liste est déjà fournie : il reste à bien l’utiliser.

Du type abstrait à la mémoire

Les deux listes de TAA ne se manipulent pas de la même façon :

  • la liste récursive ne se travaille que par la tête : liste-vide, cons (ajout en tête), tête / first, fin (le reste) ;
  • la liste itérative se travaille par les places : longueur, ième(λ, k), insérer et supprimer à la k-ième place.

Quand un langage fournit déjà une liste (les listes Caml, les list de Python, ArrayList et LinkedList en Java), on l’utilise. Sinon, il faut choisir une représentation mémoire et écrire soi-même les opérations. C’est l’objet de ce cours.

Piège n° 1 du DM

Un algorithme écrit « pour i ← 1 jusqu’à longueur(λ) » devient en Python for i in range(len(L)), qui fait varier i de 0 à len(L) - 1. Recopier les bornes de l’algo donne une erreur d’indice ou oublie un élément.

Liste récursive dans un tableau

Représentation statique

Un enregistrement qui contient le tableau des éléments et un entier : la position de la tête. Les éléments sont rangés à la suite ; la tête est le dernier rangé.

« Statique » : la mémoire de tout le tableau est réservée dès la création. Le nombre d’éléments est donc limité ; agrandir est possible mais coûte (recopie dans un tableau plus grand).

Coûts fiche § 1.2.2

Chaque élément est dans un enregistrement à deux champs : la valeur et un pointeur vers l’enregistrement suivant (nul pour le dernier). La liste est un pointeur sur le premier enregistrement, ou le pointeur nul si elle est vide.

L’ordre compte : le nouvel enregistrement pointe sur l’ancienne tête avant que L ne change.

Supprimer la tête : on fait avancer le pointeur de tête sur l’élément suivant, puis on libère la mémoire de l’enregistrement détaché.

Bilan de la vidéo : avec le tableau comme avec le chaînage, les opérations des listes récursives se font en temps constant, qui ne dépend pas de la taille de la liste (sauf agrandissement du tableau). Utiliser une liste récursive ne change donc pas la complexité d’un algorithme.

Pièges
  • Écrire L ← new avant new↑.suiv ← L : new pointe sur lui-même, la liste est perdue.
  • Oublier de libérer l’enregistrement supprimé.

Liste itérative chaînée

On peut aussi implémenter une liste itérative par chaînage. On gagne : plus aucun décalage de valeurs. On perd : l’accès direct.

  • ième(λ, k) : depuis le premier élément, on suit k − 1 liens. Pour le 4e élément : 3 liens.
  • Insérer en k-ième place : on crée l’enregistrement, on parcourt jusqu’au précédent, le nouveau pointe sur l’ancien k-ième, puis le précédent pointe sur le nouveau. En première place, c’est le pointeur de tête qui change.
  • Supprimer la k-ième place : le pointeur du précédent prend l’adresse du suivant, puis on libère l’enregistrement. Il faut donc garder l’accès au précédent pendant le parcours.
  • Longueur : il faut tout parcourir, sauf si on la stocke.

Améliorations citées par la vidéo
  • Stocker la longueur : la liste devient un enregistrement ⟨pointeur de tête, longueur⟩. On refuse tout de suite une opération impossible, comme supprimer le 8e élément d’une liste de 5. La longueur augmente de 1 à chaque ajout et diminue de 1 à chaque suppression.
  • Liste circulaire : le suivant du dernier est le premier, et la liste pointe sur le dernier : on a accès aux deux extrémités.
  • Double chaînage : chaque élément pointe aussi sur son précédent ; la liste garde un pointeur de tête, un pointeur de fin et la longueur.

 Conclusion de la vidéo : pour les listes itératives, aucune des deux représentations n’a toutes ses opérations en temps constant.

La list de Python est un tableau qui s’agrandit tout seul : L[i] est un accès direct, L.append(x) ajoute à la fin sans décalage, et insérer au début décale tout. Ce sont exactement les coûts de la colonne « tableau ».

def compte(x, L):
    cpt = 0
    for i in range(len(L)):
        if L[i] == x:
            cpt += 1
    return cpt

TD 1, ex. 1.1 (1) : « pour i ← 1 jusqu’à longueur(λ) » devient range(len(L)).

def est_present(x, L):
    i = 0
    while i < len(L) and L[i] != x:
        i += 1
    return i < len(L)

TD 1, ex. 1.1 (2) : « retourne (i <= longueur(λ)) » devient i < len(L).

>>> compte(3, [1, 3, 2, 3, 3])
3
>>> est_present(2, [5, 2, 7]), est_present(4, [5, 2, 7]), est_present(1, [])
(True, False, False)
Supprimer en place TD 1, ex. 1.2

Précondition : 1 ≤ k ≤ longueur(λ). Les axiomes disent : avant k, rien ne bouge ; à partir de k, le i-ème devient l’ancien (i + 1)-ième ; la longueur diminue de 1. C’est la suppression avec décalage de la partie 3.

def supprimer(L, k):          # k : place algo, de 1 à len(L)
    if not (1 <= k <= len(L)):
        raise Exception("position invalide")
    for i in range(k - 1, len(L) - 1):
        L[i] = L[i + 1]       # décalage vers la gauche
    L.pop()                   # la longueur diminue de 1

>>> L = [10, 20, 30, 40, 50]
>>> supprimer(L, 2)
>>> L
[10, 30, 40, 50]

def new_list(n, val):
    L = []
    for i in range(n):
        L.append(val)
    return L

TD 1, ex. 2.1 : new_list(5, 42) donne [42, 42, 42, 42, 42] ; [val] * n fait la même chose.

Pièges Python
  • M = L ne copie pas : les deux noms désignent la même liste. Après M.append(4), L a aussi changé.
  • L[len(L)] lève IndexError : le dernier indice est len(L) - 1.
  • L.append(x) renvoie None : L = L.append(x) perd la liste.
