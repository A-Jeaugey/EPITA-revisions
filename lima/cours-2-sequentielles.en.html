Looking for an element, one cell after the other.

Linear (sequential) search compares the searched key with each element, from the first to the last, until it finds it or leaves the list. It is the simplest search, it works on every list, and it costs up to n comparisons. On a sorted list, we can stop as soon as we have gone past the key; on an unsorted list, we can bring the often-searched elements closer to the head.

Part 1 sheet, introduction · video “Searches: introduction”

The vocabulary of searches

To handle data (modify it, delete it…), we first have to find it. Each element is represented by a key; we look for an element by its key, as fast as possible, whether it is present or not.

Definitions
  • A search is associative when the criterion only concerns the value of the key of the searched element. (Looking for “the elements present for more than six months” would not be associative.)
  • A search is positive (successful) when the searched key is present in the collection.
  • A search is negative (unsuccessful) when the searched key is absent.
How we count

The fundamental operation is the comparison of the searched key x with a key of the list. Complexities are expressed as a function of n, the length of the list.

Remark from the video

It is the negative search that should be the fastest: a user is even less willing to wait when the search fails.

Linear search in an unsorted list

Principle

We start on the first element. As long as elements remain and the current element is not x, we move on. If we have traversed the whole list, the search is negative; otherwise, we stopped on x.

function rechercher(list L, element x) : boolean
variables
    integer i
begin
    i ← 1
    while i <= length(L) do
        if x = nth(L, i) then
            return true
        end if
        i ← i + 1
    end while
    return false
end
/* Other version */
i ← 1
while i <= length(L)
      and x <> nth(L, i) do
    i ← i + 1
end while
return (i <= length(L))
def rechercher(L, x):
    i = 0
    while i < len(L) and L[i] != x:
        i += 1
    return i < len(L)

The second version in Python: indices go from 0 to len(L) - 1, so “i ≤ length” becomes i < len(L).

Complexity
  • Negative: n comparisons, in every case.
  • Positive: n in the worst case (x is the last one); over a large number of searches, n / 2 on average.

The list can be implemented as an array or as a linked list: we traverse it in order, without direct access.

Self-adjusting search

For a positive search, the cost is the position of the element. We do not know in advance which elements will be requested most; so we make them move towards the head as we search for them. The often-searched elements end up at the beginning of the list.

VariantFor each element found…DrawbackContiguous / linked
aggressivewe place it directly at the headputs very rarely searched elements at the headlinked only: in an array, all the elements before it have to be shifted
softwe move it forward by one placevery slow progress: 2,000 searches to bring the element at position 2,001 to the headboth: a simple swap of two neighbours
reasonablewe move it forward by a certain number of places, for example half of its distance to the head—both, but linked is the most interesting: a second pointer that advances half as fast gives the future position, without shifting

Aggressive: [4, 12, 2, 31, 25]. Soft: [12, 2, 4, 31, 25].results obtained by running the code below

def search_aggressive(L, x):
    for i in range(len(L)):
        if L[i] == x:
            for j in range(i, 0, -1):
                L[j] = L[j - 1]   # shifts
            L[0] = x
            return True
    return False

def search_soft(L, x):
    for i in range(len(L)):
        if L[i] == x:
            if i > 0:             # one swap
                L[i - 1], L[i] = L[i], L[i - 1]
            return True
    return False
To remember
  • Self-adjusting search does not apply to sorted lists: it changes the order of the elements.
  • It improves positive searches. A negative search always costs n.
  • Conclusion of the sheet: all linear searches can be implemented in a contiguous or linked list, except the aggressive one in a contiguous list (costly shifts).

Linear search in a sorted list

Principle

The list is sorted in increasing order. As long as elements remain and the current element has not gone past x, we move on. We have found x if we have not traversed the whole list and if the element where we stopped is x.

The gain: a negative search stops as soon as we go past x, instead of going to the end.

i ← 1
while i <= length(L)
      and x >= nth(L, i) do
    if x = nth(L, i) then
        return true
    end if
    i ← i + 1
end while
return false
/* Other version */
i ← 1
while i <= length(L)
      and x > nth(L, i) do
    i ← i + 1
end while
return (i <= length(L)
         and x = nth(L, i))
Example sorted list of 7 elements
−11−214156370

Search for 4: −11, −2, 1, then 4. Positive, 4 comparisons.

Search for 18: −11, −2, 1, 4, 15 are smaller; 63 goes past 18: we stop. Negative, 6 comparisons instead of 7.further on, everything is even bigger

Complexity

Positive or negative, it is the same: n in the worst case (x is the last one, or bigger than the last one), n / 2 on average. Can be implemented in a contiguous or linked list. No self-adjusting search on a sorted list.

Trap

The sheet’s note: the first version makes 2 comparisons per loop iteration (x ≥ … then x = …), the second only one, plus an equality test at the end. The second one is better.

List traversals in Python (Tutorial 1)

The homework also covers “Tutorial: list traversals in Python”. Two forms of traversal keep coming back: the full traversal (for, we look at everything) and the interrupted traversal (while with two conditions, we stop as soon as the answer is known).

Histogram Tutorial 1, ex. 2.2

A list of 256 counters, one per ASCII code: H[ord(c)] counts the c’s. We traverse the string only once.

def histogram(s):
    H = [0] * 256
    for c in s:
        H[ord(c)] += 1
    return H

def nb_different(s):
    cpt = 0
    for v in histogram(s):
        if v != 0:
            cpt += 1
    return cpt

def most_frequent(s):
    H = histogram(s)
    imax = 0
    for i in range(1, 256):
        if H[i] > H[imax]:
            imax = i
    return chr(imax), H[imax]

>>> nb_different("character")
6
>>> most_frequent("character")
('a', 2)
>>> most_frequent("abracadabra")
('a', 5)
Position in a sorted list Tutorial 1, ex. 3.1

Linear search on a sorted list (part 4), which returns the position of the first x, or −1.

def search_sorted(x, L):
    i = 0
    while i < len(L) and L[i] < x:
        i += 1
    if i < len(L) and L[i] == x:
        return i
    return -1

>>> search_sorted(5, [1, 3, 5, 5, 8]), search_sorted(4, [1, 3, 5, 8])
(2, -1)

def replace(L, k, new_v):
    i = 0
    while i < len(L) and L[i][0] < k:
        i += 1
    if i < len(L) and L[i][0] == k:
        L[i] = (k, new_v)   # tuple: we replace the pair

Tutorial 1, ex. 3.2: L[i][1] = new_v raises TypeError, a tuple is immutable.

def is_sorted(L):
    i = 1
    while i < len(L) and L[i - 1] <= L[i]:
        i += 1
    return i >= len(L)

Tutorial 1, ex. 3.3: we stop at the first pair of neighbours in the wrong order. is_sorted([]) and is_sorted([4]) are True.

Traps
  • In while i < len(L) and L[i] != x, the index test comes first: and stops at the first false, so L[i] is never read outside the list.
  • After the loop, we do not yet know why it stopped: we test i < len(L) again before reading L[i].
  • An interrupted traversal is done with while (or a return inside the for): a for that goes all the way to the end makes useless comparisons.
