Part 1

One phrase, one answer: expressions and types

You first use Caml in the interactive loop (the toplevel): you type a phrase, Caml evaluates it and answers. A phrase always ends with ;;. The # at the start of the line is Caml’s prompt: you do not type it.

An expression is a computation: a value (15, "Hello"), an operation (a + 15), a function application (float_of_int 15). Caml answers with its type and its value:

# (666 * 42 = 27972) && ("Hello" < "World") ;;
- : bool = true
Reading a Caml answer
Caml answerWhat it says
- : bool = trueAn expression: the dash says that nothing is named. Its type is bool, its value true.
val a : int = 3A definition (part 2): the name a is now bound to the value 3, of type int.
val succ : int -> int = <fun>A function (part 3): Caml gives its type but does not print its code, only <fun>.
Exception: Division_by_zero.The computation raised an exception (part 5): it has no value.
Error: Unbound value bThe phrase is rejected (syntax or type error): nothing is computed, nothing is defined.
Warning 8 [partial-match]: …A warning: the phrase is accepted, but Caml points out a probable oversight (part 6).

The five basic types of the memo, with their operators:

TypeValuesOperators
int1 45 -69 max_int+ - * / mod: / is the integer division, mod the remainder
float12.5 -0.5 3. 3e2+. -. *. /.: the same ones, followed by a dot
booltrue falsenot, && (and), || (or)
char'a' '9' '\n'a single character, between single quotes
string"a string" ""^ (concatenation), s.[i] (the character at rank i, starting from 0)

The comparisons = <> < > <= >= work for all these types, but always between two values of the same type. <> means “different”. Strings and characters compare in the order of their codes: uppercase letters before lowercase ones.

# 1. +. 2. ;;
- : float = 3.
# 1 / 2 ;;
- : int = 0
# 5 / 2 = 4 / 2 ;;
- : bool = true
# 10 - 2 * 2 ;;
- : int = 6
# 24 mod 10 * 10 ;;
- : int = 40
# (-7) mod 2 ;;
- : int = -1
# "Hello " ^ "world" ;;
- : string = "Hello world"
# "Caml".[1] ;;
- : char = 'a'
# 'Z' < 'a' ;;
- : bool = true
Remember
  • *, / and mod come before + and -. With equal priority, Caml computes from left to right: 24 mod 10 * 10 means (24 mod 10) * 10, that is 40.
  • The remainder of a negative number is negative: (-7) mod 2 is -1, not 1.
  • A float is printed with a dot and no useless zero: 3., and 4.0 is printed 4..

&& and || stop as soon as the result is known. false && … is false whatever comes next: Caml does not evaluate the rest. The same goes for true || ….

# false && (1 / 0 = 0) ;;
- : bool = false
# true && (1 / 0 = 0) ;;
Exception: Division_by_zero.
# true || (1 / 0 = 0) ;;
- : bool = true

The division by zero only happens in the second phrase. In chapter 2, this is what lets you write a function that stops as soon as the answer is known.

Trap: no automatic conversion

Caml never converts anything by itself: int and float do not mix, a character is not a string, and 1 < 2 < 3 reads (1 < 2) < 3, a boolean compared with an integer.

# 1 + 1.5 ;;
Error: This expression has type float but an expression was expected of type
         int
# 1 +. 1.5 ;;
Error: This expression has type int but an expression was expected of type
         float
  Hint: Did you mean `1.'?
# float_of_int 1 +. 1.5 ;;
- : float = 2.5
# "Hello Word" ^ '!' ;;
Error: This expression has type char but an expression was expected of type
         string
# 1 < 2 < 3 ;;
Error: This expression has type int but an expression was expected of type
         bool

Here and everywhere on the site, error messages are copied without the lines that locate the error (Line 1, characters 4-7: and the underlining), as in the memo.

Part 2

Naming a value: let and let … in

A definition binds a name to the value of an expression: let ident = expression. Caml answers with val, the name, the type and the value. The name can then be used in every following phrase.

# let a = 1 + 2 ;;
val a : int = 3
# a * 10 ;;
- : int = 30
# let one = 1 and two = 2. and three = '3' ;;
val one : int = 1
val two : float = 2.
val three : char = '3'

A name starts with a lowercase letter (or with _), followed by letters, digits and _. Caml is case-sensitive, and a name starting with an uppercase letter is kept for constructors: let Total = 3 gives Error: Unbound constructor Total. Choose explicit names.

You do not modify a name, you hide it. A name stays bound to the same value. A new definition with the same name creates a new name that hides the old one:

# let price = 3 ;;
val price : int = 3
# let price = price * 2 ;;
val price : int = 6

The second phrase computes price * 2 with the old price (3), then names the result price. Part 3 shows what a function defined before such a hiding sees.

A local definition: let x = e1 in e2. The name x only exists inside e2. The whole phrase is an expression: Caml answers with -, not with val, and x disappears afterwards.

# let total = 10 in total * total ;;
- : int = 100
# total ;;
Error: Unbound value total
# let a = 1 and b = 3 in
    let x = a + b and y = a - b in
      x * y ;;
- : int = -8

and or two let … in? The two phrases below only differ there. Guess the Caml answer before comparing.

# let x = 2 and y = 5 in
    let y = x and z = y in
      y + z ;;
- : int = 7
# let x = 2 and y = 5 in
    let y = x in
      let z = y in
        y + z ;;
Warning 26 [unused-var]: unused variable y.
- : int = 4
Remember

With and, the definitions are simultaneous: every expression is computed with the names from before. In let y = x and z = y, the y on the right is still 5: z is 5, y is 2, result 7. With two nested let … in, z is defined after the new y: z is 2, result 4. The warning says that the first y (5) is never used.

This is also why, in the header, let a = 5 and b = 2 * a in a * b is 120: the a in 2 * a is the old a, which is 12.

Trap: a let … in must be followed by an expression 
# let a = 3 in let c = 2 + a ;;
Error: Syntax error
# let a = 2 in b = 5 in a * b ;;
Error: Syntax error
# let a = 2 and b = 5 in a * b ;;
- : int = 10

let c = 2 + a alone is not an expression: its in … is missing. To define two local names, write let … and … in or two let … in one after the other.

Part 3

Functions: one parameter, several parameters

let f x = expression defines a function with parameter x. Its type is written type_of_x -> type_of_the_result, and its value is printed <fun>. To apply it, write its name then the argument, separated by a space: succ 3, with no parentheses and no comma.

# let succ x = x + 1 ;;
val succ : int -> int = <fun>
# succ 3 ;;
- : int = 4

Application comes before every operator: f x + y reads (f x) + y. Guess the answers:

# succ 3 * 2 ;;
- : int = 8
# succ (3 * 2) ;;
- : int = 7
# succ -1 ;;
Error: This expression has type int -> int
       but an expression was expected of type int
# succ (-1) ;;
- : int = 0

succ -1 reads succ - 1: a subtraction between a function and an integer. An argument that is not a simple value (an operation, a negative number) goes between parentheses.

Several parameters. let f x y = expression: the parameters follow each other, separated by spaces, and so do the arguments.

# let average a b = float_of_int (a + b) /. 2. ;;
val average : int -> int -> float = <fun>
# average 2 3 ;;
- : float = 2.5
# average 2 ;;
- : int -> float = <fun>

The type int -> int -> float reads from left to right: a first int, a second int, and the last type, float, is the type of the result. average 2 3 means (average 2) 3: average 2 is already a function, which waits for the second integer. Apply the arguments one at a time:

Trap: application reads from left to right 
# succ succ 2 ;;
Error: This function has type int -> int
       It is applied to too many arguments; maybe you forgot a `;'.
# succ (succ 2) ;;
- : int = 4
# let f2 x = int_of_float sqrt float_of_int x ;;
Error: This function has type float -> int
       It is applied to too many arguments; maybe you forgot a `;'.
# let f2 x = int_of_float (sqrt (float_of_int x)) ;;
val f2 : int -> int = <fun>

succ succ 2 reads (succ succ) 2: succ receives a function instead of an integer. To chain functions, put the inner call between parentheses (seminar, exercise 2.1).

Trap: a pair is not two parameters 
# let f x y = x mod y ;;
val f : int -> int -> int = <fun>
# f (2, 5) ;;
Error: This expression has type 'a * 'b
       but an expression was expected of type int
# let g (x, y) = x mod y ;;
val g : int * int -> int = <fun>
# g (2, 5) ;;
- : int = 2

let g (x, y) = … has only one parameter, a pair (part 7): its type is int * int -> int. Follow the shape of the examples of a subject: for check_list 2 lst, write let check_list k lst, not let check_list (k, lst).

Example seminar · ex. 2.2 mirror reverses a number with two non-zero digits; abba uses it. A function can call another one, provided that the other one is defined first.

# let mirror n = n mod 10 * 10 + n / 10 ;;
val mirror : int -> int = <fun>
# mirror 15 ;;
- : int = 51
# let abba n = n * 100 + mirror n ;;
val abba : int -> int = <fun>
# abba 42 ;;
- : int = 4224

Local definitions inside a function seminar · ex. 2.3 Compute x31 with as few multiplications as possible: each let … in names a result so that it is reused instead of computed again.

# let power31 x =
    let x2 = x * x in
    let x3 = x2 * x in
    let x5 = x3 * x2 in
    let x10 = x5 * x5 in
    let x20 = x10 * x10 in
      x20 * x10 * x ;;
val power31 : int -> int = <fun>
# power31 2 ;;
- : int = 2147483648

7 multiplications instead of 30. The version with successive squares (x2, x4, x8, x16, then x16 · x8 · x4 · x2 · x) uses 8.

Trap: a function keeps the values of its definition 
# let x = 1 ;;
val x : int = 1
# let add_x y = x + y ;;
val add_x : int -> int = <fun>
# let x = 100 ;;
val x : int = 100
# add_x 1 ;;
- : int = 2

add_x was defined when x was 1: it keeps that x. The new x only hides the old one for the following phrases.

Part 4

Conditionals: if … then … else

if condition then e1 else e2 is e1 if the condition is true, e2 otherwise. It is an expression: it has a value, and it can go wherever a value is expected.

# if 2 > 1 then "higher" else "lower" ;;
- : string = "higher"
# let absolute_value x =
    if x >= 0 then
      x
    else
      -x ;;
val absolute_value : int -> int = <fun>
# absolute_value (-7) ;;
- : int = 7
Remember
  • The condition is a bool.
  • Both branches have the same type: it is the type of the whole conditional.
  • The else is compulsory: without it, Caml wants a then branch of type unit (nothing), which only happens with printing.
  • Indentation of the memo: then and else under the if, each branch indented. A short conditional fits on one line.
# let test b = if b then true else 0 ;;
Error: This expression has type int but an expression was expected of type
         bool
# let pos x = if x > 0 then x ;;
Error: This expression has type int but an expression was expected of type
         unit
       because it is in the result of a conditional with no else branch

Example seminar · ex. 3.3 The maximum of two values. Look carefully at the type given by Caml:

# let max2 a b =
    if a > b then
      a
    else
      b ;;
val max2 : 'a -> 'a -> 'a = <fun>
# max2 3 8 ;;
- : int = 8
# max2 "caml" "algo" ;;
- : string = "caml"
Why 'a?

> compares two values of any type, as long as both have the same one. Nothing forces a and b to be integers: Caml gives the most general type, 'a -> 'a -> 'a (read “alpha”). 'a stands for any type, the same one everywhere it appears. Your Caml answer copies this 'a: writing int -> int -> int would be wrong.

Example seminar · ex. 3.3 and 3.4 min3 with no helper function, then the sum of the squares of the two largest of three integers: it is the sum of the three squares, minus the square of the smallest one.

# let min3 a b c =
    if a < b then
      if a < c then a else c
    else
      if b < c then b else c ;;
val min3 : 'a -> 'a -> 'a -> 'a = <fun>
# let highest_square_sum a b c =
    let m = min3 a b c in
      a * a + b * b + c * c - m * m ;;
val highest_square_sum : int -> int -> int -> int = <fun>
# highest_square_sum 3 2 1 ;;
- : int = 13
# highest_square_sum 1 (-5) 10 ;;
- : int = 101
# highest_square_sum (-1) (-2) (-3) ;;
- : int = 5

Here the type is int: * only exists on integers. A boolean conditional can be written without if (seminar, exercises 3.1 and 3.2):

With ifWithout if
if c then true else falsec
if c then false else truenot c
if a then b else falsea && b
if a then true else ba || b
if a then b else truenot a || b (implication)
if a then not b else ba <> b (exclusive or)
if a then b else not ba = b (equivalence)
 
# let all_even a b c d =
    a mod 2 = 0 && b mod 2 = 0 && c mod 2 = 0 && d mod 2 = 0 ;;
val all_even : int -> int -> int -> int -> bool = <fun>
# all_even 0 2 4 6 ;;
- : bool = true

In the seminar, all_even is written with four nested if and eight lines of true and false: one line is enough.

Trap: not is a function 
# not true = false ;;
- : bool = true

not a = b reads (not a) = b, like any application. Write not (a = b), or more simply a <> b.

Part 5

Reporting an error: failwith and invalid_arg

When a function cannot return a result, it raises an exception: the computation stops at once and Caml answers Exception: instead of a value. Two functions are enough in this course, and they are the only two predefined functions allowed at the exam (part 8).

# invalid_arg ;;
- : string -> 'a = <fun>
# failwith ;;
- : string -> 'a = <fun>
# invalid_arg "weight has to be positive" ;;
Exception: Invalid_argument "weight has to be positive".
# failwith "unknown code" ;;
Exception: Failure "unknown code".
invalid_arg "message"

Raises Exception: Invalid_argument "message".

A parameter is outside the domain: a negative number, a rank equal to zero, a number that does not have two digits…

failwith "message"

Raises Exception: Failure "message".

The parameters are valid, but the computation fails: parcel too heavy, unknown code, list too short…

Their type, string -> 'a, says that the “result” can be of any type, since it never comes. An exception can therefore go in any branch, next to an int, a float or a string.

Example seminar · ex. 3.7 The economy rate of a parcel, from its weight in grams: €3.4 up to 500 g, €4.6 up to 1,000 g, €5.1 up to 2,000 g, €6.9 up to 3,000 g.

# let rate_eco w =
    if w < 0 then
      invalid_arg "weight has to be positive"
    else if w <= 500 then 3.4
    else if w <= 1000 then 4.6
    else if w <= 2000 then 5.1
    else if w <= 3000 then 6.9
    else
      failwith "too heavy" ;;
val rate_eco : int -> float = <fun>
# rate_eco 750 ;;
- : float = 4.6
# rate_eco (-150) ;;
Exception: Invalid_argument "weight has to be positive".
# rate_eco 3500 ;;
Exception: Failure "too heavy".

The branches are float values; invalid_arg and failwith adapt to them, hence the type int -> float. The test on the parameter comes first, before any computation.

The seminar left aside invalid numbers for mirror (exercise 2.2). With invalid_arg, the function rejects them. The message starts with the name of the function, as in the subjects ("check_list: k < 0"):

# let mirror n =
    if n < 10 || n > 99 || n mod 10 = 0 then
      invalid_arg "mirror: not a two-digit number"
    else
      n mod 10 * 10 + n / 10 ;;
val mirror : int -> int = <fun>
# mirror 7 ;;
Exception: Invalid_argument "mirror: not a two-digit number".
# mirror 15 ;;
- : int = 51
Remember
  • An exception stops the whole current computation: 1 + failwith "stop" has no value, Caml answers Exception: Failure "stop".
  • Test the parameters first, then the failure cases, then the normal case. In chapter 2, a “wrapper” function will do this test only once, before the recursive calls.
  • Caml also raises its own exceptions: 1 / 0 gives Exception: Division_by_zero.
Trap: naming an exception does not raise it 
# let check x = if x < 0 then Invalid_argument "negative" else x ;;
Error: This expression has type int but an expression was expected of type
         exn
# let check x = if x < 0 then invalid_arg "negative" else x ;;
val check : int -> int = <fun>
# Invalid_arg "x" ;;
Error: Unbound constructor Invalid_arg

Invalid_argument "negative" (with an uppercase letter) builds an exception, a value of type exn, without raising it. Write invalid_arg "…" (with a lowercase letter). And Invalid_arg does not exist, even though the lists tutorial writes it in one example.

Part 6

Pattern matching: match … with

Pattern matching compares a value with a list of patterns and returns the expression of the first pattern that fits it (that “matches” it).

match expression with
    pattern1 -> expression1
  | pattern2 -> expression2
  | patternn -> expressionn
Remember
  • All the expressions on the right have the same type: the type of the match. The patterns have the type of the matched value.
  • The patterns are tried in order, from top to bottom. The first one that matches wins, the following ones are not looked at.
  • The matching must be exhaustive: cover every possible value.
PatternMatches
0 true 'c' "on"this exact value
x (a name)any value, and names it x on the right of the arrow
_any value, without naming it
0 | 2 | 4one of these values
x when x > 0a value that satisfies the guard (the condition after when)
(0, _)a pair whose first element is 0 (part 7)

function directly matches the single parameter, without naming it: let f = function … is the same as let f x = match x with ….

# let sign = function
      0 -> 0
    | y when y > 0 -> 1
    | _ -> -1 ;;
val sign : int -> int = <fun>
# sign (-12) ;;
- : int = -1

The order of the patterns seminar · ex. 3.5 The seminar’s grade function gives a letter from the average of two marks. Follow Caml pattern by pattern, then put the cases back in the right order.

# let grade a b =
    match (a + b) / 2 with
        x when x > 15 -> 'A'
      | x when x > 5 -> 'D'
      | 8 | 9 | 10 -> 'C'
      | x when x > 11 -> 'B'
      | _ -> 'E' ;;
val grade : int -> int -> char = <fun>
# grade 12 14 ;;
- : char = 'D'
# grade 9 9 ;;
- : char = 'D'

13 satisfies x > 5: the second pattern matches, and the case x when x > 11 is never reached. Caml says nothing, because it does not read guards. Put the most specific cases first.

Warnings. An incomplete matching or a useless case does not block the definition, but Caml reports them in its answer:

# let even x = match x with
      0 | 2 | 4 | 6 | 8 -> true
    | 1 | 3 | 5 | 7 | 9 -> false ;;
Warning 8 [partial-match]: this pattern-matching is not exhaustive.
Here is an example of a case that is not matched:
10
val even : int -> bool = <fun>
# even 10 ;;
Exception: Match_failure ("//toplevel//", 1, 13).
# let even x = match x mod 2 with
      0 -> true
    | _ -> false ;;
val even : int -> bool = <fun>
# let f x = match x with
      0 -> 18
    | y -> y * y
    | 1 -> 24 ;;
Warning 11 [redundant-case]: this match case is unused.
val f : int -> int = <fun>

The first even is defined despite the warning, and the error comes at run time: Match_failure. In the second one, _ also covers negative remainders ((-3) mod 2 is -1). In f, y matches everything that is left: the case 1 is never tried. In a Caml answer at the exam, a Warning gives away a forgotten case.

Trap: a name in a pattern matches everything 
# let h x y =
    match x with
        0 -> 0
      | y -> 1
      | _ -> -1 ;;
Warning 11 [redundant-case]: this match case is unused.
val h : int -> 'a -> int = <fun>
# h 5 3 ;;
- : int = 1
# let h x y =
    match x with
        0 -> 0
      | z when z = y -> 1
      | _ -> -1 ;;
val h : int -> int -> int = <fun>
# h 5 3 ;;
- : int = -1

A name in a pattern creates a new variable: | y -> does not compare x with the parameter y, it matches any value. To compare, use a guard: | z when z = y ->.

Trap: Caml does not read guards 
# let square x = match x with
      x when x > 0 -> x * x
    | x when x <= 0 -> invalid_arg "x has to be positive" ;;
Warning 8 [partial-match]: this pattern-matching is not exhaustive.
All clauses in this pattern-matching are guarded.
val square : int -> int = <fun>

x > 0 and x <= 0 cover everything, but Caml does not see it. End with a case without a guard: | _ -> or | x ->.

Part 7

Tuples and anonymous functions

A tuple (pair, triple…) groups several values, possibly of different types, between parentheses and separated by commas. Its type is the product of the types, written with *.

# let one = (1, "one") and two = (2., "two") ;;
val one : int * string = (1, "one")
val two : float * string = (2., "two")
# let pair = (one, two) ;;
val pair : (int * string) * (float * string) = ((1, "one"), (2., "two"))

To get the elements back, use a tuple pattern in a let or a match. A function that must return several results returns a tuple:

# let (x, y) = one ;;
val x : int = 1
val y : string = "one"
# let divmod x y = (x / y, x mod y) ;;
val divmod : int -> int -> int * int = <fun>
# let (q, r) = divmod 17 5 ;;
val q : int = 3
val r : int = 2

Example seminar · ex. 2.6 Convert a duration into seconds, and back. Guess each answer before comparing.

# let sec_of_time h m s = h * 3600 + m * 60 + s ;;
val sec_of_time : int -> int -> int -> int = <fun>
# let time_of_sec s = (s / 3600, s mod 3600 / 60, s mod 60) ;;
val time_of_sec : int -> int * int * int = <fun>
# time_of_sec 83639 ;;
- : int * int * int = (23, 13, 59)
# let add_times h1 m1 s1 h2 m2 s2 =
    time_of_sec (sec_of_time h1 m1 s1 + sec_of_time h2 m2 s2) ;;
val add_times : int -> int -> int -> int -> int -> int -> int * int * int =
  <fun>
# add_times 12 22 15 15 13 10 ;;
- : int * int * int = (27, 35, 25)
Remember
  • int -> int * int * int is a function of one integer that returns a triple: the arrow separates the parameters, the star separates the elements of the tuple.
  • Caml cuts answers that are too long: the <fun> of add_times goes to the next line. Copy the whole type, on one or two lines.

Matching several values at once: group them in a tuple. The memo writes the implication in two ways, with two different types:

# let implication = function
      (true, x) -> x
    | _ -> true ;;
val implication : bool * bool -> bool = <fun>
# let implication a b = match (a, b) with
      (true, x) -> x
    | _ -> true ;;
val implication : bool -> bool -> bool = <fun>
# let count = function
      (0, 0) -> 2
    | (0, _) | (_, 0) -> 1
    | _ -> 0 ;;
val count : int * int -> int = <fun>
# count (0, 1) ;;
- : int = 1

The first implication takes a pair (a single parameter); the second one takes two parameters and groups them to match them together. count (seminar, exercise 3.9) counts the zeros of a pair, with pattern matching but without match.

Anonymous functions. A function is a value like any other: you can write it without giving it a name, with function.

# function x -> x + 1 ;;
- : int -> int = <fun>
# (function x -> x * x) 4 ;;
- : int = 16
# let average = function a -> function b -> (a + b) / 2 ;;
val average : int -> int -> int = <fun>
# (function x -> function y -> x < y) 3 5 ;;
- : bool = true
Remember
  • let f x = e and let f = function x -> e define the same function.
  • function has only one parameter: for two, nest them, function a -> function b -> …. OCaml also accepts the shortcut fun a b -> …, but the memo and the subjects write function.
  • In chapter 4, these functions are passed as parameters. The October 2024 subject gives for instance insert_x 7 (function x -> function y -> x < y) [1; 3; 5; 9].
Traps 
# let f = function x y -> x + y ;;
Error: Syntax error
# let h x y = match (x, y) with
      (x, x) -> true
    | _ -> false ;;
Error: Variable x is bound several times in this matching
# let h x y = match (x, y) with
      (a, b) when a = b -> true
    | _ -> false ;;
val h : 'a -> 'a -> bool = <fun>

function takes only one parameter. The same name cannot appear twice in a pattern: to test equality, use a guard (seminar, exercise 3.8). Here, let h x y = x = y was enough.

Writing a function at the exam

The exam is on paper, directly on the subject. Its rules are written at the top of every subject, and they count in the mark.

The rules of the subjects (November 2020, October 2022, October 2024)
  • Answer within the provided space, in pen: penciled answers and red-pen answers (since 2021) are not marked.
  • “All Caml code not indented will not be marked.”
  • “In the absence of any indication in the document, the only functions that you can use are failwith and invalid_arg”: no other predefined function, neither abs, nor max, nor float_of_int, nor String.length. Operators (+ mod = && not…) are still allowed.
  • “Any Caml code must be followed by the result of its evaluation: the Caml answer.” Since 2023, the subject adds that it “is part of the mark”.
  • Your functions must follow the given application examples. Only one version per function. You may write your own helper functions, if you say what they do; the last function written is the one that answers (October 2024).
  • The presentation is marked.

  1. Read the examples before the statement. They give the name, the order and the type of the parameters, the type of the result, and the expected exception with its message.

  2. Write down the expected type. It will be your Caml answer: for instance val rate : int -> string -> float = <fun>.

  3. List the cases: invalid parameters first (invalid_arg), then the failures (failwith), then the normal case.

  4. Write the code, indented: then and else under the if, one match case per line with the | aligned, ;; at the end of the phrase.

  5. Under every definition, the Caml answer: val name : type = … for a definition (<fun> for a function), - : type = value for an expression.

Caml function: 
# let rate w code =
    if w < 0 then
      invalid_arg "weight has to be positive"
    else
      let (eco, standard, express) =
        if w <= 500 then (3.4, 4.6, 9.1)
        else if w <= 1000 then (4.6, 5.9, 11.)
        else if w <= 2000 then (5.1, 6.5, 13.5)
        else if w <= 3000 then (6.9, 7.2, 14.2)
        else failwith "too heavy"
      in
        match code with
            "eco" -> eco
          | "standard" -> standard
          | "express" -> express
          | _ -> failwith "unknown code" ;;
val rate : int -> string -> float = <fun>
# rate 750 "eco" ;;
- : float = 4.6
# rate (-150) "standard" ;;
Exception: Invalid_argument "weight has to be positive".
# rate 150 "drone" ;;
Exception: Failure "unknown code".
# rate 3500 "express" ;;
Exception: Failure "too heavy".

The triple picks the row of the table only once, then the match picks the column. A single function, no predefined function apart from failwith and invalid_arg. On the paper, the Caml answer to write is the one of your definition (val rate : …); the examples of the statement let you check your function.

At the exam
  • The nine subjects found (2017 to 2024) never test this chapter on its own: their exercises to write are about lists (chapter 3), with an exception required by the statement in all nine subjects. Yet everything they ask is written with the tools of this chapter.
  • Seven subjects out of nine have a “Mystery” exercise: give the Caml answers to a few phrases, type included (2 to 4 points). This is what you do in the blocks where you type your answer.
  • First follow the exception of the examples: Invalid_argument or Failure. Copy their message too; the official corrections do not always reproduce it word for word, but the constructor counts.
  • The examples of the subjects write negative numbers between parentheses: check_list (-1) [[1]; [2]; []] (October 2024).
Frequent mistakes on the paper 
# let f x = x + 1
  f 2 ;;
Error: This expression has type int
       This is not a function; it cannot be applied.
  • The forgotten ;;: the next phrase sticks to the previous one, and Caml reads x + 1 f 2.
  • val versus -: a definition answers val name : …, an expression - : …. For a function, the value is <fun>, never a result.
  • The exact type: 'a when the function only compares (max2), int * int -> int for a pair, int -> int -> int for two parameters.
  • A predefined function such as abs or max: write it again yourself, like absolute_value and max2 above.
