Partie 1

Une phrase, une réponse : expressions et types

Caml se pratique d’abord dans la boucle d’interaction (le toplevel) : tu tapes une phrase, Caml l’évalue et répond. Une phrase se termine toujours par ;;. Le # en début de ligne est l’invite de Caml : tu ne le tapes pas.

Une expression est un calcul : une valeur (15, "Hello"), une opération (a + 15), une application de fonction (float_of_int 15). Caml répond par son type et sa valeur :

# (666 * 42 = 27972) && ("Hello" < "World") ;;
- : bool = true
Lire une réponse de Caml
Réponse de CamlCe qu’elle dit
- : bool = trueUne expression : le tiret dit que rien n’est nommé. Son type est bool, sa valeur true.
val a : int = 3Une définition (partie 2) : le nom a est désormais lié à la valeur 3, de type int.
val succ : int -> int = <fun>Une fonction (partie 3) : Caml donne son type mais n’affiche pas son code, seulement <fun>.

Les cinq types de base du mémo, avec leurs opérateurs :

TypeValeursOpérateurs

Les comparaisons = <> < > <= >= marchent pour tous ces types, mais toujours entre deux valeurs du même type. <> veut dire « différent ». Les chaînes et les caractères se comparent dans l’ordre des codes : les majuscules avant les minuscules.

# 1. +. 2. ;;
- : float = 3.
# 1 / 2 ;;
- : int = 0
# 5 / 2 = 4 / 2 ;;
- : bool = true
# 10 - 2 * 2 ;;
- : int = 6
# 24 mod 10 * 10 ;;
- : int = 40
# (-7) mod 2 ;;
- : int = -1
# "Hello " ^ "world" ;;
- : string = "Hello world"
# "Caml".[1] ;;
- : char = 'a'
# 'Z' < 'a' ;;
- : bool = true
À retenir
  • *, / et mod passent avant + et -. À priorité égale, Caml calcule de gauche à droite : 24 mod 10 * 10 vaut (24 mod 10) * 10, soit 40.
  • Le reste d’un nombre négatif est négatif : (-7) mod 2 vaut -1, pas 1.
  • Un flottant s’affiche avec un point et sans zéro inutile : 3., et 4.0 s’affiche 4..

&& et || s’arrêtent dès que le résultat est connu. false && … vaut false quoi qu’il y ait après : Caml n’évalue pas la suite. De même pour true || ….

# false && (1 / 0 = 0) ;;
- : bool = false
# true && (1 / 0 = 0) ;;
Exception: Division_by_zero.
# true || (1 / 0 = 0) ;;
- : bool = true

La division par zéro n’a lieu que dans la deuxième phrase. Au chapitre 2, c’est ce qui permet d’écrire une fonction qui s’arrête dès que la réponse est connue.

Piège : aucune conversion automatique

Caml ne convertit jamais tout seul : int et float ne se mélangent pas, un caractère n’est pas une chaîne, et 1 < 2 < 3 se lit (1 < 2) < 3, un booléen comparé à un entier.

# 1 + 1.5 ;;
Error: This expression has type float but an expression was expected of type
         int
# 1 +. 1.5 ;;
Error: This expression has type int but an expression was expected of type
         float
  Hint: Did you mean `1.'?
# float_of_int 1 +. 1.5 ;;
- : float = 2.5
# "Hello Word" ^ '!' ;;
Error: This expression has type char but an expression was expected of type
         string
# 1 < 2 < 3 ;;
Error: This expression has type int but an expression was expected of type
         bool

Ici et dans tout le site, les messages d’erreur sont recopiés sans les lignes qui situent l’erreur (Line 1, characters 4-7: et le soulignement), comme dans le mémo.

Partie 1 sur 8
Partie 2

Nommer une valeur : let et let … in

Une définition lie un nom à la valeur d’une expression : let ident = expression. Caml répond par val, le nom, le type et la valeur. Le nom s’utilise ensuite dans toutes les phrases suivantes.

# let a = 1 + 2 ;;
val a : int = 3
# a * 10 ;;
- : int = 30
# let one = 1 and two = 2. and three = '3' ;;
val one : int = 1
val two : float = 2.
val three : char = '3'

Un nom commence par une minuscule (ou par _), puis des lettres, des chiffres et des _. Caml distingue majuscules et minuscules, et un nom qui commence par une majuscule est réservé aux constructeurs : let Total = 3 donne Error: Unbound constructor Total. Choisis des noms explicites.

On ne modifie pas un nom, on le masque. Un nom reste lié à la même valeur. Une nouvelle définition avec le même nom crée un nouveau nom qui cache l’ancien :

# let price = 3 ;;
val price : int = 3
# let price = price * 2 ;;
val price : int = 6

La seconde phrase calcule price * 2 avec l’ancien price (3), puis nomme le résultat price. La partie 3 montre ce que voit une fonction définie avant un masquage.

Une définition locale : let x = e1 in e2. Le nom x n’existe que dans e2. Toute la phrase est une expression : Caml répond par -, pas par val, et x disparaît ensuite.

# let total = 10 in total * total ;;
- : int = 100
# total ;;
Error: Unbound value total
# let a = 1 and b = 3 in
    let x = a + b and y = a - b in
      x * y ;;
- : int = -8

and ou deux let … in ? Les deux phrases ci-dessous ne diffèrent que par là. Devine la réponse de Caml avant de comparer.

# let x = 2 and y = 5 in
    let y = x and z = y in
      y + z ;;
- : int = 7
# let x = 2 and y = 5 in
    let y = x in
      let z = y in
        y + z ;;
Warning 26 [unused-var]: unused variable y.
- : int = 4
À retenir

Avec and, les définitions sont simultanées : toutes les expressions sont calculées avec les noms d’avant. Dans let y = x and z = y, le y de droite vaut encore 5 : z vaut 5, y vaut 2, résultat 7. Avec deux let … in imbriqués, z est défini après le nouveau y : z vaut 2, résultat 4. L’avertissement signale que le premier y (5) ne sert jamais.

C’est aussi pourquoi, dans l’en-tête, let a = 5 and b = 2 * a in a * b vaut 120 : le a de 2 * a est l’ancien a, qui vaut 12.

Piège : un let … in doit être suivi d’une expression 
# let a = 3 in let c = 2 + a ;;
Error: Syntax error
# let a = 2 in b = 5 in a * b ;;
Error: Syntax error
# let a = 2 and b = 5 in a * b ;;
- : int = 10

let c = 2 + a seul n’est pas une expression : il lui manque son in …. Pour définir deux noms locaux, écris let … and … in ou deux let … in à la suite.

Partie 3

Les fonctions : un paramètre, plusieurs paramètres

let f x = expression définit une fonction de paramètre x. Son type s’écrit type_de_x -> type_du_résultat, et sa valeur s’affiche <fun>. Pour l’appliquer, écris son nom puis l’argument, séparés par une espace : succ 3, sans parenthèses ni virgule.

# let succ x = x + 1 ;;
val succ : int -> int = <fun>
# succ 3 ;;
- : int = 4

L’application passe avant tous les opérateurs : f x + y se lit (f x) + y. Devine les réponses :

# succ 3 * 2 ;;
- : int = 8
# succ (3 * 2) ;;
- : int = 7
# succ -1 ;;
Error: This expression has type int -> int
       but an expression was expected of type int
# succ (-1) ;;
- : int = 0

succ -1 se lit succ - 1 : une soustraction entre une fonction et un entier. Un argument qui n’est pas une valeur simple (une opération, un nombre négatif) se met entre parenthèses.

Plusieurs paramètres. let f x y = expression : les paramètres se suivent, séparés par des espaces, et l’application aussi.

# let average a b = float_of_int (a + b) /. 2. ;;
val average : int -> int -> float = <fun>
# average 2 3 ;;
- : float = 2.5
# average 2 ;;
- : int -> float = <fun>

Le type int -> int -> float se lit de gauche à droite : un premier int, un second int, et le dernier type, float, est celui du résultat. average 2 3 veut dire (average 2) 3 : average 2 est déjà une fonction, qui attend le second entier. Applique les arguments un par un :

Piège : l’application se lit de gauche à droite 
# succ succ 2 ;;
Error: This function has type int -> int
       It is applied to too many arguments; maybe you forgot a `;'.
# succ (succ 2) ;;
- : int = 4
# let f2 x = int_of_float sqrt float_of_int x ;;
Error: This function has type float -> int
       It is applied to too many arguments; maybe you forgot a `;'.
# let f2 x = int_of_float (sqrt (float_of_int x)) ;;
val f2 : int -> int = <fun>

succ succ 2 se lit (succ succ) 2 : succ reçoit une fonction au lieu d’un entier. Pour enchaîner des fonctions, parenthèse l’appel intérieur (séminaire, exercice 2.1).

Piège : un couple n’est pas deux paramètres 
# let f x y = x mod y ;;
val f : int -> int -> int = <fun>
# f (2, 5) ;;
Error: This expression has type 'a * 'b
       but an expression was expected of type int
# let g (x, y) = x mod y ;;
val g : int * int -> int = <fun>
# g (2, 5) ;;
- : int = 2

let g (x, y) = … n’a qu’un paramètre, un couple (partie 7) : son type est int * int -> int. Respecte la forme des exemples d’un sujet : pour check_list 2 lst, écris let check_list k lst, pas let check_list (k, lst).

Exemple séminaire · ex. 2.2 mirror retourne un nombre à deux chiffres non nuls ; abba l’utilise. Une fonction peut en appeler une autre, à condition que celle-ci soit définie avant.

# let mirror n = n mod 10 * 10 + n / 10 ;;
val mirror : int -> int = <fun>
# mirror 15 ;;
- : int = 51
# let abba n = n * 100 + mirror n ;;
val abba : int -> int = <fun>
# abba 42 ;;
- : int = 4224

Des définitions locales dans une fonction séminaire · ex. 2.3 Calculer x31 avec le moins de multiplications possible : chaque let … in nomme un résultat pour le réutiliser au lieu de le recalculer.

# let power31 x =
    let x2 = x * x in
    let x3 = x2 * x in
    let x5 = x3 * x2 in
    let x10 = x5 * x5 in
    let x20 = x10 * x10 in
      x20 * x10 * x ;;
val power31 : int -> int = <fun>
# power31 2 ;;
- : int = 2147483648

7 multiplications au lieu de 30. La version par carrés successifs (x2, x4, x8, x16, puis x16 · x8 · x4 · x2 · x) en fait 8.

Piège : une fonction garde les valeurs de sa définition 
# let x = 1 ;;
val x : int = 1
# let add_x y = x + y ;;
val add_x : int -> int = <fun>
# let x = 100 ;;
val x : int = 100
# add_x 1 ;;
- : int = 2

add_x a été définie quand x valait 1 : elle garde ce x-là. Le nouveau x ne fait que masquer l’ancien pour les phrases suivantes.

Partie 4

L’alternative : if … then … else

if condition then e1 else e2 vaut e1 si la condition vaut true, e2 sinon. C’est une expression : elle a une valeur, et elle se place partout où une valeur est attendue.

# if 2 > 1 then "higher" else "lower" ;;
- : string = "higher"
# let absolute_value x =
    if x >= 0 then
      x
    else
      -x ;;
val absolute_value : int -> int = <fun>
# absolute_value (-7) ;;
- : int = 7
À retenir
  • La condition est un bool.
  • Les deux branches ont le même type : c’est le type de toute l’alternative.
  • Le else est obligatoire : sans lui, Caml veut une branche then de type unit (rien), ce qui n’arrive qu’avec des affichages.
  • Indentation du mémo : then et else sous le if, chaque branche en retrait. Une alternative courte tient sur une ligne.
# let test b = if b then true else 0 ;;
Error: This expression has type int but an expression was expected of type
         bool
# let pos x = if x > 0 then x ;;
Error: This expression has type int but an expression was expected of type
         unit
       because it is in the result of a conditional with no else branch

Exemple séminaire · ex. 3.3 Le maximum de deux valeurs. Regarde bien le type que donne Caml :

# let max2 a b =
    if a > b then
      a
    else
      b ;;
val max2 : 'a -> 'a -> 'a = <fun>
# max2 3 8 ;;
- : int = 8
# max2 "caml" "algo" ;;
- : string = "caml"
Pourquoi 'a ?

> compare deux valeurs de n’importe quel type, pourvu qu’elles aient le même. Rien n’oblige a et b à être des entiers : Caml donne le type le plus général, 'a -> 'a -> 'a (lis « alpha »). 'a désigne un type quelconque, le même partout où il apparaît. Ta réponse Caml recopie ce 'a : écrire int -> int -> int serait faux.

Exemple séminaire · ex. 3.3 et 3.4 min3 sans fonction intermédiaire, puis la somme des carrés des deux plus grands de trois entiers : c’est la somme des trois carrés, moins le carré du plus petit.

# let min3 a b c =
    if a < b then
      if a < c then a else c
    else
      if b < c then b else c ;;
val min3 : 'a -> 'a -> 'a -> 'a = <fun>
# let highest_square_sum a b c =
    let m = min3 a b c in
      a * a + b * b + c * c - m * m ;;
val highest_square_sum : int -> int -> int -> int = <fun>
# highest_square_sum 3 2 1 ;;
- : int = 13
# highest_square_sum 1 (-5) 10 ;;
- : int = 101
# highest_square_sum (-1) (-2) (-3) ;;
- : int = 5

Ici le type est int : * n’existe que sur les entiers. Une alternative booléenne se réécrit sans if (séminaire, exercices 3.1 et 3.2) :

Avec ifSans if
if c then true else falsec
if c then false else truenot c
if a then b else falsea && b
if a then true else ba || b
if a then b else truenot a || b (implication)
if a then not b else ba <> b (ou exclusif)
if a then b else not ba = b (équivalence)
 
# let all_even a b c d =
    a mod 2 = 0 && b mod 2 = 0 && c mod 2 = 0 && d mod 2 = 0 ;;
val all_even : int -> int -> int -> int -> bool = <fun>
# all_even 0 2 4 6 ;;
- : bool = true

Dans le séminaire, all_even s’écrit avec quatre if imbriqués et huit lignes de true et false : une seule ligne suffit.

Piège : not est une fonction 
# not true = false ;;
- : bool = true

not a = b se lit (not a) = b, comme toute application. Écris not (a = b), ou plus simplement a <> b.

Partie 5

Signaler une erreur : failwith et invalid_arg

Quand une fonction ne peut pas rendre de résultat, elle déclenche une exception : le calcul s’arrête net et Caml répond Exception: au lieu d’une valeur. Deux fonctions suffisent dans ce cours, et ce sont les deux seules fonctions prédéfinies permises à l’examen (partie 8).

# invalid_arg ;;
- : string -> 'a = <fun>
# failwith ;;
- : string -> 'a = <fun>
# invalid_arg "weight has to be positive" ;;
Exception: Invalid_argument "weight has to be positive".
# failwith "unknown code" ;;
Exception: Failure "unknown code".
invalid_arg "message"

Déclenche Exception: Invalid_argument "message".

Un paramètre est en dehors du domaine : un nombre négatif, un rang nul, un nombre qui n’a pas deux chiffres…

failwith "message"

Déclenche Exception: Failure "message".

Les paramètres sont valides, mais le calcul échoue : colis trop lourd, code inconnu, liste trop courte…

Leur type, string -> 'a, dit que le « résultat » peut être de n’importe quel type, puisqu’il n’arrive jamais. Une exception se place donc dans n’importe quelle branche, à côté d’un int, d’un float ou d’une chaîne.

Exemple séminaire · ex. 3.7 Le tarif économique d’un colis, d’après son poids en grammes : 3,4 € jusqu’à 500 g, 4,6 € jusqu’à 1 000 g, 5,1 € jusqu’à 2 000 g, 6,9 € jusqu’à 3 000 g.

# let rate_eco w =
    if w < 0 then
      invalid_arg "weight has to be positive"
    else if w <= 500 then 3.4
    else if w <= 1000 then 4.6
    else if w <= 2000 then 5.1
    else if w <= 3000 then 6.9
    else
      failwith "too heavy" ;;
val rate_eco : int -> float = <fun>
# rate_eco 750 ;;
- : float = 4.6
# rate_eco (-150) ;;
Exception: Invalid_argument "weight has to be positive".
# rate_eco 3500 ;;
Exception: Failure "too heavy".

Les branches sont des float ; invalid_arg et failwith s’y adaptent, d’où le type int -> float. Le test du paramètre vient en premier, avant tout calcul.

Le séminaire laissait de côté les nombres invalides pour mirror (exercice 2.2). Avec invalid_arg, la fonction les refuse. Le message commence par le nom de la fonction, comme dans les sujets ("check_list: k < 0") :

# let mirror n =
    if n < 10 || n > 99 || n mod 10 = 0 then
      invalid_arg "mirror: not a two-digit number"
    else
      n mod 10 * 10 + n / 10 ;;
val mirror : int -> int = <fun>
# mirror 7 ;;
Exception: Invalid_argument "mirror: not a two-digit number".
# mirror 15 ;;
- : int = 51
À retenir
  • Une exception arrête tout le calcul en cours : 1 + failwith "stop" n’a pas de valeur, Caml répond Exception: Failure "stop".
  • Teste les paramètres d’abord, puis les cas d’échec, puis le cas normal. Au chapitre 2, une fonction « chapeau » fera ce test une seule fois, avant les appels récursifs.
  • Caml déclenche aussi ses propres exceptions : 1 / 0 donne Exception: Division_by_zero.
Piège : nommer une exception ne la déclenche pas 
# let check x = if x < 0 then Invalid_argument "negative" else x ;;
Error: This expression has type int but an expression was expected of type
         exn
# let check x = if x < 0 then invalid_arg "negative" else x ;;
val check : int -> int = <fun>
# Invalid_arg "x" ;;
Error: Unbound constructor Invalid_arg

Invalid_argument "negative" (avec une majuscule) construit une exception, une valeur de type exn, sans la déclencher. Écris invalid_arg "…" (avec une minuscule). Et Invalid_arg n’existe pas, même si le TD listes l’écrit dans un exemple.

Partie 6

Le filtrage : match … with

Le filtrage compare une valeur à une suite de motifs et rend l’expression du premier motif qui lui correspond (qui la « filtre »).

match expression with
    motif1 -> expression1
  | motif2 -> expression2
  | motifn -> expressionn
À retenir
  • Toutes les expressions de droite ont le même type : c’est celui du match. Les motifs ont le type de la valeur filtrée.
  • Les motifs sont essayés dans l’ordre, de haut en bas. Le premier qui filtre gagne, les suivants ne sont pas regardés.
  • Le filtrage doit être exhaustif : couvrir toutes les valeurs possibles.
MotifFiltre
0 true 'c' "on"cette valeur, exactement
x (un nom)n’importe quelle valeur, et la nomme x à droite de la flèche
_n’importe quelle valeur, sans la nommer
0 | 2 | 4l’une de ces valeurs
x when x > 0une valeur qui vérifie la garde (la condition après when)
(0, _)un couple dont le premier élément vaut 0 (partie 7)

function filtre directement l’unique paramètre, sans le nommer : let f = function … revient à let f x = match x with ….

# let sign = function
      0 -> 0
    | y when y > 0 -> 1
    | _ -> -1 ;;
val sign : int -> int = <fun>
# sign (-12) ;;
- : int = -1

L’ordre des motifs séminaire · ex. 3.5 La fonction grade du séminaire donne une lettre d’après la moyenne de deux notes. Suis Caml motif par motif, puis remets les cas dans le bon ordre.

# let grade a b =
    match (a + b) / 2 with
        x when x > 15 -> 'A'
      | x when x > 5 -> 'D'
      | 8 | 9 | 10 -> 'C'
      | x when x > 11 -> 'B'
      | _ -> 'E' ;;
val grade : int -> int -> char = <fun>
# grade 12 14 ;;
- : char = 'D'
# grade 9 9 ;;
- : char = 'D'

13 vérifie x > 5 : le deuxième motif filtre, et le cas x when x > 11 n’est jamais atteint. Caml ne signale rien, car il ne lit pas les gardes. Place les cas les plus particuliers d’abord.

Les avertissements. Un filtrage incomplet ou un cas inutile ne bloque pas la définition, mais Caml les signale dans sa réponse :

# let even x = match x with
      0 | 2 | 4 | 6 | 8 -> true
    | 1 | 3 | 5 | 7 | 9 -> false ;;
Warning 8 [partial-match]: this pattern-matching is not exhaustive.
Here is an example of a case that is not matched:
10
val even : int -> bool = <fun>
# even 10 ;;
Exception: Match_failure ("//toplevel//", 1, 13).
# let even x = match x mod 2 with
      0 -> true
    | _ -> false ;;
val even : int -> bool = <fun>
# let f x = match x with
      0 -> 18
    | y -> y * y
    | 1 -> 24 ;;
Warning 11 [redundant-case]: this match case is unused.
val f : int -> int = <fun>

La première even est définie malgré l’avertissement, et l’erreur arrive à l’exécution : Match_failure. Dans la seconde, _ couvre aussi les restes négatifs ((-3) mod 2 vaut -1). Dans f, y filtre tout ce qui reste : le cas 1 n’est jamais essayé. Dans une réponse Caml d’examen, un Warning trahit un cas oublié.

Piège : un nom dans un motif filtre tout 
# let h x y =
    match x with
        0 -> 0
      | y -> 1
      | _ -> -1 ;;
Warning 11 [redundant-case]: this match case is unused.
val h : int -> 'a -> int = <fun>
# h 5 3 ;;
- : int = 1
# let h x y =
    match x with
        0 -> 0
      | z when z = y -> 1
      | _ -> -1 ;;
val h : int -> int -> int = <fun>
# h 5 3 ;;
- : int = -1

Un nom dans un motif crée une nouvelle variable : | y -> ne compare pas x au paramètre y, il filtre n’importe quelle valeur. Pour comparer, une garde : | z when z = y ->.

Piège : Caml ne lit pas les gardes 
# let square x = match x with
      x when x > 0 -> x * x
    | x when x <= 0 -> invalid_arg "x has to be positive" ;;
Warning 8 [partial-match]: this pattern-matching is not exhaustive.
All clauses in this pattern-matching are guarded.
val square : int -> int = <fun>

x > 0 et x <= 0 couvrent tout, mais Caml ne le voit pas. Termine par un cas sans garde : | _ -> ou | x ->.

Partie 7

N-uplets et fonctions anonymes

Un n-uplet (couple, triplet…) regroupe plusieurs valeurs, de types éventuellement différents, entre parenthèses et séparées par des virgules. Son type est le produit des types, écrit avec *.

# let one = (1, "one") and two = (2., "two") ;;
val one : int * string = (1, "one")
val two : float * string = (2., "two")
# let pair = (one, two) ;;
val pair : (int * string) * (float * string) = ((1, "one"), (2., "two"))

Pour récupérer les éléments, un motif n-uplet dans un let ou un match. Une fonction qui doit rendre plusieurs résultats rend un n-uplet :

# let (x, y) = one ;;
val x : int = 1
val y : string = "one"
# let divmod x y = (x / y, x mod y) ;;
val divmod : int -> int -> int * int = <fun>
# let (q, r) = divmod 17 5 ;;
val q : int = 3
val r : int = 2

Exemple séminaire · ex. 2.6 Convertir une durée en secondes, et l’inverse. Devine chaque réponse avant de comparer.

# let sec_of_time h m s = h * 3600 + m * 60 + s ;;
val sec_of_time : int -> int -> int -> int = <fun>
# let time_of_sec s = (s / 3600, s mod 3600 / 60, s mod 60) ;;
val time_of_sec : int -> int * int * int = <fun>
# time_of_sec 83639 ;;
- : int * int * int = (23, 13, 59)
# let add_times h1 m1 s1 h2 m2 s2 =
    time_of_sec (sec_of_time h1 m1 s1 + sec_of_time h2 m2 s2) ;;
val add_times : int -> int -> int -> int -> int -> int -> int * int * int =
  <fun>
# add_times 12 22 15 15 13 10 ;;
- : int * int * int = (27, 35, 25)
À retenir
  • int -> int * int * int est une fonction d’un entier qui rend un triplet : la flèche sépare les paramètres, l’étoile sépare les éléments du n-uplet.
  • Caml coupe les réponses trop longues : le <fun> de add_times passe à la ligne. Recopie le type en entier, sur une ou deux lignes.

Filtrer plusieurs valeurs à la fois : on les regroupe en n-uplet. Le mémo écrit l’implication de deux façons, avec deux types différents :

# let implication = function
      (true, x) -> x
    | _ -> true ;;
val implication : bool * bool -> bool = <fun>
# let implication a b = match (a, b) with
      (true, x) -> x
    | _ -> true ;;
val implication : bool -> bool -> bool = <fun>
# let count = function
      (0, 0) -> 2
    | (0, _) | (_, 0) -> 1
    | _ -> 0 ;;
val count : int * int -> int = <fun>
# count (0, 1) ;;
- : int = 1

La première implication prend un couple (un seul paramètre) ; la seconde prend deux paramètres et les regroupe pour les filtrer ensemble. count (séminaire, exercice 3.9) compte les zéros d’un couple, avec du filtrage mais sans match.

Les fonctions anonymes. Une fonction est une valeur comme une autre : on peut l’écrire sans lui donner de nom, avec function.

# function x -> x + 1 ;;
- : int -> int = <fun>
# (function x -> x * x) 4 ;;
- : int = 16
# let average = function a -> function b -> (a + b) / 2 ;;
val average : int -> int -> int = <fun>
# (function x -> function y -> x < y) 3 5 ;;
- : bool = true
À retenir
  • let f x = e et let f = function x -> e définissent la même fonction.
  • function n’a qu’un paramètre : pour deux, on imbrique function a -> function b -> …. OCaml accepte aussi le raccourci fun a b -> …, mais le mémo et les sujets écrivent function.
  • Au chapitre 4, ces fonctions passent en paramètre. Le sujet d’octobre 2024 donne par exemple insert_x 7 (function x -> function y -> x < y) [1; 3; 5; 9].
Pièges 
# let f = function x y -> x + y ;;
Error: Syntax error
# let h x y = match (x, y) with
      (x, x) -> true
    | _ -> false ;;
Error: Variable x is bound several times in this matching
# let h x y = match (x, y) with
      (a, b) when a = b -> true
    | _ -> false ;;
val h : 'a -> 'a -> bool = <fun>

function ne prend qu’un paramètre. Un même nom ne peut pas apparaître deux fois dans un motif : pour tester l’égalité, une garde (séminaire, exercice 3.8). Ici, let h x y = x = y suffisait.

Écrire une fonction à l’examen

L’examen se fait sur papier, directement sur le sujet. Ses règles sont écrites en tête de chaque sujet, et elles comptent dans la note.

Les règles des sujets (novembre 2020, octobre 2022, octobre 2024)
  • Réponds dans les espaces prévus, au stylo : ni crayon de papier, ni stylo rouge (depuis 2021).
  • « Tout code Caml non indenté ne sera pas corrigé. »
  • Sauf indication de l’énoncé, les seules fonctions permises sont failwith et invalid_arg : aucune autre fonction prédéfinie, ni abs, ni max, ni float_of_int, ni String.length. Les opérateurs (+ mod = && not…) restent permis.
  • « Tout code Caml doit être suivi du résultat de son évaluation : la réponse de Caml. » Depuis 2023, le sujet précise qu’elle « fait partie de la note ».
  • Tes fonctions doivent respecter les exemples d’application donnés. Une seule version par fonction. Tu peux écrire tes propres fonctions intermédiaires, si tu dis ce qu’elles font ; la dernière fonction écrite est celle qui répond (octobre 2024).
  • La présentation est notée.

  1. Lis les exemples avant l’énoncé. Ils donnent le nom, l’ordre et le type des paramètres, le type du résultat, et l’exception attendue avec son message.

  2. Écris le type attendu. Ce sera ta réponse Caml : par exemple val rate : int -> string -> float = <fun>.

  3. Liste les cas : les paramètres invalides d’abord (invalid_arg), puis les échecs (failwith), puis le cas normal.

  4. Écris le code, indenté : then et else sous le if, un cas de match par ligne avec les | alignés, ;; à la fin de la phrase.

  5. Sous chaque définition, la réponse de Caml : val nom : type = … pour une définition (<fun> pour une fonction), - : type = valeur pour une expression.

Exemple complet séminaire · ex. 3.7, question 4 Le tarif d’un colis d’après son poids et le code du tarif, en une seule fonction. Les tarifs :

Poids jusqu’à"eco""standard""express"
500 g3,4 €4,6 €9,1 €
1 000 g4,6 €5,9 €11 €
2 000 g5,1 €6,5 €13,5 €
3 000 g6,9 €7,2 €14,2 €

Les exemples de l’énoncé fixent tout : rate 750 "eco" donne 4.6 (le poids, puis le code ; un float), un poids négatif déclenche Invalid_argument, un code inconnu ou un poids de plus de 3 000 g, Failure.

Fonction Caml : 
# let rate w code =
    if w < 0 then
      invalid_arg "weight has to be positive"
    else
      let (eco, standard, express) =
        if w <= 500 then (3.4, 4.6, 9.1)
        else if w <= 1000 then (4.6, 5.9, 11.)
        else if w <= 2000 then (5.1, 6.5, 13.5)
        else if w <= 3000 then (6.9, 7.2, 14.2)
        else failwith "too heavy"
      in
        match code with
            "eco" -> eco
          | "standard" -> standard
          | "express" -> express
          | _ -> failwith "unknown code" ;;
val rate : int -> string -> float = <fun>
# rate 750 "eco" ;;
- : float = 4.6
# rate (-150) "standard" ;;
Exception: Invalid_argument "weight has to be positive".
# rate 150 "drone" ;;
Exception: Failure "unknown code".
# rate 3500 "express" ;;
Exception: Failure "too heavy".

Le triplet choisit la ligne du tableau une seule fois, le match choisit ensuite la colonne. Une seule fonction, aucune fonction prédéfinie en dehors de failwith et invalid_arg. Sur la copie, la réponse de Caml à écrire est celle de ta définition (val rate : …) ; les exemples de l’énoncé te servent à vérifier ta fonction.

Au partiel
  • Les neuf sujets retrouvés (2017 à 2024) n’interrogent jamais ce chapitre seul : leurs exercices à écrire portent sur des listes (chapitre 3), avec une exception exigée par l’énoncé dans les neuf sujets. Tout ce qu’ils demandent s’écrit pourtant avec les outils de ce chapitre.
  • Sept sujets sur neuf ont un exercice « Mystery » : donner les réponses de Caml à quelques phrases, type compris (2 à 4 points). C’est ce que tu fais dans les blocs où tu tapes ta réponse.
  • Respecte d’abord l’exception des exemples : Invalid_argument ou Failure. Recopie aussi leur message ; les corrigés officiels ne le reproduisent pas toujours à l’identique, mais le constructeur compte.
  • Les exemples des sujets écrivent les nombres négatifs entre parenthèses : check_list (-1) [[1]; [2]; []] (octobre 2024).
Erreurs fréquentes sur la copie 
# let f x = x + 1
  f 2 ;;
Error: This expression has type int
       This is not a function; it cannot be applied.
  • Le ;; oublié : la phrase suivante se colle à la précédente, et Caml lit x + 1 f 2.
  • val contre - : une définition répond val nom : …, une expression - : …. Pour une fonction, la valeur est <fun>, jamais un résultat.
  • Le type exact : 'a quand la fonction ne fait que comparer (max2), int * int -> int pour un couple, int -> int -> int pour deux paramètres.
  • Une fonction prédéfinie comme abs ou max : réécris-la, comme absolute_value et max2 plus haut.
