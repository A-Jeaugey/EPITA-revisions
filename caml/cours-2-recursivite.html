Partie 1

Le raisonnement récursif : cas d’arrêt, cas récursif

Une fonction récursive s’appelle elle-même. L’idée : pour résoudre un problème, supposer qu’on sait déjà résoudre le même problème, en plus petit, et s’en servir.

Exemple : la factorielle, n! = 1 × 2 × … × n. Si tu connais (n − 1)!, il suffit de multiplier par n : n! = n × (n − 1)!. Et 0! = 1 se connaît sans calcul. Ce sont les deux cas de toute fonction récursive :

cas d’arrêt

La réponse est connue directement, sans nouvel appel : fact 0 vaut 1.

On dit aussi « cas de base ».

cas récursif

Le problème s’exprime avec le même problème, plus petit : fact n vaut n * fact (n-1).

C’est l’« équation de récurrence ».

En Caml, une fonction qui s’appelle elle-même se définit avec let rec :

# let rec fact n =
    if n = 0 then
      1
    else
      n * fact (n-1) ;;
val fact : int -> int = <fun>
# fact 5 ;;
- : int = 120

La réponse de Caml ne mentionne pas rec : c’est val fact : int -> int = <fun>, comme pour une fonction ordinaire. C’est elle que tu recopies sous ta fonction à l’examen.

La méthode du Moodle Moodle · conseils pour la récursivité Dans l’ordre :

  1. Les spécifications. Que doit faire la fonction exactement ? Ses paramètres (leur sens, leur type), la nature du résultat, les conditions d’appel (n ≥ 0…) : c’est le « mode d’emploi ».

  2. Le principe et les cas. « J’ai déjà vu quelque chose de ressemblant » donne la structure. Écris-la comme une fonction à trous : les différents cas, et pour chacun la réponse.

  3. L’équation de récurrence. Le cas de base est le cas d’arrêt ; les cas récursifs expriment le problème avec le même problème plus petit (n-1, n/10, n/2…).

  4. Les vérifications. Chaque appel se rapproche-t-il d’un cas d’arrêt (partie 8) ? Les cas particuliers sont-ils traités ? Faut-il une fonction chapeau (partie 3) ?

Exemple séminaire · ex. 4.2 La suite définie par u0 = 1 et un = 4un−1 + 2.

  • Spécifications : seq n rend un, pour un entier n ≥ 0. Type attendu : int -> int.
  • Cas d’arrêt : n = 0, la réponse est 1.
  • Cas récursif : un se calcule à partir de un−1, soit 4 * seq (n-1) + 2.
# let rec seq n =
    if n = 0 then
      1
    else
      4 * seq (n-1) + 2 ;;
val seq : int -> int = <fun>
# seq 0 ;;
- : int = 1
# seq 3 ;;
- : int = 106

Vérifie à la main : u1 = 6, u2 = 26, u3 = 4 × 26 + 2 = 106. Même schéma pour la suite géométrique de l’exercice 4.3, de premier terme u0 et de raison q :

# let rec geo u0 q n =
    if n = 0 then
      u0
    else
      q *. geo u0 q (n-1) ;;
val geo : float -> float -> int -> float = <fun>
# geo 3. 2. 4 ;;
- : float = 48.

u0 et q ne changent pas d’un appel à l’autre ; seul n diminue. La partie 3 montre comment éviter de les repasser à chaque appel.

À retenir
  • Toute fonction récursive a au moins un cas d’arrêt et au moins un cas récursif. Le cas d’arrêt se teste en premier.
  • Le cas récursif appelle la fonction sur une donnée plus petite, qui se rapproche du cas d’arrêt.
  • Les deux cas ont le même type, comme les deux branches d’un if : c’est le type du résultat.
Piège : le rec oublié 
# let sum n =
    if n = 0 then
      0
    else
      n + sum (n-1) ;;
Error: Unbound value sum
Hint: If this is a recursive definition,
you should add the 'rec' keyword on line 1

Sans rec, le nom sum n’existe pas encore pendant sa propre définition. Pire : si un sum existait déjà, Caml le prendrait sans rien dire, et ta fonction appellerait l’ancienne.

Partie 2

Évaluer un appel récursif : la pile des appels

Que fait Caml quand tu demandes fact 4 ? Il remplace l’appel par le corps de la fonction : 4 * fact 3. Il ne peut pas encore multiplier : il lui faut d’abord fact 3. L’appel fact 4 reste en attente, et ainsi de suite jusqu’au cas d’arrêt :

fact 4 = 4 * fact 3
       = 4 * (3 * fact 2)
       = 4 * (3 * (2 * fact 1))
       = 4 * (3 * (2 * (1 * fact 0)))
       = 4 * (3 * (2 * (1 * 1)))
       = 24

Les appels en attente forment une pile : le dernier appelé est en haut. À la descente, la pile se remplit, un appel par niveau. Au cas d’arrêt, fact 0 rend 1 sans nouvel appel. À la remontée, chaque appel reçoit la valeur de celui du dessus, termine sa multiplication et quitte la pile. Avance pas à pas :

À retenir
  • Un appel ne se termine qu’après tous les appels qu’il a lancés. Les multiplications de fact se font à la remontée, dans l’ordre inverse des appels : 1 × 1, puis 2 × 1, 3 × 2, 4 × 6.
  • fact n fait n + 1 appels, et la pile en contient jusqu’à n + 1 à la fois. Sa taille est limitée : une récursion qui ne s’arrête pas la fait déborder (partie 8).
  • Chaque appel a ses propres paramètres : le n de fact 3 vaut 3, celui de fact 4 vaut toujours 4.

Avant ou après l’appel ? séminaire · ex. 4.1 Le séminaire le montre avec un peu d’impératif : print_int affiche un entier, print_char un caractère, e1; e2 évalue e1 puis e2 (une séquence, entourée de begin … end), et () est la valeur « rien », de type unit. Ces fonctions prédéfinies ne servent pas à l’examen ; ici, elles font voir l’ordre des calculs. Devine ce qui s’affiche :

# let rec print1 n =
    if n = 0 then
      ()
    else
      begin
        print_int n; print_char ' ';
        print1 (n-1)
      end ;;
val print1 : int -> unit = <fun>
# print1 5 ;;
5 4 3 2 1 - : unit = ()
# let rec print2 n =
    if n = 0 then
      ()
    else
      begin
        print2 (n-1);
        print_int n; print_char ' ';
      end ;;
val print2 : int -> unit = <fun>
# print2 5 ;;
1 2 3 4 5 - : unit = ()

Dans print1, l’affichage précède l’appel récursif : il se fait à la descente, de 5 à 1. Dans print2, il le suit : chaque appel attend que print2 (n-1) ait fini avant d’afficher son n, donc l’affichage se fait à la remontée, de 1 à 5. La réponse de Caml, - : unit = (), vient après ce qui est affiché, sur la même ligne.

À toi séminaire · ex. 4.1 Que calculent ces fonctions ? Déroule un appel à la main, comme fact 4 plus haut, puis tape la réponse de Caml. C’est l’exercice « Mystery » de l’examen.

# let rec f3 d n =
    if n <= 1 then
      d
    else
      d * f3 (d - 1) (n - 1) ;;
val f3 : int -> int -> int = <fun>
# f3 5 3 ;;
- : int = 60
# let rec f4 n =
    if n <= 0 then 0
    else
      let r = f4 (n - 1) in
      if n mod 4 = 0 then r + n else r ;;
val f4 : int -> int = <fun>
# f4 12 ;;
- : int = 24

f3 d n multiplie n facteurs en partant de d et en descendant : f3 5 3 = 5 × 4 × 3 = 60. f4 n additionne les multiples de 4 jusqu’à n : 4 + 8 + 12 = 24. Dans f4, let r = f4 (n - 1) in fait l’appel d’abord ; l’ajout éventuel de n vient à la remontée.

Piège : la valeur du cas d’arrêt n’est pas le résultat

fact 0 rend 1, mais fact 4 vaut 24 : la valeur du cas d’arrêt remonte à l’appel du dessus, qui la transforme, et ainsi de suite jusqu’au premier appel. Pour un « Mystery », descends jusqu’au cas d’arrêt, puis remonte jusqu’en haut : ne t’arrête pas à la valeur du cas d’arrêt. Seule exception, l’accumulateur (partie 4) : son cas d’arrêt rend bien le résultat final.

Partie 3

Les fonctions chapeau : vérifier une seule fois

La factorielle de la partie 1 suppose n ≥ 0. Avec un nombre négatif, n passe de −1 à −2, −3… sans jamais valoir 0 : la récursion ne s’arrête pas, jusqu’à ce que la pile déborde.

# let rec fact n =
    if n = 0 then
      1
    else
      n * fact (n-1) ;;
val fact : int -> int = <fun>
# fact (-1) ;;
Stack overflow during evaluation (looping recursion?).

Il faut refuser les paramètres invalides avec invalid_arg (chapitre 1, partie 5). Première idée Moodle · conseils pour la récursivité : tester n < 0 dans la fonction.

# let rec fact n =
    if n < 0 then
      invalid_arg "fact: n is not a natural"
    else
      if n = 0 then
        1
      else
        n * fact (n-1) ;;
val fact : int -> int = <fun>

C’est juste, mais le test n < 0 n’est utile qu’au premier appel : ensuite, n-1 vient d’un n strictement positif, il ne peut plus être négatif. Le test est pourtant refait à chaque appel : 2n tests au lieu de n, note la page du Moodle.

La fonction chapeau vérifie les paramètres une seule fois, puis appelle une fonction récursive locale, définie par let rec … in, qui ne s’occupe que du calcul :

# let fact n =
    if n < 0 then
      invalid_arg "fact: n is not a natural"
    else
      let rec fact_rec = function
          0 -> 1
        | n -> n * fact_rec (n-1)
      in
        fact_rec n ;;
val fact : int -> int = <fun>
# fact 5 ;;
- : int = 120
# fact (-3) ;;
Exception: Invalid_argument "fact: n is not a natural".
À retenir : la forme d’une fonction chapeau 
let f n =
  if n < 0 then                  (* les paramètres invalides *)
    invalid_arg "f: n < 0"
  else
    let rec f_rec n =            (* le calcul seul *)
      …
    in
      f_rec n                    (* l’appel, avec les valeurs de départ *)
  • La fonction chapeau n’est pas récursive : let f, sans rec. La fonction locale, si : let rec f_rec … in.
  • La fonction locale voit les paramètres de la fonction chapeau : ceux qui ne changent pas d’un appel à l’autre n’ont pas besoin d’être repassés.
  • La réponse de Caml ne montre que la fonction chapeau, val fact : int -> int = <fun> : la fonction locale n’existe pas en dehors.

Éliminer les cas particuliers Moodle · conseils pour la récursivité La page du Moodle calcule x × y dans ℤ avec des additions (séminaire, exercice 4.6). Sa fonction locale mult_rec n’a qu’un paramètre, y : x ne change jamais, elle le prend dans la fonction chapeau. Elle ne marche que pour y ≥ 0 ; plutôt qu’une seconde fonction récursive pour les négatifs, la fonction chapeau l’appelle avec -y et change le signe du résultat. Mais la page contient une coquille : recopiée telle quelle, sa fonction est refusée.

# let multiply x y =
    let rec mult_rec = function
        0 -> 0
      | y -> x + mult_rec (x, y-1)
    in
    match x with
      0 -> 0
    | 1 -> y
    | x ->
        if y < 0 then
          -mult_rec (-y)
        else
          mult_rec y ;;
Error: This expression has type 'a * 'b
       but an expression was expected of type int

mult_rec prend un seul entier, et la page lui passe un couple, (x, y-1). Corrigé : mult_rec (y-1).

# let multiply x y =
    let rec mult_rec = function
        0 -> 0
      | y -> x + mult_rec (y-1)
    in
    match x with
      0 -> 0
    | 1 -> y
    | x ->
        if y < 0 then
          -mult_rec (-y)
        else
          mult_rec y ;;
val multiply : int -> int -> int = <fun>
# multiply 7 (-3) ;;
- : int = -21
# multiply (-2) 6 ;;
- : int = -12

Les cas x = 0 et x = 1 se règlent sans aucun appel récursif, et le signe de y n’est testé qu’une fois. La fonction f2 du séminaire (exercice 4.1) teste n < 0 à chaque appel : elle gagnerait, elle aussi, à avoir une fonction chapeau.

Au partiel

  • Un paramètre invalide déclenche Invalid_argument dans les neuf sujets, et l’énoncé dit lequel : check_list k lst si k < 0 (octobre 2024), pos_max lst si la liste est « initialement vide » (octobre 2022). « Initialement » : le test se fait une fois, dans la fonction chapeau, avant tout parcours.
  • Une fonction que tu ajoutes se documente : une phrase qui dit ce qu’elle fait (consigne d’octobre 2024). Une fonction locale respecte aussi l’autre consigne : « la dernière fonction écrite doit être celle qui répond à la question ».

Partie 4

Paramètres supplémentaires : accumulateur et compteur

Parfois, la fonction récursive a besoin d’informations que la fonction demandée n’a pas en paramètre. La page du Moodle en cite trois sortes : un accumulateur, où le résultat se construit au fil des appels ; une information emmenée en avançant dans la récursion (la plus grande valeur vue jusqu’ici, par exemple) ; un compteur ou un indice, souvent 0 ou 1 au premier appel. La fonction chapeau appelle la fonction récursive avec la bonne valeur de départ.

Un accumulateur séminaire · ex. 4.1 Que calcule f ?

# let f n =
    let rec g n acc =
      if n = 0 then
        acc
      else
        g (n-1) (acc * 10 + 1)
      in
        g n 0 ;;
val f : int -> int = <fun>
# f 4 ;;
- : int = 1111
# f 0 ;;
- : int = 0

g ajoute un chiffre 1 à droite de acc à chaque appel : 0, 1, 11, 111, 1111. Quand n vaut 0, le résultat est déjà construit : le cas d’arrêt rend acc. Le calcul se fait à la descente, et la remontée ne change plus rien.

Le miroir d’un entier séminaire · ex. 4.9 reverse_int 1234 doit rendre 4321. En récursion pure, il faudrait placer le 4 devant le miroir de 123, donc connaître le nombre de chiffres. Avec un accumulateur, c’est direct : on retire le dernier chiffre de n (n mod 10) et on le pousse à droite de l’accumulateur (acc * 10 + …).

# let reverse_int n =
    if n < 0 then
      invalid_arg "reverse_int: n < 0"
    else
      let rec rev acc n =
        if n = 0 then
          acc
        else
          rev (acc * 10 + n mod 10) (n / 10)
      in
        rev 0 n ;;
val reverse_int : int -> int = <fun>
# reverse_int 1234 ;;
- : int = 4321
# reverse_int 1200 ;;
- : int = 21

Compare avec la pile de fact 4 (partie 2) : ici, aucun appel n’a de calcul en attente. Chacun rend tel quel ce que rend le suivant, et le dernier rend l’accumulateur. reverse_int 1200 vaut 21 : les zéros de tête d’un entier disparaissent (la version du séminaire qui rend une chaîne donne "0021").

Un compteur séminaire · ex. 4.13 La somme des diviseurs de n plus petits que n. La fonction locale essaie chaque diviseur possible d, de 1 à n − 1 : d est un compteur, qui part de 1.

# let sum_divisors n =
    if n <= 0 then
      invalid_arg "sum_divisors: n <= 0"
    else
      let rec sum d =
        if d >= n then
          0
        else
          if n mod d = 0 then
            d + sum (d + 1)
          else
            sum (d + 1)
      in
        sum 1 ;;
val sum_divisors : int -> int = <fun>
# sum_divisors 28 ;;
- : int = 28
# sum_divisors 12 ;;
- : int = 16
# let is_perfect n =
    n > 1 && sum_divisors n = n ;;
val is_perfect : int -> bool = <fun>
# is_perfect 28 ;;
- : bool = true
# is_perfect 0 ;;
- : bool = false

Un nombre est parfait s’il est plus grand que 1 et égal à la somme de ses diviseurs propres : 28 = 1 + 2 + 4 + 7 + 14. is_perfect réutilise sum_divisors, et && s’arrête dès que n > 1 est faux : is_perfect 0 vaut false sans déclencher l’exception de sum_divisors.

Elle ne fait que compliquer les choses et vous risquez d’obtenir un résultat différent de celui demandé. » Au chapitre 3, un accumulateur renverse l’ordre d’une liste.

Récursivité sur les entiers : chiffres, pgcd, puissance

Le séminaire s’entraîne sur des entiers (exercices 4.2 à 4.13). Le raisonnement est toujours le même ; ce qui change, c’est la façon de rendre le problème plus petit :

Le calcul porte surProblème plus petitCas d’arrêtSéminaire
n : suite, somme, produitn-1n = 04.2, 4.3
les chiffres de nn / 10 ; le dernier chiffre est n mod 10n < 104.1, 4.9
deux entiers a et bb et a mod ba mod b = 04.4
une puissance xnn-1, ou n / 2 (partie 7)n = 04.10
une division par soustractionsa - ba < b4.7

Les chiffres d’un entier. Le dernier chiffre de n est n mod 10, et n / 10 retire ce chiffre. La somme des chiffres, puis la racine numérique : on recommence tant qu’il reste plus d’un chiffre.

# let rec sum_digits n =
    if n < 10 then
      n
    else
      n mod 10 + sum_digits (n / 10) ;;
val sum_digits : int -> int = <fun>
# sum_digits 2026 ;;
- : int = 10
# let rec digital_root n =
    if n < 10 then
      n
    else
      digital_root (sum_digits n) ;;
val digital_root : int -> int = <fun>
# digital_root 2026 ;;
- : int = 1

digital_root appelle sum_digits, puis s’appelle elle-même sur le résultat : 2026, puis 10, puis 1. Elle termine, car la somme des chiffres d’un nombre d’au moins deux chiffres est plus petite que lui.

Le pgcd séminaire · ex. 4.4 Algorithme d’Euclide : si b divise a, le pgcd est b ; sinon, c’est le pgcd de b et du reste a mod b. L’exercice porte sur des entiers naturels non nuls : la fonction chapeau le vérifie.

# let gcd a b =
    if a <= 0 || b <= 0 then
      invalid_arg "gcd: a and b must be > 0"
    else
      let rec euclid a b =
        if a mod b = 0 then
          b
        else
          euclid b (a mod b)
      in
        euclid a b ;;
val gcd : int -> int -> int = <fun>
# gcd 150 45 ;;
- : int = 15
# gcd 45 150 ;;
- : int = 15
# gcd 0 5 ;;
Exception: Invalid_argument "gcd: a and b must be > 0".

Inutile d’ordonner a et b : si a < b, a mod b vaut a, et le premier appel les échange. Sans la fonction chapeau, euclid 5 0 déclencherait Exception: Division_by_zero.

La puissance et la division séminaire · ex. 4.10 et 4.7 xn = x × xn−1, pour un réel x : attention aux opérateurs flottants. Puis le quotient et le reste de a par b, avec des soustractions et une seule fonction récursive, qui rend un couple :

# let rec power x n =
    if n = 0 then
      1.
    else
      x *. power x (n-1) ;;
val power : float -> int -> float = <fun>
# power 2. 10 ;;
- : float = 1024.
# let euclid_div a b =
    if a < 0 || b <= 0 then
      invalid_arg "euclid_div: a < 0 or b <= 0"
    else
      let rec div a =
        if a < b then
          (0, a)
        else
          let (q, r) = div (a - b) in
            (q + 1, r)
      in
        div a ;;
val euclid_div : int -> int -> int * int = <fun>
# euclid_div 17 5 ;;
- : int * int = (3, 2)
# euclid_div 3 5 ;;
- : int * int = (0, 3)

17 = 5 × 3 + 2 : on retire 5 trois fois avant de passer sous 5. Chaque appel récupère le couple de l’appel suivant avec let (q, r) = … in et ajoute 1 au quotient. Comme mult_rec (partie 3), la fonction locale div ne prend que a : b ne change pas.

Au partiel
  • Disons-le franchement : de 2017 à 2024, aucun des neuf sujets n’a demandé une fonction récursive sur des entiers seuls (factorielle, pgcd, puissance, chiffres). Les fonctions à écrire portent sur des listes.
  • Ce chapitre sert pourtant partout. Une fonction sur une liste suit le même raisonnement : cas d’arrêt, cas récursif, fonction chapeau, accumulateur. Et les QCM du séminaire (30 % de la note) portent aussi sur la récursivité : c’est le thème du QCM 5.
  • Sept sujets sur neuf ont un exercice « Mystery » (2 à 4 points) : lire du code récursif et donner les réponses de Caml, comme en partie 2.
Piège : les parenthèses de l’appel 
# let rec sum_digits n =
    if n < 10 then
      n
    else
      n mod 10 + sum_digits n / 10 ;;

sum_digits n / 10 se lit (sum_digits n) / 10 : l’application passe avant la division (chapitre 1, partie 3). La fonction se rappelle avec le même n, sans fin. Caml accepte la définition, seule l’exécution révèle l’erreur. Écris sum_digits (n / 10), fact (n-1).

Partie 6

Plusieurs appels récursifs : Fibonacci, Hanoï

Une fonction peut s’appeler plusieurs fois dans un même cas. La suite de Fibonacci du séminaire séminaire · ex. 4.8 : F(n) = 1 si n ≤ 1, et F(n) = F(n − 1) + F(n − 2) sinon. La définition se traduit mot pour mot :

# let rec fibo n =
    if n <= 1 then
      1
    else
      fibo (n-1) + fibo (n-2) ;;
val fibo : int -> int = <fun>
# fibo 5 ;;
- : int = 8
# fibo 10 ;;
- : int = 89

Chaque appel qui n’est pas un cas d’arrêt en lance deux : les appels ne forment plus une chaîne, mais un arbre. Un appel se termine entièrement, avec tous ses sous-appels, avant que l’autre commence. Déroule fibo 5 :

15 appels pour fibo 5, alors qu’il n’existe que six valeurs différentes, de fibo 0 à fibo 5. Les appels en pointillés refont un calcul déjà fait : fibo 3 est calculé deux fois, fibo 2 trois fois. La partie 7 règle ce problème.

Le dérouleur évalue fibo (n-1) avant fibo (n-2), dans l’ordre de lecture. OCaml ne fixe pas l’ordre d’évaluation des deux membres d’un +, et commence en pratique par celui de droite : le résultat et le nombre d’appels sont les mêmes.

Les tours de Hanoï Moodle · Hanoï Trois piquets, numérotés 1, 2 et 3 ; n disques de tailles différentes, empilés sur le piquet 1, du plus grand en bas au plus petit en haut. Il faut les amener sur le piquet 3, un disque à la fois, sans jamais poser un disque sur un plus petit.

Le raisonnement récursif donne la solution sans chercher les coups un par un. Pour déplacer n disques de source vers destination :

  1. déplacer les n − 1 disques du dessus vers le troisième piquet : le même problème, plus petit ;

  2. déplacer le grand disque, désormais seul, vers destination ;

  3. déplacer les n − 1 disques du troisième piquet vers destination : encore le même problème, plus petit.

Avec 0 disque, il n’y a rien à faire : c’est le cas d’arrêt. Les piquets valent 1, 2 et 3, de somme 6 : le troisième piquet est 6 - source - destination. La page donne move, qui affiche un déplacement, et la fonction chapeau ; il reste à écrire play (le FIXME de la page) :

# let move source destination =
    print_int source ;
    print_string " -> " ;
    print_int destination ;
    print_newline() ;;
val move : int -> int -> unit = <fun>
# let hanoi n =
    let rec play n source destination =
      if n > 0 then
        let other = 6 - source - destination in
          begin
            play (n-1) source other ;
            move source destination ;
            play (n-1) other destination
          end
    in
      if n <= 0 then
        invalid_arg "Hanoi: number of disks invalid"
      else
        play n 1 3 ;;
val hanoi : int -> unit = <fun>
# hanoi 3 ;;
1 -> 3
1 -> 2
3 -> 2
1 -> 3
2 -> 1
2 -> 3
1 -> 3
- : unit = ()

C’est exactement l’affichage de la page. Le corps de play est un if sans else : c’est permis ici, car la fonction ne rend rien (unit), elle affiche (chapitre 1, partie 4). Les trois étapes forment une séquence entre begin et end, évaluée dans l’ordre.

Combien de déplacements ? La page pose la question : 1 coup pour un disque, 3 pour deux. Le raisonnement donne directement une fonction récursive : n − 1 disques, puis le grand, puis encore n − 1 disques.

# let rec moves n =
    if n = 0 then
      0
    else
      2 * moves (n-1) + 1 ;;
val moves : int -> int = <fun>
# moves 3 ;;
- : int = 7
# moves 10 ;;
- : int = 1023

Le nombre de coups double presque à chaque disque ajouté : 2n − 1. Avec les 64 disques de la légende d’Édouard Lucas, il en faudrait 264 − 1, plus de 18 milliards de milliards.

À retenir
  • Avec deux appels par cas, le nombre d’appels est multiplié à chaque niveau : il croît de façon exponentielle avec n.
  • Pour Hanoï, c’est inévitable : chaque déplacement affiché doit être fait. Pour Fibonacci, non : les mêmes valeurs sont recalculées, et la partie 7 les calcule une seule fois.
  • L’ordre d’une séquence e1; e2; e3 est garanti : de gauche à droite. Celui des deux membres de fibo (n-1) + fibo (n-2) ne l’est pas.
Piège : deux appels, ce n’est pas deux fois plus long

Deux appels par cas ne font pas deux fois plus d’appels que fact : fibo 5 fait 15 appels, fibo 25 en fait 242 785, fibo 40 plus de 331 millions (partie 7). Chaque niveau multiplie le nombre d’appels du niveau précédent.

Partie 7

Optimiser : ne pas répéter un calcul, s’arrêter dès que possible

La fiche du cours fixe trois règles de complexité : « éviter les calculs inutiles, ne pas répéter des calculs, arrêter dès qu’une réponse est donnée ». Une fonction peut donner le bon résultat et les enfreindre toutes : cette partie montre comment les respecter.

Ne pas répéter un calcul. Combien d’appels fait fibo n ? Une fonction récursive de la même forme le dit : un appel, plus ceux des deux sous-appels.

# let rec calls n =
    if n <= 1 then
      1
    else
      1 + calls (n-1) + calls (n-2) ;;
val calls : int -> int = <fun>
# calls 5 ;;
- : int = 15
# calls 25 ;;
- : int = 242785
# calls 40 ;;
- : int = 331160281

Plus de 331 millions d’appels pour fibo 40, qui ne demande que 41 valeurs. La solution : calculer chaque valeur une seule fois, en emmenant les deux derniers termes de la suite dans des paramètres supplémentaires (partie 4).

# let fibo n =
    if n < 0 then
      invalid_arg "fibo: n < 0"
    else
      let rec fib a b n =
        if n = 0 then
          a
        else
          fib b (a + b) (n-1)
      in
        fib 1 1 n ;;
val fibo : int -> int = <fun>
# fibo 10 ;;
- : int = 89
# fibo 50 ;;
- : int = 20365011074

a et b sont deux termes consécutifs de la suite ; à chaque appel, on avance d’un terme : (a, b) devient (b, a + b). fibo 50 fait 51 appels et répond tout de suite ; la première version en ferait plus de 40 milliards.

Un appel répété dans un if. Le plus grand chiffre d’un entier : on compare le dernier chiffre au plus grand chiffre du reste.

# let rec max_digit n =
    if n < 10 then
      n
    else
      if n mod 10 > max_digit (n / 10) then
        n mod 10
      else
        max_digit (n / 10) ;;
val max_digit : int -> int = <fun>
# max_digit 2026 ;;
- : int = 6
# let rec max_digit n =
    if n < 10 then
      n
    else
      let m = max_digit (n / 10) in
        if n mod 10 > m then
          n mod 10
        else
          m ;;
val max_digit : int -> int = <fun>
# max_digit 2026 ;;
- : int = 6

Les deux versions rendent 6. Mais la première écrit deux fois max_digit (n / 10) : quand le test est faux, le même appel est refait en entier, et chacun peut se dédoubler à son tour. Sur un entier de 10 chiffres comme 9876543210, cela fait 1 023 appels au lieu de 10. Un let … in nomme le résultat pour le réutiliser. Au chapitre 3, le maximum d’une liste tend le même piège.

La puissance rapide séminaire · ex. 4.10 xn = (xn/2)² si n est pair, et x × (xn/2)² sinon, avec n/2 en division entière. Le carré se fait avec un seul appel, nommé p :

# let rec fast_power x n =
    if n = 0 then
      1.
    else
      let p = fast_power x (n / 2) in
        if n mod 2 = 0 then
          p *. p
        else
          x *. p *. p ;;
val fast_power : float -> int -> float = <fun>
# fast_power 2. 10 ;;
- : float = 1024.
# fast_power 1.5 3 ;;
- : float = 3.375

Pour n = 1 000 : 11 appels, contre 1 001 pour power (partie 5). Écrire fast_power x (n / 2) *. fast_power x (n / 2) referait chaque calcul deux fois : 2 047 appels, pire que la version classique.

S’arrêter dès que la réponse est connue séminaire · ex. 4.12 Un entier n > 1 est premier s’il n’a aucun diviseur entre 2 et n − 1. Deux économies : s’arrêter au premier diviseur trouvé, puisque la réponse est alors false ; et ne pas chercher au-delà de √n, car si n = d × e avec d ≤ e, alors d × d ≤ n.

# let is_prime n =
    if n <= 1 then
      invalid_arg "is_prime: n <= 1"
    else
      let rec no_divisor d =
        if d * d > n then
          true
        else
          if n mod d = 0 then
            false
          else
            no_divisor (d + 1)
      in
        no_divisor 2 ;;
val is_prime : int -> bool = <fun>
# is_prime 97 ;;
- : bool = true
# is_prime 91 ;;
- : bool = false
# is_prime 1 ;;
Exception: Invalid_argument "is_prime: n <= 1".

Pour 1 000 003, qui est premier, no_divisor fait 1 000 appels au lieu d’un million ; pour 1 000 000, un seul. Les deux cas d’arrêt passent avant le cas récursif, et le test d * d > n évite sqrt, une fonction prédéfinie. Avec || et &&, qui s’arrêtent dès que le résultat est connu (chapitre 1, partie 1), la même fonction tient en une ligne :

# let is_prime n =
    if n <= 1 then
      invalid_arg "is_prime: n <= 1"
    else
      let rec no_divisor d =
        d * d > n || (n mod d <> 0 && no_divisor (d + 1))
      in
        no_divisor 2 ;;
val is_prime : int -> bool = <fun>
# is_prime 91 ;;
- : bool = false
À retenir : les trois règles
  • Éviter les calculs inutiles : tester les paramètres une seule fois (fonction chapeau, partie 3), régler les cas simples sans appel (multiply).
  • Ne pas répéter un calcul : un résultat qui sert deux fois se nomme avec let … in ; une valeur qu’on recalculerait s’emmène dans un paramètre.
  • S’arrêter dès que la réponse est connue : un cas d’arrêt de plus (trouvé, propriété fausse), ou && et ||.
Au partiel

Huit sujets sur neuf (2017 à 2024) demandent une fonction qui peut s’arrêter avant la fin de la liste : chercher un élément, vérifier une propriété, parcourir une liste triée. La page « Conseils pour les listes » le rappelle : un parcours partiel a au moins un autre cas d’arrêt que la liste vide. Le chapitre 3 l’applique.

Piège : un let … in trop tôt 
# let is_prime n =
    if n <= 1 then
      invalid_arg "is_prime: n <= 1"
    else
      let rec no_divisor d =
        if d * d > n then
          true
        else
          let rest = no_divisor (d + 1) in
            n mod d <> 0 && rest
      in
        no_divisor 2 ;;

Le résultat est juste, mais rest est calculé avant le test : la fonction va toujours jusqu’à √n, soit 1 000 appels pour 1 000 000 au lieu d’un seul. Un let … in évite de répéter un calcul ; placé trop tôt, il fait un calcul dont on n’a peut-être pas besoin. Écris l’appel là où sa valeur sert.

Partie 8

Terminaison et erreurs fréquentes

Une fonction récursive termine si chaque appel se rapproche d’un cas d’arrêt et finit par l’atteindre, pour tous les paramètres permis. « Plus petit » ne suffit pas : il faut tomber sur le cas d’arrêt. Le séminaire le demande : « étudier tous les cas ». Ces appels terminent-ils ?

# let rec f1 n = match n with
      0 -> 0
    | n -> n + f1 (n-1) ;;
val f1 : int -> int = <fun>
# f1 (-1) ;;
Stack overflow during evaluation (looping recursion?).
# let rec halve n =
    if n = 0 then
      0
    else
      1 + halve (n - 2) ;;
val halve : int -> int = <fun>
# halve 6 ;;
- : int = 3
# halve 7 ;;
Stack overflow during evaluation (looping recursion?).

Quand une récursion ne s’arrête pas, la pile des appels grossit jusqu’à déborder : Caml répond Stack overflow during evaluation (looping recursion?). Avec f1 (-1), n descend sans jamais valoir 0. Avec halve 7, n vaut 7, 5, 3, 1, −1… : il saute par-dessus 0. Deux remèdes : un cas d’arrêt qui couvre tout ce qui reste (n <= 0, n < 2), ou une fonction chapeau qui refuse les paramètres hors du domaine.

Le cas de double · séminaire, exercice 4.1 
# let rec double = function
      0 -> 0
    | n -> n / 2 + double (2*n) ;;
val double : int -> int = <fun>
# double 0 ;;
- : int = 0
# double 1 ;;
- : int = -1

Pour n ≠ 0, 2*n s’éloigne de 0 : mathématiquement, double n ne termine pas, et c’est la réponse attendue au séminaire. Pourtant Caml répond −1. Ses entiers sont bornés (max_int vaut 262 − 1) : à force de doubler, 2*n dépasse la borne, et le calcul finit par donner 0, ce qui arrête la récursion. Ce −1 n’a aucun sens : seul le raisonnement compte.

  • Les motifs sont essayés dans l’ordre : n filtre tout, le cas 0 placé après ne sert jamais, et f1 3 ne s’arrête pas. L’avertissement le signale : le cas d’arrêt vient en premier.
  • Le cas d’arrêt et le cas récursif ont le même type : 1., pas 1, quand le résultat est un float.
  • count_digits 0 rend 0, mais 0 s’écrit avec un chiffre. Teste le plus petit cas : le bon cas d’arrêt est n < 10, qui rend 1. C’est mystery, en tête de chapitre.

Avant de rendre une fonction récursive :

  1. Les spécifications viennent de l’énoncé et des exemples : nom, ordre et type des paramètres, type du résultat, exception et son message.

  2. Le cas d’arrêt est testé en premier, et vérifié sur le plus petit exemple.

  3. Le cas récursif appelle la fonction sur une donnée plus petite, entre parenthèses.

  4. La terminaison est assurée pour tous les paramètres permis ; les autres sont refusés par la fonction chapeau.

  5. Aucun calcul répété ni inutile, et l’arrêt dès que la réponse est connue.

  6. La réponse de Caml suit la fonction : val fact : int -> int = <fun>, sans rec.
