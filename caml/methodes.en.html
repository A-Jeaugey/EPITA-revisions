1Method 1

Writing a recursive function

This is the method of the Moodle page “Advice on recursion” (in French, « Conseils pour la récursivité »), in its order. It works for almost every function to write: all 9 papers have a recursive function on a list, with an exception required by the statement.

  1. What is the question? The specification. What the function computes, its parameters (meaning, type, order), the calling conditions and the exception when they do not hold. The examples of the paper give it: read them first. Write down the expected type: it will be your Caml answer.

  2. The principle. “I have already seen something like it”: a full traversal (counting), a partial traversal (searching), a list to build, a rank that goes down. It gives the structure and the cases.

  3. The function with holes. Write the structure with its cases, then the answer of each: the base cases (the answer is known without a new call), then the recursive cases (the same problem, smaller). Check that each call gets closer to a base case.

  4. The special cases. Once the general case is written, try the edge cases: empty list, a single element, parameter out of range, element not found. Add the missing cases.

  5. The wrapper, if needed. A non-recursive “wrapper” function checks the parameters once, then calls the local recursive function. It also gives that function its extra parameters (counter, accumulator) with their starting value.

Example lists tutorial · ex. 1.4 The element at rank i of a list. Same scheme as remove_nth (October 2019) and insert_nth (2018 and 2020).

1. Specification:

nth i lst returns the element at rank i of the list lst (the first one is at rank 1). It raises Invalid_argument if i ≤ 0, Failure if the list has fewer than i elements. Expected type: int -> 'a list -> 'a.

2. Principle:

A partial traversal, like a search, with a rank that goes down: for each element passed, look for rank i - 1 in the rest. At rank 1, it is the head.

3. Function with holes (it does not compile yet): 
let rec get i = function
    [] -> (* no element left: the list is too short *)
  | e :: l ->
      if i = 1 then
        (* the answer is the head *)
      else
        (* same problem, smaller: rank i - 1 in l *)
4. Special cases: without a test, a rank ≤ 0 never equals 1, and the recursion goes down to the empty list: 
# let rec get i = function
      [] -> failwith "nth: list too short"
    | e :: l ->
        if i = 1 then
          e
        else
          get (i-1) l ;;
val get : int -> 'a list -> 'a = <fun>
# get 0 ['a'; 'b'] ;;
Exception: Failure "nth: list too short".
5. The wrapper checks the rank once, then calls the recursive function: 
# let nth i lst =
    if i <= 0 then
      invalid_arg "nth: i <= 0"
    else
      let rec get i = function
          [] -> failwith "nth: list too short"
        | e :: l ->
            if i = 1 then
              e
            else
              get (i-1) l
      in
        get i lst ;;
val nth : int -> 'a list -> 'a = <fun>
# nth 3 ['a'; 'b'; 'c'; 'd'] ;;
- : char = 'c'
# nth 5 ['a'; 'b'] ;;
Exception: Failure "nth: list too short".
# nth 0 ['a'; 'b'] ;;
Exception: Invalid_argument "nth: i <= 0".
# nth (-1) [] ;;
Exception: Invalid_argument "nth: i <= 0".

The recursive function only sees ranks ≥ 1; it goes down to 1 (found) or to [] (too short): each call gets closer to a base case. The test on i is done only once, even on a long list, and nth (-1) [] does raise Invalid_argument.

The Moodle page

It shows the wrapper on fact, then on multiply x y. This second example has a typo: mult_rec (x, y-1) while mult_rec takes a single integer. As it stands, it does not compile; it should be mult_rec (y-1).

The course: base case and recursive case, wrapper functions, extra parameters. To do: lists tutorial 1.4, remove_nth (2019), insert_mult (2023).

2Method 2

Handling one or two lists

The Moodle page “Advice on lists” starts from a question: how many lists must be traversed, and is the head enough? The answer gives the cases of the pattern matching. Then add the cases due to the other parameters (value searched for, sorted list, property).

SituationThe casesIn the papers
One list[] · e :: lstremove_x (2023), insert_post (2022)
The head is not enough: comparing two neighbours[] · [e] · e1 :: e2 :: lstdominoes (2019), the April 2019 Mystery
Pairs[] · (a, b) :: lstassoc (2017, April 2019)
A list of lists[] · l :: otherscheck_list (2024)
Two lists traversed together([], []) · (lst, []) · ([], lst) · (e1 :: l1, e2 :: l2)for_all2 (2017, 2019), is_image (2018)
Two lists, only one moves at each callthe same cases, and two recursive calls depending on which list movesshared (lists tutorial 4.2), alternate_list (2021)

  1. The empty list is a base case. Decide what it returns from the statement: a value (0, true, []) or an exception.

  2. Full or partial traversal? If the whole list must be seen (counting, copying), every non-empty case is recursive. Otherwise you need at least one other base case: found, property false, value passed in a sorted list.

  3. Pure recursion first. Express the result for e :: lst from the result for lst. Moodle warns that an accumulator is, most of the time, not needed: it only makes things more complicated and you risk getting a different result from the one asked for. In 2023, a script lost 2 points out of 8 because its accumulator had reversed the order of the sublists.

  4. Two lists together: group them in a pair with match (l1, l2) with, and check that the four cases are covered. A catch-all case | _ -> at the end groups the different lengths.

The head is not enough October 2019 · ex. 2 · 4 points A chain of dominoes is valid if neighbouring halves have the same number of spots. Three cases, and the recursive call starts again from (c, d) :: l, not from l, otherwise a domino is lost (official answer key):

# let rec is_dominoes = function
      [] | [_] -> true
    | (_, b) :: (c, d) :: l -> b = c && is_dominoes ((c, d) :: l) ;;
val is_dominoes : ('a * 'a) list -> bool = <fun>
# is_dominoes [(1, 2); (2, 3); (3, 3); (3, 6)] ;;
- : bool = true
# is_dominoes [(2, 3); (2, 4); (1, 4)] ;;
- : bool = false
# is_dominoes [] ;;
- : bool = true

Two lists, only one moves lists tutorial · ex. 4.2 The elements shared by two increasing lists. If the heads differ, only the list with the smaller head moves on: call again with the other list whole (l1 or l2), so as not to lose its head.

# let rec shared l1 l2 = match (l1, l2) with
      ([], _) | (_, []) -> []
    | (e1 :: r1, e2 :: r2) ->
        if e1 = e2 then
          e1 :: shared r1 r2
        else
          if e1 < e2 then
            shared r1 l2
          else
            shared l1 r2 ;;
val shared : 'a list -> 'a list -> 'a list = <fun>
# shared [1; 3; 6; 6; 8; 9] [2; 5; 6; 6; 8; 9] ;;
- : int list = [6; 6; 8; 9]
Traps
  • [e; lst] is a list of two elements, not “an element followed by a list”: the general case is written e :: lst.
  • A forgotten case does not show when you write: Caml prints Warning 8 under your definition, then Match_failure at run time. In your Caml answer, a warning reveals an oversight.

The course: matching a list, two lists, two elements, pairs, accumulator. To do: dominoes, shared, alternate lists.

3Method 3

Choosing failwith or invalid_arg, and where to put the test

All nine papers require an exception. These are the only two predefined functions allowed, and the statement always says which one it expects: its examples show the constructor and the message.

invalid_arg "…"failwith "…"
Caml answerException: Invalid_argument "…".Exception: Failure "…".
WhenA parameter does not meet the calling conditions: rank ≤ 0, k < 0, i > j, list empty “from the start”.The computation fails on the way: list too short, key not found, no element to insert after.
WhereIn the wrapper function, before any traversal, once.Where the failure shows, often the [] case of the recursive function.
Papers9 out of 97 out of 9 (not in 2023 nor 2024)

  1. Read the examples: copy the constructor and the message. The 2018 to 2020 papers and the lists tutorial print Invalid_arg "negative rank": it is a typo, the constructor is Invalid_argument, and you raise it with invalid_arg.

  2. An invalid parameter is tested in the wrapper. Tested in the recursive function, it would be redone at each call, and a base case met before it would give the wrong exception.

  3. A failure on the way is raised in the case that reveals it: end of the list reached too early, a key passed in a sorted list.

  4. Follow the order set by the statement. for_all2 (2017, 2019): “If it finds a pair such that p ai bi is false, it returns false. Otherwise, it raises an exception”: the false pair comes before the exception, so the exception comes at the end of the traversal, not from a length test beforehand.

Both functions have type string -> 'a: an exception takes the type of any branch. That is what allows if i < 1 then invalid_arg "…" else ….

# invalid_arg ;;
- : string -> 'a = <fun>
# failwith ;;
- : string -> 'a = <fun>

The test in the wrong place October 2019 · ex. 3 · 5 points remove_nth i list deletes the element at rank i; Invalid_argument if i is negative or zero, Failure if the list is too short. With the test on i inside the recursive function, the empty list is matched before it:

# let rec remove_nth i = function
      [] -> failwith "out of bound"
    | e :: q ->
        if i <= 0 then
          invalid_arg "negative rank"
        else
          if i = 1 then
            q
          else
            e :: remove_nth (i-1) q ;;
val remove_nth : int -> 'a list -> 'a list = <fun>
# remove_nth (-2) [1; 2; 3] ;;
Exception: Invalid_argument "negative rank".
# remove_nth (-2) [] ;;
Exception: Failure "out of bound".
Caml function: 
# let remove_nth i list =
    if i < 1 then
      invalid_arg "negative rank"
    else
      let rec del i = function
          [] -> failwith "out of bound"
        | e :: q ->
            if i = 1 then
              q
            else
              e :: del (i-1) q
      in
        del i list ;;
val remove_nth : int -> 'a list -> 'a list = <fun>
# remove_nth 5 [1; 2; 3; 4; 5; 6; 7; 8; 9] ;;
- : int list = [1; 2; 3; 4; 6; 7; 8; 9]
# remove_nth 10 [1; 2; 3; 4; 5; 6; 7; 8; 9] ;;
Exception: Failure "out of bound".
# remove_nth (-2) [] ;;
Exception: Invalid_argument "negative rank".

4Method 4

Writing the Caml answer of a phrase

Under every function on your script, and for every phrase of a Mystery. Since 2023, the header says it “is part of the mark”. It has a fixed form, which depends on the phrase:

PhraseCaml answer
Definition of a value: let a = 1 + 2 ;;val a : int = 3
Definition of a functionval nth : int -> 'a list -> 'a = <fun>
Expression: nth 3 ['a'; 'b'; 'c'] ;;- : char = 'c'
Exception raisedException: Failure "nth: list too short".
Phrase rejected (type, unknown name): nothing is definedError: Unbound value fact
Incomplete matching: the warning, then the definitionWarning 8 [partial-match]: this pattern-matching is not exhaustive.

  1. One type per parameter, in order, separated by ->, then the type of the result: insert_mult n x lst gives int -> 'a -> 'a list -> 'a list.

  2. A function parameter is written in brackets, with its own type: ('a -> bool) for a predicate, ('a -> 'a -> bool) for an order.

  3. 'a when nothing forces the type. Comparing (=, <) or moving elements does not fix their type; +, mod or a constant 0 give int, +. gives float. Two unrelated types: 'a and 'b.

  4. Compound types: int list, (int * 'a) list for a list of pairs, 'a list list for a list of lists.

  5. The value as Caml writes it: 4. and not 4.0, strings in double quotes, characters in single quotes, [1; 2] with semicolons; a function is <fun>.

Your turn. Type the Caml answer to each phrase, then compare. An empty field simply reveals the answer.

# let rec how_many f = function
      [] -> 0
    | e :: l -> (if f e then 1 else 0) + how_many f l ;;
val how_many : ('a -> bool) -> 'a list -> int = <fun>
# how_many (function x -> x > 0) [-1; 2; 0; 5] ;;
- : int = 2
# let count_even = how_many (function x -> x mod 2 = 0) ;;
val count_even : int list -> int = <fun>
# let first = function
      [] -> failwith "first: empty list"
    | (a, b) :: _ -> a ;;
val first : ('a * 'b) list -> 'a = <fun>
# first [(3.5, "x"); (1., "y")] ;;
- : float = 3.5
# first [] ;;
Exception: Failure "first: empty list".
# [[1; 2]; []] ;;
- : int list list = [[1; 2]; []]
# [] ;;
- : 'a list = []
# 4.0 ;;
- : float = 4.
Traps
  • count_even is defined without writing its list: it is a partial application, and its type is what remains, int list -> int.
  • first does nothing with b: its type stays free, 'b.
  • An exception has no type in the answer: Exception: … and a full stop.
  • Caml splits a long type over two lines (… list = then <fun>); on your script, one line is enough.

The course: reading a Caml answer, the type of a function, partial application. To do: seminar 1.2, 2.1, higher-order tutorial 1.1.

5Method 5

Reading a Mystery: the trace, then what it computes

7 papers out of 9, worth 2 to 4 points: a function with a meaningless name, whose type you must give (2022, 2024), the results of a few phrases, sometimes what it computes (April 2019), a phrase to declare “Error” (2021) or the call that produces a given result (2022).

  1. The type first, by reading the code: the patterns (list, pair), the operations (* forces int), what each case returns. If a matching misses a case, Caml prints Warning 8 before the val; the April 2019 answer key accepts an answer “apart from any warnings”.

  2. Unroll the smallest example, call by call, writing down what each call waits for. Spot the shadowed names: a variable with the same name in a local function hides the one above.

  3. Do the other phrases, starting with the edge cases (empty list, one element): they often hit a base case.

  4. Say in one sentence what the function computes, and check it on an example you did not unroll.

  5. “Error”? Check the type of each argument: in 2021, a two-parameter function is passed where a one-parameter predicate is expected.

Example November 2020 · ex. 5 · 2 points “The function go is defined as below. Give the results of the successive evaluations of the following phrases.”

let go = function
    [] -> []
  | e :: list ->
    let rec what x = function
          [] -> []
       | e :: list -> ( e * x ) ::( what e list )
    in
    what e list ;;

The type. go matches a list; e * x forces integers; each case returns a list of integers. Answer: val go : int list -> int list = <fun>. In what, the e and list of the pattern shadow those of go.

The trace of go [1; 2; 3; 4; 5]: go calls what with the head and the rest. Each call of what waits for the result of the next one to put a product in front.

# go [1; 1; 1; 1; 1] ;;
- : int list = [1; 1; 1; 1]
# go [42] ;;
- : int list = []
# go [1; 2; 3; 4; 5] ;;
- : int list = [2; 6; 12; 20]
# go [2; 21; 2; 21; 2; 21] ;;
- : int list = [42; 42; 42; 42; 42]
What go computes:

The list of the products of two neighbouring elements: [a1 * a2; a2 * a3; …], one element fewer than the starting list. Hence [] for a one-element list.

The course: the call stack. To do, from the simplest to the longest: go (2020), sublist (2019), April 2019, 2024, 2021, 2022.

6Method 6

Using a higher-order function

7 papers out of 9 make you write a function that receives a function as a parameter, and 7 out of 9 go on with “Use the previous function to define…”. The functions are always written by hand: neither List.map nor List.filter.

  1. Spot the function parameter: “a boolean function”, “a predicate”, “a comparison function”, “a two-argument function”. In the type, it is in brackets.

  2. Call it like a function, with its arguments: f e, p e1 e2, order x e. It is already a boolean: if f e then, not if f e = true then.

  3. Pass it to every recursive call: how_many f l, not how_many l.

  4. To use it, give it an anonymous function (function x -> x mod n = 0), a named local function, or an operator in brackets such as (=). Question 2 can be done even if question 1 is not: in 2022, “whether it is written or not”.

  5. Keep the order of the parameters of the statement: the comparison is the last parameter of insert x list comp (April 2019), the second of insert_x x order lst (2024).

Example October 2018 · ex. 3 · 4 points how_many f l counts the elements of l that satisfy f; then use it for count_multiples n l, the number of multiples of n in l.

Caml function: 
# let rec how_many f = function
      [] -> 0
    | e :: l ->
        if f e then
          1 + how_many f l
        else
          how_many f l ;;
val how_many : ('a -> bool) -> 'a list -> int = <fun>
# let count_multiples n l = how_many (function x -> x mod n = 0) l ;;
val count_multiples : int -> int list -> int = <fun>
# count_multiples 3 [1; 3; 6; 7; 9; 0] ;;
- : int = 4

The predicate uses n, the parameter of count_multiples: that is why it is written inside. The official answer key also gives the form without l, a partial application, of the same type:

# let count_multiples n = how_many (function x -> x mod n = 0) ;;
val count_multiples : int -> int list -> int = <fun>
Two mistakes Caml rejects 
# let rec bad f = function
      [] -> 0
    | e :: l -> if f e = true then 1 + bad l else bad f l ;;
Error: This expression has type 'a list
       but an expression was expected of type 'a -> bool
# how_many (=) [1; 2] ;;
Error: This expression has type 'a -> 'a -> bool
       but an expression was expected of type 'a -> bool
       Type 'a -> bool is not compatible with type bool
  • bad l: the function parameter was forgotten in the recursive call.
  • (=) takes two parameters, how_many expects a one-parameter predicate: that is the “Error” of the 2021 Mystery.

The course: a function as a parameter, an order as a parameter, for_all2. To do: how_many, for_all2 and almost, insertion sort (2024), less2 and common.

7Method 7

Optimising: never repeat a computation, stop early

The course sheet asks you to “avoid useless computations, not repeat computations, stop as soon as an answer is found”. A function that is right but slow loses points: stopping early is expected in 8 papers out of 9.

  1. Do not redo a recursive call: if its result is used twice, name it with let … in.

  2. Stop as soon as the answer is known: element found, property false, value passed in a sorted list. && and || do not evaluate their second operand when the first one is enough.

  3. Test the parameters only once, in the wrapper (method 3).

  4. Add at the head with ::. l1 @ l2 copies the whole of l1: a reverse written with @ copies n(n − 1)/2 cells, nearly 200 million for 20,000 elements, against 20,000 with an accumulator (lists tutorial 3.5).

A call done again lists tutorial · ex. 1.5 The maximum of a list. When the test is false, this version computes maximum lst again in full:

# let rec maximum = function
      [] -> failwith "maximum: empty list"
    | [e] -> e
    | e :: lst ->
        if e > maximum lst then
          e
        else
          maximum lst ;;
val maximum : 'a list -> 'a = <fun>
# maximum [1; 2; 3; 4] ;;
- : int = 4

On an increasing list, each call starts two: 7 calls for 3 elements, 15 for 4, 1,048,575 for [1; …; 20]. With let … in, one call per element:

# let rec maximum = function
      [] -> failwith "maximum: empty list"
    | [e] -> e
    | e :: lst ->
        let m = maximum lst in
          if e > m then
            e
          else
            m ;;
val maximum : 'a list -> 'a = <fun>

Stopping early November 2020 · ex. 2 In an increasing list, there is no point looking for x after a greater element. And ||, && stop at the first operand when it is enough:

# let rec delete x = function
      [] -> []
    | e :: l ->
        if e > x then
          e :: l
        else
          if e = x then
            l
          else

val delete : 'a -> 'a list -> 'a list = <fun>
# delete 4 [1; 2; 2; 3; 4; 4; 4; 5] ;;
- : int list = [1; 2; 2; 3; 4; 4; 5]
# delete 0 [1; 2; 3] ;;
- : int list = [1; 2; 3]
# false && (1 / 0 = 0) ;;

Trap

present a list && present b list gives the right answer to search_both (2020), but goes through the list twice. The expected idea: a single traversal, which looks for the second value in the rest as soon as the first one is found.

!To reread the night before

The most frequent traps

Phrases and definitions
  • let rec forgotten: Error: Unbound value fact. If an older fact exists, the definition goes through and calls the old one.
  • ;; forgotten: the next phrase sticks to this one.
  • n * fact n-1 reads n * (fact n) - 1: the definition is accepted, the call never stops (Stack overflow).
  • succ -1 is a subtraction: write succ (-1).
Pattern matching
  • A name in a pattern is a new variable: | y -> matches everything, even if a y already exists. To compare: | z when z = y ->.
  • A match inside a match swallows the following cases: put it in brackets.
  • Cases all guarded by when: Caml does not see that they cover everything (Warning 8). End with | _ ->.
  • [e; lst] has two elements; e :: lst has at least one.
Types
  • :: adds one element in front of a list; [1; 2] :: [3] is rejected.
  • Both branches of an if have the same type; no if without else.
  • not a = b reads (not a) = b: write a <> b.
  • = and <>, never == nor !=.
  • Caml writes 4., not 4.0.
On your script
  • The wrong exception, or an exception tested after a base case.
  • abs, max, List.length: forbidden. x - y <= 1 && y - x <= 1 replaces abs (x - y) <= 1.
  • An accumulator that reverses the order of the result (2 points lost out of 8 in 2023).
  • A constant 0 for any element: the type becomes int and the examples on char fail.
# let fact n = if n = 0 then 1 else n * fact (n-1) ;;
Error: Unbound value fact
Hint: If this is a recursive definition,
you should add the 'rec' keyword on line 1

Mistakes in the official documents: do not copy them
  • Invalid_arg "negative rank" in the examples of 2018, 2019, 2020 and of lists tutorial 3.3: the constructor is Invalid_argument.
  • October 2019 answer key: Failure "negative rank" instead of Invalid_argument. 2020 answer key: search v1 v2 l instead of search_both list a b.
  • 2018, exercise 5: the printed code of encode (encode-rec) does not compile; the answer key evaluates another version. 2021: the message "remove_internal: …" is a typo.
  • - : float = 4.0 (April 2019 answer key, lists tutorial 1.6): Caml writes 4.. Memo, p. 5: (2, "two") for a float * string, Caml writes (2., "two").
  • Moodle page on recursion: mult_rec (x, y-1) does not compile, it should be mult_rec (y-1).
