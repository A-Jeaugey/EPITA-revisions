1Méthode 1

Écrire une fonction récursive

C’est la méthode de la page Moodle « Conseils pour la récursivité », dans son ordre. Elle sert pour presque toutes les fonctions à écrire : dans les 9 sujets, il y a une fonction récursive sur une liste, avec une exception exigée par l’énoncé.

  1. C’est quoi la question ? La spécification. Ce que la fonction calcule, ses paramètres (leur sens, leur type, leur ordre), les conditions d’appel et l’exception quand elles ne sont pas remplies. Les exemples du sujet la donnent : lis-les d’abord. Écris le type attendu, ce sera ta réponse de Caml.

  2. Le principe. « J’ai déjà vu quelque chose de ressemblant » : un parcours complet (compter), un parcours partiel (chercher), une liste à construire, un rang à faire descendre. Il donne la structure et les cas.

  3. La fonction à trous. Écris la structure avec ses cas, puis la réponse de chacun : les cas d’arrêt (la réponse est connue sans nouvel appel), puis les cas récursifs (le même problème, plus petit). Vérifie que chaque appel se rapproche d’un cas d’arrêt.

  4. Les cas particuliers. Le cas général écrit, essaie les cas limites : liste vide, un seul élément, paramètre hors limites, élément absent. Ajoute les cas qui manquent.

  5. Le chapeau, si besoin. Une fonction « chapeau », non récursive, vérifie les paramètres une seule fois puis appelle la fonction récursive locale. Elle sert aussi à donner à celle-ci des paramètres supplémentaires (compteur, accumulateur) avec leur valeur de départ.

Exemple TD listes · ex. 1.4 Le i-ème élément d’une liste. Même schéma que remove_nth (octobre 2019) et insert_nth (2018 et 2020).

1. Spécification :

nth i lst retourne l’élément de rang i de la liste lst (le premier est au rang 1). Elle déclenche Invalid_argument si i ≤ 0, Failure si la liste a moins de i éléments. Type attendu : int -> 'a list -> 'a.

2. Principe :

Un parcours partiel, comme une recherche, avec un rang qui descend : à chaque élément passé, on cherche le rang i - 1 dans la suite. Au rang 1, c’est la tête.

3. Fonction à trous (elle ne compile pas encore) : 
let rec get i = function
    [] -> (* plus d'élément : la liste est trop courte *)
  | e :: l ->
      if i = 1 then
        (* la réponse est la tête *)
      else
        (* même problème, plus petit : rang i - 1 dans l *)
4. Cas particuliers : sans test, un rang ≤ 0 ne vaut jamais 1, et la récursion va jusqu’à la liste vide : 
# let rec get i = function
      [] -> failwith "nth: list too short"
    | e :: l ->
        if i = 1 then
          e
        else
          get (i-1) l ;;
val get : int -> 'a list -> 'a = <fun>
# get 0 ['a'; 'b'] ;;
Exception: Failure "nth: list too short".
5. Le chapeau teste le rang une fois, puis appelle la fonction récursive : 
# let nth i lst =
    if i <= 0 then
      invalid_arg "nth: i <= 0"
    else
      let rec get i = function
          [] -> failwith "nth: list too short"
        | e :: l ->
            if i = 1 then
              e
            else
              get (i-1) l
      in
        get i lst ;;
val nth : int -> 'a list -> 'a = <fun>
# nth 3 ['a'; 'b'; 'c'; 'd'] ;;
- : char = 'c'
# nth 5 ['a'; 'b'] ;;
Exception: Failure "nth: list too short".
# nth 0 ['a'; 'b'] ;;
Exception: Invalid_argument "nth: i <= 0".
# nth (-1) [] ;;
Exception: Invalid_argument "nth: i <= 0".

La fonction récursive ne voit que des rangs ≥ 1 ; elle descend jusqu’à 1 (trouvé) ou jusqu’à [] (trop courte) : chaque appel se rapproche d’un cas d’arrêt. Le test de i n’est fait qu’une fois, même sur une longue liste, et nth (-1) [] déclenche bien Invalid_argument.

La page Moodle

Elle montre le chapeau sur fact, puis sur multiply x y. Ce second exemple contient une coquille : mult_rec (x, y-1) alors que mult_rec prend un seul entier. Tel quel, il ne compile pas ; il faut mult_rec (y-1).

Le cours : cas d’arrêt et cas récursif, fonctions chapeau, paramètres supplémentaires. À faire : TD listes 1.4, remove_nth (2019), insert_mult (2023).

2Méthode 2

Traiter une ou deux listes

La page Moodle « Conseils pour les listes » part d’une question : combien de listes faut-il parcourir, et la tête suffit-elle ? La réponse donne les cas du filtrage. Ajoute ensuite les cas dus aux autres paramètres (valeur cherchée, liste triée, propriété).

SituationLes casDans les sujets
Une liste[] · e :: lstremove_x (2023), insert_post (2022)
La tête ne suffit pas : comparer deux voisins[] · [e] · e1 :: e2 :: lstles dominos (2019), le Mystery d’avril 2019
Des couples[] · (a, b) :: lstassoc (2017, avril 2019)
Une liste de listes[] · l :: otherscheck_list (2024)
Deux listes parcourues ensemble([], []) · (lst, []) · ([], lst) · (e1 :: l1, e2 :: l2)for_all2 (2017, 2019), is_image (2018)
Deux listes, une seule avance à chaque appelles mêmes cas, et deux appels récursifs selon la liste qui avanceshared (TD listes 4.2), alternate_list (2021)

  1. La liste vide est un cas d’arrêt. Décide ce qu’elle rend d’après l’énoncé : une valeur (0, true, []) ou une exception.

  2. Parcours complet ou partiel ? Si toute la liste doit être vue (compter, recopier), tous les cas non vides sont récursifs. Sinon, il faut au moins un autre cas d’arrêt : trouvé, propriété fausse, valeur dépassée dans une liste triée.

  3. Récursion pure d’abord. Exprime le résultat pour e :: lst à partir du résultat pour lst. Le Moodle prévient, à propos de l’accumulateur : « la plupart du temps, cette méthode n’est pas nécessaire. Elle ne fait que compliquer les choses et vous risquez d’obtenir un résultat différent de celui demandé. » En 2023, une copie a perdu 2 points sur 8 parce que son accumulateur avait renversé l’ordre des sous-listes.

  4. Deux listes ensemble : regroupe-les dans un couple avec match (l1, l2) with, et vérifie que les quatre cas sont couverts. Un cas fourre-tout | _ -> en dernier regroupe les longueurs différentes.

La tête ne suffit pas octobre 2019 · ex. 2 · 4 points Une chaîne de dominos est valide si les parties voisines ont le même nombre de points. Trois cas, et l’appel récursif repart de (c, d) :: l, pas de l, sinon un domino est perdu (corrigé officiel) :

# let rec is_dominoes = function
      [] | [_] -> true
    | (_, b) :: (c, d) :: l -> b = c && is_dominoes ((c, d) :: l) ;;
val is_dominoes : ('a * 'a) list -> bool = <fun>
# is_dominoes [(1, 2); (2, 3); (3, 3); (3, 6)] ;;
- : bool = true
# is_dominoes [(2, 3); (2, 4); (1, 4)] ;;
- : bool = false
# is_dominoes [] ;;
- : bool = true

Deux listes, une seule avance TD listes · ex. 4.2 Les éléments communs à deux listes croissantes. Si les têtes diffèrent, seule la liste qui a la plus petite avance : on rappelle avec l’autre liste entière (l1 ou l2), pour ne pas perdre sa tête.

# let rec shared l1 l2 = match (l1, l2) with
      ([], _) | (_, []) -> []
    | (e1 :: r1, e2 :: r2) ->
        if e1 = e2 then
          e1 :: shared r1 r2
        else
          if e1 < e2 then
            shared r1 l2
          else
            shared l1 r2 ;;
val shared : 'a list -> 'a list -> 'a list = <fun>
# shared [1; 3; 6; 6; 8; 9] [2; 5; 6; 6; 8; 9] ;;
- : int list = [6; 6; 8; 9]
Pièges
  • [e; lst] est une liste de deux éléments, pas « un élément suivi d’une liste » : le cas général s’écrit e :: lst.
  • Un cas oublié ne se voit pas à l’écriture : Caml affiche Warning 8 sous ta définition, puis Match_failure à l’exécution. Dans ta réponse de Caml, un avertissement signale un oubli.

Le cours : filtrer une liste, deux listes, deux éléments, couples, accumulateur. À faire : les dominos, shared, listes alternées.

3Méthode 3

Choisir failwith ou invalid_arg, et où placer le test

Les neuf sujets exigent une exception. Ce sont les deux seules fonctions prédéfinies permises, et l’énoncé dit toujours laquelle il attend : ses exemples montrent le constructeur et le message.

invalid_arg "…"failwith "…"
Réponse de CamlException: Invalid_argument "…".Exception: Failure "…".
QuandUn paramètre ne respecte pas les conditions d’appel : rang ≤ 0, k < 0, i > j, liste vide « initialement ».Le calcul échoue en route : liste trop courte, clé absente, aucun élément après lequel insérer.
OùDans la fonction chapeau, avant tout parcours, une seule fois.Là où l’échec se voit, souvent le cas [] de la fonction récursive.
Sujets9 sur 97 sur 9 (pas en 2023 ni en 2024)

  1. Lis les exemples : recopie le constructeur et le message. Les sujets de 2018 à 2020 et le TD listes écrivent Invalid_arg "negative rank" : c’est une coquille, le constructeur est Invalid_argument, et on le déclenche avec invalid_arg.

  2. Un paramètre invalide se teste dans le chapeau. Testé dans la fonction récursive, il serait refait à chaque appel, et un cas d’arrêt rencontré avant lui donnerait la mauvaise exception.

  3. Un échec en route se déclenche dans le cas qui le révèle : la fin de liste atteinte trop tôt, une clé dépassée dans une liste triée.

  4. Respecte l’ordre que fixe l’énoncé. for_all2 (2017, 2019) : « Si elle trouve une paire telle que p ai bi est faux, elle retourne faux. Sinon, elle déclenche une exception » : la paire fausse passe avant l’exception, donc l’exception vient en fin de parcours, pas dans un test de longueur préalable.

Les deux fonctions ont le type string -> 'a : une exception prend le type de n’importe quelle branche. C’est ce qui permet if i < 1 then invalid_arg "…" else ….

# invalid_arg ;;
- : string -> 'a = <fun>
# failwith ;;
- : string -> 'a = <fun>

Le test au mauvais endroit octobre 2019 · ex. 3 · 5 points remove_nth i list supprime l’élément de rang i ; Invalid_argument si i est négatif ou nul, Failure si la liste est trop courte. Avec le test de i dans la fonction récursive, la liste vide est filtrée avant lui :

# let rec remove_nth i = function
      [] -> failwith "out of bound"
    | e :: q ->
        if i <= 0 then
          invalid_arg "negative rank"
        else
          if i = 1 then
            q
          else
            e :: remove_nth (i-1) q ;;
val remove_nth : int -> 'a list -> 'a list = <fun>
# remove_nth (-2) [1; 2; 3] ;;
Exception: Invalid_argument "negative rank".
# remove_nth (-2) [] ;;
Exception: Failure "out of bound".
Fonction Caml : 
# let remove_nth i list =
    if i < 1 then
      invalid_arg "negative rank"
    else
      let rec del i = function
          [] -> failwith "out of bound"
        | e :: q ->
            if i = 1 then
              q
            else
              e :: del (i-1) q
      in
        del i list ;;
val remove_nth : int -> 'a list -> 'a list = <fun>
# remove_nth 5 [1; 2; 3; 4; 5; 6; 7; 8; 9] ;;
- : int list = [1; 2; 3; 4; 6; 7; 8; 9]
# remove_nth 10 [1; 2; 3; 4; 5; 6; 7; 8; 9] ;;
Exception: Failure "out of bound".
# remove_nth (-2) [] ;;
Exception: Invalid_argument "negative rank".

« Initialement vide » octobre 2022 · ex. 3 Quand la liste vide de départ est un paramètre invalide, le chapeau la filtre avec function, et la fonction récursive reçoit le premier élément comme maximum de départ (corrigé officiel) :

Le corrigé d’octobre 2019 écrit failwith "negative rank" dans ses trois versions : il déclenche Failure, alors que l’énoncé demande Invalid_argument. Suis l’énoncé.

Le cours : failwith et invalid_arg, fonctions chapeau. À faire : insert_nth, remove_interval (2021), pos_max (2022).

4Méthode 4

Écrire la réponse de Caml d’une phrase

Sous chaque fonction de ta copie, et pour chaque phrase d’un Mystery. Depuis 2023, l’en-tête précise qu’elle « fait partie de la note ». Elle a une forme fixe, qui dépend de la phrase :

PhraseRéponse de Caml
Définition d’une valeur : let a = 1 + 2 ;;val a : int = 3
Définition d’une fonctionval nth : int -> 'a list -> 'a = <fun>
Expression : nth 3 ['a'; 'b'; 'c'] ;;- : char = 'c'
Exception déclenchéeException: Failure "nth: list too short".
Phrase refusée (type, nom inconnu) : rien n’est définiError: Unbound value fact
Filtrage incomplet : l’avertissement, puis la définitionWarning 8 [partial-match]: this pattern-matching is not exhaustive.

  1. Un type par paramètre, dans l’ordre, séparés par ->, puis le type du résultat : insert_mult n x lst donne int -> 'a -> 'a list -> 'a list.

  2. Un paramètre fonction s’écrit entre parenthèses, avec son propre type : ('a -> bool) pour un prédicat, ('a -> 'a -> bool) pour un ordre.

  3. 'a quand rien n’impose le type. Comparer (=, <) ou déplacer des éléments ne fixe pas leur type ; +, mod ou une constante 0 donnent int, +. donne float. Deux types qui n’ont rien à voir : 'a et 'b.

  4. Les types composés : int list, (int * 'a) list pour une liste de couples, 'a list list pour une liste de listes.

  5. La valeur comme Caml l’écrit : 4. et pas 4.0, les chaînes entre guillemets, les caractères entre apostrophes, [1; 2] avec des points-virgules ; une fonction vaut <fun>.

À toi. Tape la réponse de Caml à chaque phrase, puis compare. Un champ vide dévoile simplement la réponse.

# let rec how_many f = function
      [] -> 0
    | e :: l -> (if f e then 1 else 0) + how_many f l ;;
val how_many : ('a -> bool) -> 'a list -> int = <fun>
# how_many (function x -> x > 0) [-1; 2; 0; 5] ;;
- : int = 2
# let count_even = how_many (function x -> x mod 2 = 0) ;;
val count_even : int list -> int = <fun>
# let first = function
      [] -> failwith "first: empty list"
    | (a, b) :: _ -> a ;;
val first : ('a * 'b) list -> 'a = <fun>
# first [(3.5, "x"); (1., "y")] ;;
- : float = 3.5
# first [] ;;
Exception: Failure "first: empty list".
# [[1; 2]; []] ;;
- : int list list = [[1; 2]; []]
# [] ;;
- : 'a list = []
# 4.0 ;;
- : float = 4.
Pièges
  • count_even est définie sans écrire sa liste : c’est une application partielle, et son type est ce qui reste, int list -> int.
  • first ne fait rien de b : son type reste libre, 'b.
  • Une exception n’a pas de type dans la réponse : Exception: … et un point final.
  • Un type long, Caml le coupe sur deux lignes (… list = puis <fun>) ; sur la copie, une ligne suffit.

Le cours : lire une réponse de Caml, le type d’une fonction, application partielle. À faire : séminaire 1.2, 2.1, TD ordre supérieur 1.1.

5Méthode 5

Lire un Mystery : la trace, puis ce qu’il calcule

7 sujets sur 9, de 2 à 4 points : une fonction au nom muet, dont il faut donner le type (2022, 2024), les résultats de quelques phrases, parfois ce qu’elle calcule (avril 2019), une phrase à déclarer « Erreur » (2021) ou l’appel qui produit un résultat donné (2022).

  1. Le type d’abord, en lisant le code : les motifs (liste, couple), les opérations (* impose int), ce que rend chaque cas. Si un filtrage oublie un cas, Caml affiche Warning 8 avant le val ; le corrigé d’avril 2019 accepte une réponse « hors warning éventuels ».

  2. Déroule le plus petit exemple, appel par appel, en écrivant ce que chaque appel attend. Repère les noms masqués : une variable du même nom dans une fonction locale cache celle du dessus.

  3. Fais les autres phrases, en commençant par les cas limites (liste vide, un élément) : ils tombent souvent sur un cas d’arrêt.

  4. Dis en une phrase ce que calcule la fonction, et vérifie-la sur un exemple que tu n’as pas déroulé.

  5. « Erreur » ? Vérifie le type de chaque argument : en 2021, une fonction à deux paramètres est passée là où un prédicat à un paramètre est attendu.

Exemple novembre 2020 · ex. 5 · 2 points « Soit la fonction go définie ci-dessous. Donner les résultats des évaluations successives des phrases suivantes. »

let go = function
    [] -> []
  | e :: list ->
    let rec what x = function
          [] -> []
       | e :: list -> ( e * x ) ::( what e list )
    in
    what e list ;;

Le type. go filtre une liste ; e * x impose des entiers ; chaque cas rend une liste d’entiers. Réponse : val go : int list -> int list = <fun>. Dans what, le e et le list du motif masquent ceux de go.

La trace de go [1; 2; 3; 4; 5] : go appelle what avec la tête et la suite. Chaque appel de what attend le résultat du suivant pour mettre un produit devant.

# go [1; 1; 1; 1; 1] ;;
- : int list = [1; 1; 1; 1]
# go [42] ;;
- : int list = []
# go [1; 2; 3; 4; 5] ;;
- : int list = [2; 6; 12; 20]
# go [2; 21; 2; 21; 2; 21] ;;
- : int list = [42; 42; 42; 42; 42]
Ce que calcule go :

La liste des produits de deux éléments voisins : [a1 * a2; a2 * a3; …], un élément de moins que la liste de départ. D’où [] pour une liste d’un seul élément.

Le cours : la pile des appels. À faire, du plus simple au plus long : go (2020), sous-liste (2019), avril 2019, 2024, 2021, 2022.

6Méthode 6

Utiliser une fonction d’ordre supérieur

7 sujets sur 9 font écrire une fonction qui reçoit une fonction en paramètre, et 7 sur 9 enchaînent avec « Utiliser la fonction précédente pour définir… ». Les fonctions sont toujours écrites à la main : ni List.map ni List.filter.

  1. Repère le paramètre fonction : « une fonction booléenne », « un prédicat », « une fonction de comparaison », « une fonction à deux paramètres ». Dans le type, il est entre parenthèses.

  2. Appelle-la comme une fonction, avec ses arguments : f e, p e1 e2, order x e. C’est déjà un booléen : if f e then, pas if f e = true then.

  3. Passe-la à chaque appel récursif : how_many f l, pas how_many l.

  4. Pour l’utiliser, donne-lui une fonction anonyme (function x -> x mod n = 0), une fonction locale nommée, ou un opérateur entre parenthèses comme (=). La question 2 se traite même si la 1 ne l’est pas : en 2022, « qu’elle soit écrite ou pas ».

  5. Garde l’ordre des paramètres de l’énoncé : la comparaison est le dernier paramètre de insert x list comp (avril 2019), le deuxième de insert_x x order lst (2024).

Exemple octobre 2018 · ex. 3 · 4 points how_many f l compte les éléments de l qui vérifient f ; puis l’utiliser pour count_multiples n l, le nombre de multiples de n dans l.

Fonction Caml : 
# let rec how_many f = function
      [] -> 0
    | e :: l ->
        if f e then
          1 + how_many f l
        else
          how_many f l ;;
val how_many : ('a -> bool) -> 'a list -> int = <fun>
# let count_multiples n l = how_many (function x -> x mod n = 0) l ;;
val count_multiples : int -> int list -> int = <fun>
# count_multiples 3 [1; 3; 6; 7; 9; 0] ;;
- : int = 4

Le prédicat utilise n, le paramètre de count_multiples : c’est pour cela qu’il est écrit à l’intérieur. Le corrigé officiel donne aussi la forme sans l, une application partielle, de même type :

# let count_multiples n = how_many (function x -> x mod n = 0) ;;
val count_multiples : int -> int list -> int = <fun>
Deux erreurs que Caml refuse 
# let rec bad f = function
      [] -> 0
    | e :: l -> if f e = true then 1 + bad l else bad f l ;;
Error: This expression has type 'a list
       but an expression was expected of type 'a -> bool
# how_many (=) [1; 2] ;;
Error: This expression has type 'a -> 'a -> bool
       but an expression was expected of type 'a -> bool
       Type 'a -> bool is not compatible with type bool
  • bad l : le paramètre fonction a été oublié dans l’appel récursif.
  • (=) prend deux paramètres, how_many attend un prédicat à un seul : c’est l’« Erreur » du Mystery de 2021.

Le cours : une fonction en paramètre, un ordre en paramètre, for_all2. À faire : how_many, for_all2 et almost, tri par insertion (2024), less2 et common.

7Méthode 7

Optimiser : ne pas répéter un calcul, s’arrêter tôt

La fiche de cours demande d’« éviter les calculs inutiles, ne pas répéter des calculs, arrêter dès qu’une réponse est donnée ». Une fonction juste mais lente perd des points : l’arrêt anticipé est attendu dans 8 sujets sur 9.

  1. Ne refais pas un appel récursif : si son résultat sert deux fois, nomme-le avec let … in.

  2. Arrête-toi dès que la réponse est connue : élément trouvé, propriété fausse, valeur dépassée dans une liste triée. && et || n’évaluent pas leur second membre quand le premier suffit.

  3. Teste les paramètres une seule fois, dans le chapeau (méthode 3).

  4. Ajoute en tête avec ::. l1 @ l2 recopie toute l1 : un miroir écrit avec @ recopie n(n − 1)/2 cellules, soit près de 200 millions pour 20 000 éléments, contre 20 000 avec un accumulateur (TD listes 3.5).

Un appel refait TD listes · ex. 1.5 Le maximum d’une liste. Quand le test est faux, cette version recalcule maximum lst en entier :

# let rec maximum = function
      [] -> failwith "maximum: empty list"
    | [e] -> e
    | e :: lst ->
        if e > maximum lst then
          e
        else
          maximum lst ;;
val maximum : 'a list -> 'a = <fun>
# maximum [1; 2; 3; 4] ;;
- : int = 4

Sur une liste croissante, chaque appel en lance deux : 7 appels pour 3 éléments, 15 pour 4, 1 048 575 pour [1; …; 20]. Avec let … in, un appel par élément :

# let rec maximum = function
      [] -> failwith "maximum: empty list"
    | [e] -> e
    | e :: lst ->
        let m = maximum lst in
          if e > m then
            e
          else
            m ;;
val maximum : 'a list -> 'a = <fun>

S’arrêter tôt novembre 2020 · ex. 2 Dans une liste croissante, on ne cherche plus x après un élément plus grand. Et ||, && s’arrêtent au premier membre quand il suffit :

# let rec delete x = function
      [] -> []
    | e :: l ->
        if e > x then
          e :: l
        else
          if e = x then
            l
          else

Les pièges les plus fréquents

Phrases et définitions
  • let rec oublié : Error: Unbound value fact. Si un ancien fact existe, la définition passe et appelle l’ancien.
  • ;; oublié : la phrase suivante se colle à celle-ci.
  • n * fact n-1 se lit n * (fact n) - 1 : la définition passe, l’appel ne s’arrête jamais (Stack overflow).
  • succ -1 est une soustraction : écris succ (-1).
Filtrage
  • Un identifiant dans un motif est une nouvelle variable : | y -> filtre tout, même si un y existe déjà. Pour comparer : | z when z = y ->.
  • Un match dans un match avale les cas suivants : mets-le entre parenthèses.
  • Des cas tous gardés par when : Caml ne voit pas qu’ils couvrent tout (Warning 8). Termine par | _ ->.
  • [e; lst] a deux éléments ; e :: lst en a au moins un.
Types
  • :: ajoute un élément devant une liste ; [1; 2] :: [3] est refusé.
  • Les deux branches d’un if ont le même type ; pas de if sans else.
  • not a = b se lit (not a) = b : écris a <> b.
  • = et <>, jamais == ni !=.
  • Caml écrit 4., pas 4.0.
Sur la copie
  • La mauvaise exception, ou une exception testée après un cas d’arrêt.
  • abs, max, List.length : interdites. x - y <= 1 && y - x <= 1 remplace abs (x - y) <= 1.
  • Un accumulateur qui renverse l’ordre du résultat (2 points perdus sur 8 en 2023).
  • Une constante 0 pour un élément quelconque : le type devient int et les exemples en char échouent.
