Partie 1

Une fonction est une valeur

Au chapitre 1, une fonction se définissait avec let f x = …. C’est en fait une valeur, comme 3 ou "abc" : elle a un type, et elle peut s’écrire sans nom, avec function. On parle alors de fonction anonyme.

# function x -> x + 1 ;;
- : int -> int = <fun>
# (function x -> x + 1) 5 ;;
- : int = 6
# let succ = function x -> x + 1 ;;
val succ : int -> int = <fun>
# succ ;;
- : int -> int = <fun>

La première phrase est une expression : Caml répond par -, son type int -> int et <fun>. La deuxième l’applique à 5 sans la nommer. La troisième la nomme : c’est exactement la définition let succ x = x + 1.

Deux écritures d’une même fonction
Paramètres à gauche du =Avec functionRéponse de Caml
let succ x = x + 1let succ = function x -> x + 1val succ : int -> int = <fun>
let times x y = x * ylet times = function x -> function y -> x * yval times : int -> int -> int = <fun>

Comme toute valeur, une fonction se range dans une liste ou dans un couple. Les parenthèses du type montrent où se trouve la fonction :

# let ops = [succ; (function x -> 2 * x); (function x -> x * x)] ;;
val ops : (int -> int) list = [<fun>; <fun>; <fun>]
# (succ, "succ") ;;
- : (int -> int) * string = (<fun>, "succ")
# function x -> x ;;
- : 'a -> 'a = <fun>

(int -> int) list est une liste de fonctions de int dans int. La dernière fonction rend son paramètre sans s’en servir : il peut être de n’importe quel type, d’où 'a -> 'a.

Les opérateurs sont aussi des fonctions, à deux paramètres. Entre parenthèses, ils s’emploient comme une fonction ordinaire :

# (+) ;;
- : int -> int -> int = <fun>
# (+) 2 3 ;;
- : int = 5
# (<) ;;
- : 'a -> 'a -> bool = <fun>

(<) fait le même calcul que function x -> function y -> x < y. Le corrigé officiel d’octobre 2022 passe ainsi (=) à une fonction (partie 7). Pour la multiplication, écris ( * ) avec des espaces : (* ouvre un commentaire.

À retenir
  • function x -> e est une fonction sans nom, à un seul paramètre (chapitre 1, partie 7). Pour deux paramètres : function x -> function y -> e.
  • Une fonction a un type et vaut <fun>. Elle se nomme, se range dans une liste, se passe en paramètre (partie 3) et se rend en résultat (partie 2).
  • Les sujets écrivent function, jamais le raccourci fun.
Piège : une fonction anonyme va jusqu’au bout de la phrase 
# function x -> x + 1 5 ;;
Error: This expression has type int
       This is not a function; it cannot be applied.
# (function x -> x + 1) 5 ;;
- : int = 6

Tout ce qui suit la flèche fait partie de la fonction : Caml lit x + (1 5) et refuse d’appliquer l’entier 1 à 5. Mets une fonction anonyme entre parenthèses dès qu’elle n’est pas seule : pour l’appliquer, comme pour la passer en argument.

Piège : deux fonctions ne se comparent pas 
# succ = (function x -> x + 1) ;;
Exception: Invalid_argument "compare: functional value".
# succ = succ ;;
Exception: Invalid_argument "compare: functional value".

La phrase est bien typée, mais = ne sait pas comparer deux fonctions, même identiques : il déclenche une exception (séminaire, exercice 1.2). Une liste ou un couple qui contient une fonction ne se compare pas non plus.

Au partiel
  • Les exemples de cinq sujets passent une fonction anonyme en argument : is_image (function x -> x * 2) [1; 2; 3; 4; 5] [2; 4; 6; 8; 10] (octobre 2018), insert 12 [1;5;9;13;15;28] (function x -> function y -> x <= y) (avril 2019), insert_post 42 (function y -> y mod 2 = 0) [5; -7; 2; 4; 1] (octobre 2022), split (function x -> x = 3) [1; 2; 3; 4; 5] (octobre 2023), insert_x 7 (function x -> function y -> x < y) [1; 3; 5; 9] (octobre 2024).
  • Toujours entre parenthèses, toujours avec function. Lis-les comme des valeurs : la fonction à écrire les reçoit en paramètre.

Partie 2

Des fonctions qui rendent des fonctions

Une fonction à deux paramètres est en réalité une fonction à un paramètre qui rend une fonction. L’écriture avec function le montre : times prend x et rend function y -> x * y.

# let times = function x -> function y -> x * y ;;
val times : int -> int -> int = <fun>
# times 2 ;;
- : int -> int = <fun>
# let double = times 2 ;;
val double : int -> int = <fun>
# double 15 ;;
- : int = 30

Le type int -> int -> int se lit int -> (int -> int) : la flèche se groupe à droite. Donner moins d’arguments que de paramètres s’appelle une application partielle : times 2 est la fonction qui attend encore y, et double lui donne un nom. Inversement, times 2 15 se lit (times 2) 15, comme average 2 3 au chapitre 1.

Que les paramètres soient écrits à gauche du = ou après function, c’est la même fonction :

# let add n x = x + n ;;
val add : int -> int -> int = <fun>
# let add n = function x -> x + n ;;
val add : int -> int -> int = <fun>
# let add = function n -> function x -> x + n ;;
val add : int -> int -> int = <fun>

Une fonction peut aussi choisir la fonction qu’elle rend séminaire · ex. 3.8 Ici, d’après le nom d’un opérateur logique. Devine chaque réponse avant de comparer.

# let f = function
      "and" -> (function (v1, v2) -> v1 && v2)
    | "or" -> (function (v1, v2) -> v1 || v2)
    | "xor" -> (function (v1, v2) -> v1 <> v2)
    | "imply" -> (function (v1, v2) -> not v1 || v2)
    | _ -> failwith "unknown operator" ;;
val f : string -> bool * bool -> bool = <fun>
# f "xor" ;;
- : bool * bool -> bool = <fun>
# f "xor" (true, false) ;;
- : bool = true
# f "nand" (true, false) ;;
Exception: Failure "unknown operator".
# let x = 5 in function a -> function b ->
    let y = 2 in float_of_int (a * x) > (float_of_int y +. b) ;;
- : int -> float -> bool = <fun>
Pourquoi string -> bool * bool -> bool ?

f prend une chaîne et rend une fonction de type bool * bool -> bool : sa réponse se lit string -> (bool * bool -> bool). Caml n’écrit pas ces parenthèses, puisque la flèche se groupe à droite. Il les écrit en revanche quand c’est le paramètre qui est une fonction (partie 3) : (int -> int) -> int n’est pas int -> int -> int.

La dernière phrase est une expression (-) dont la valeur est une fonction : elle a gardé x, qui vaut 5, comme toute fonction garde les valeurs de sa définition (chapitre 1, partie 3).

Piège : on ne fixe que les premiers paramètres 
# double 2 3 ;;
Error: This function has type int -> int
       It is applied to too many arguments; maybe you forgot a `;'.
# let multiple n x = x mod n = 0 ;;
val multiple : int -> int -> bool = <fun>
# let multiple_of_3 = multiple 3 ;;
val multiple_of_3 : int -> bool = <fun>
# let is_multiple x n = x mod n = 0 ;;
val is_multiple : int -> int -> bool = <fun>
# let multiple_of_3 = function x -> is_multiple x 3 ;;
val multiple_of_3 : int -> bool = <fun>

double n’attend plus qu’un argument. Une application partielle fixe toujours les premiers paramètres : avec multiple n x, multiple 3 est le prédicat « multiple de 3 ». Avec l’ordre inverse, is_multiple x n, il faut une fonction anonyme. Garde l’ordre des paramètres de l’énoncé, et passe par function quand l’application partielle ne suffit pas.

  • Le Mystery de novembre 2021 (4 points) contient une phrase à déclarer « Erreur » : une fonction à deux paramètres passée là où un prédicat à un paramètre est attendu (partie 5). Une fonction a autant de paramètres que son type a de flèches hors parenthèses.

Partie 3

Une fonction en paramètre

Une fonction peut recevoir une autre fonction en paramètre : c’est une fonction d’ordre supérieur (higher-order function, ou functional, dans le titre du TD). Les deux dernières fonctions de l’exercice 1.1 du TD, avec double écrite directement (dans le TD, elle vaut times 2, la même fonction) :

# let succ x = x + 1 and double x = 2 * x ;;
val succ : int -> int = <fun>
val double : int -> int = <fun>
# let double_fun f x = double (f x) ;;
val double_fun : ('a -> int) -> 'a -> int = <fun>
# double_fun succ 2 ;;
- : int = 6
# double_fun (function x -> x + 1) ;;
- : int -> int = <fun>
# let double_succ = double_fun succ ;;
val double_succ : int -> int = <fun>
# double_succ 2 ;;
- : int = 6

Comment Caml trouve ('a -> int) -> 'a -> int :

  1. f x : f est appliquée à x, c’est donc une fonction, et son paramètre a le type de x. Rien d’autre ne contraint x : ce type est 'a.

  2. double (f x) : double attend un int, donc f rend un int. Le type de f est 'a -> int.

  3. Le résultat est celui de double, un int. Les parenthèses de ('a -> int) disent que le premier paramètre est la fonction tout entière.

Généraliser un calcul TD · ex. 1.2 Les deux premières sommes du TD, Σ i et Σ i² pour i de 0 à n, ne diffèrent que par le terme ajouté :

# let rec sigma n =
    if n <= 0 then
      0
    else
      n + sigma (n-1) ;;
val sigma : int -> int = <fun>
# let rec sigma_squares n =
    if n <= 0 then
      0
    else
      n * n + sigma_squares (n-1) ;;
val sigma_squares : int -> int = <fun>
# sigma 10 ;;
- : int = 55
# sigma_squares 3 ;;
- : int = 14

Ce terme devient un paramètre : une fonction f, appliquée à chaque i de 0 à n. Une seule fonction calcule alors toutes ces sommes.

# let rec sum_f f n =
    if n < 0 then
      0
    else
      f n + sum_f f (n-1) ;;
val sum_f : (int -> int) -> int -> int = <fun>
# sum_f (function i -> i) 10 ;;
- : int = 55
# sum_f (function i -> i * i) 3 ;;
- : int = 14
# sum_f (function i -> 1) 4 ;;
- : int = 5
# let sigma2 = sum_f (function i -> i * i) ;;
val sigma2 : int -> int = <fun>
# sigma2 3 ;;
- : int = 14

La fonction constante 1 compte les termes : de 0 à 4, il y en a 5. sigma2 est une application partielle (partie 2) : elle fixe la fonction et attend n. Lis le type de sum_f et applique ses arguments un par un :

Répéter une fonction TD · ex. 1.3, bonus Un prédicat est une « fonction booléenne représentant une propriété » (TD). loop p f x applique f à x encore et encore, jusqu’à obtenir une valeur qui vérifie p : elle rend fn(x), pour le plus petit n tel que p(fn(x)) est vrai. Puis find_power x n rend la première puissance de x supérieure ou égale à n, avec loop.

# let rec loop p f x =
    if p x then
      x
    else
      loop p f (f x) ;;
val loop : ('a -> bool) -> ('a -> 'a) -> 'a -> 'a = <fun>
# loop (function x -> x > 100) (function x -> 2 * x) 3 ;;
- : int = 192
# loop (function x -> x mod 7 = 0) (function x -> x + 1) 7 ;;
- : int = 7
# let find_power x n =
    if x < 2 then
      invalid_arg "find_power: x < 2"
    else
      loop (function p -> p >= n) (function p -> p * x) 1 ;;
val find_power : int -> int -> int = <fun>
# find_power 2 100 ;;
- : int = 128
# find_power 10 1 ;;
- : int = 1
# find_power 1 5 ;;
Exception: Invalid_argument "find_power: x < 2".

3, 6, 12, 24, 48, 96, 192 : la première valeur au-dessus de 100. Si p x est vrai dès le départ, n vaut 0 et loop rend x. Le type ('a -> bool) -> ('a -> 'a) -> 'a -> 'a a deux paramètres fonctions : le résultat de f repasse dans f et dans p, d’où le même 'a partout. find_power part de x0 = 1. Pour x = 0 ou 1, la boucle ne s’arrêterait pas (1, 1, 1…) : ce corrigé refuse donc tout x < 2 par une exception. C’est un choix, le TD ne dit rien de ce cas.

Piège : l’appel récursif repasse la fonction 
# let rec sum_f f n =
    if n < 0 then
      0
    else
      f n + sum_f (n-1) ;;
Error: This expression has type int but an expression was expected of type
         int -> int

sum_f a deux paramètres, la fonction d’abord. sum_f (n-1) lui donne un entier à la place de la fonction : Caml attend int -> int, le type de f. Écris sum_f f (n-1) : à chaque appel, la fonction suit.

Partie 4

Prédicats sur une liste : for_all, exists, find

Un prédicat rend un booléen : son type est 'a -> bool. Avec un prédicat en paramètre, une seule fonction répond à « tous les éléments vérifient-ils p ? », une autre à « au moins un ? » (TD, exercices 2.2 et 2.3).

# let rec for_all p = function
      [] -> true
    | e :: l -> p e && for_all p l ;;
val for_all : ('a -> bool) -> 'a list -> bool = <fun>
# for_all (function x -> x mod 2 = 0) [2; 4; 6] ;;
- : bool = true
# for_all (function x -> x mod 2 = 0) [2; 3; 6] ;;
- : bool = false
# for_all (function x -> x > 0) [] ;;
- : bool = true
# let rec exists p = function
      [] -> false
    | e :: l -> p e || exists p l ;;
val exists : ('a -> bool) -> 'a list -> bool = <fun>
# exists (function x -> x < 0) [3; -1; 2] ;;
- : bool = true
# exists (function x -> x < 0) [] ;;
- : bool = false
À retenir
  • for_all p [] vaut true : aucun élément ne contredit p. exists p [] vaut false : aucun élément ne le vérifie.
  • && et || s’arrêtent dès que la réponse est connue (chapitre 1, partie 1) : for_all s’arrête au premier élément faux, exists au premier vrai. La suite de la liste n’est pas parcourue.
  • Le prédicat reçoit un élément de la liste : le même 'a dans ('a -> bool) et dans 'a list.

Rendre l’élément trouvé TD · ex. 2.5 « Modifier la fonction exists pour qu’elle retourne le premier élément de la liste vérifiant le prédicat. » Si aucun ne convient, il n’y a rien à rendre : une exception. Le TD ne dit pas laquelle ; failwith convient, puisque les paramètres ne sont pas en cause.

# let rec find p = function
      [] -> failwith "find: not found"
    | e :: l ->
        if p e then
          e
        else
          find p l ;;
val find : ('a -> bool) -> 'a list -> 'a = <fun>
# find (function x -> x > 10) [3; 12; 40] ;;
- : int = 12
# find (function x -> x > 10) [3] ;;
Exception: Failure "find: not found".

Compter octobre 2018 · ex. 3 how_many f lst rend le nombre d’éléments de lst qui vérifient f, puis count_multiples n l l’utilise. Le corrigé officiel, aux espaces près :

# let rec how_many f = function
      [] -> 0
    | e :: l -> (if f e then 1 else 0) + how_many f l ;;
val how_many : ('a -> bool) -> 'a list -> int = <fun>
# let count_multiples n = how_many (function x -> x mod n = 0) ;;
val count_multiples : int -> int list -> int = <fun>
# count_multiples 3 [1; 3; 6; 7; 9; 0] ;;
- : int = 4

count_multiples n fixe le prédicat et laisse la liste : une application partielle. Le prédicat function x -> x mod n = 0 se sert de n, le paramètre de count_multiples.

Exemple de sujet octobre 2022 · ex. 2 · 3,5 points « Écrire la fonction insert_post x f lst qui prend en paramètres : un élément x, une fonction à un paramètre f renvoyant une valeur booléenne, une liste lst, et qui insère l’élément x dans la liste lst juste après le premier élément y tel que f y est true. La fonction devra déclencher une exception Failure s’il n’existe aucun élément y après lequel x peut être inséré. »

Fonction Caml : 
# let rec insert_post x f = function
      [] -> failwith "insert_post: x cannot be inserted"
    | e :: l ->
        if f e then
          e :: x :: l
        else
          e :: insert_post x f l ;;
val insert_post : 'a -> ('a -> bool) -> 'a list -> 'a list = <fun>
# insert_post 42 (function y -> y mod 2 = 0) [5; -7; 2; 4; 1] ;;
- : int list = [5; -7; 2; 42; 4; 1]
# insert_post "toto" (function y -> y = "one") ["one"; "two"; "three"; "four"] ;;
- : string list = ["one"; "toto"; "two"; "three"; "four"]
# insert_post 4.1 (function y -> y < 0.) [1.1; 2.4; 2.] ;;
Exception: Failure "insert_post: x cannot be inserted".

C’est le corrigé officiel, à la mise en page près. Le parcours s’arrête au premier élément qui vérifie f : la suite l est rendue telle quelle. Atteindre la liste vide, c’est n’avoir rien trouvé : Failure, comme dans les exemples. Le même code sert pour des entiers, des chaînes et des flottants.

Piège : l’appel récursif d’abord, et tout est parcouru 
# let rec for_all_late p = function
      [] -> true
    | e :: l -> for_all_late p l && p e ;;
val for_all_late : ('a -> bool) -> 'a list -> bool = <fun>
# for_all (function x -> 100 / x > 1) [200; 0] ;;
- : bool = false
# for_all_late (function x -> 100 / x > 1) [200; 0] ;;
Exception: Division_by_zero.

Même type, même résultat d’ordinaire, mais for_all_late descend jusqu’au bout de la liste avant de tester le premier élément. for_all voit que 100 / 200 > 1 est faux et s’arrête : elle ne divise jamais par 0. Teste la tête avant l’appel récursif : « s’arrêter dès que la réponse est connue » est l’une des règles d’optimisation du cours.

Partie 5

Construire une liste : map, filter, partition

map applique une fonction à chaque élément et construit la liste des résultats : map f [a1; …; an] vaut [f a1; …; f an] (TD, exercice 2.1).

# let rec map f = function
      [] -> []
    | e :: l -> f e :: map f l ;;
val map : ('a -> 'b) -> 'a list -> 'b list = <fun>
# map (function x -> x * x) [1; 2; 3] ;;
- : int list = [1; 4; 9]
# map (function x -> x > 0) [3; -1; 0] ;;
- : bool list = [true; false; false]

Le type ('a -> 'b) -> 'a list -> 'b list permet de changer de type : des entiers en entrée, des booléens en sortie. La liste rendue a toujours la longueur de la liste de départ. f e :: map f l se lit (f e) :: (map f l) : l’application passe avant ::.

filter p lst garde les éléments qui vérifient p, dans leur ordre (TD, exercice 2.6) :

# let rec filter p = function
      [] -> []
    | e :: l ->
        if p e then
          e :: filter p l
        else
          filter p l ;;
val filter : ('a -> bool) -> 'a list -> 'a list = <fun>
# filter (function x -> x mod 2 = 0) [1; 2; 3; 4; 5; 6] ;;
- : int list = [2; 4; 6]
# let remove_x x lst = filter (function e -> e <> x) lst ;;
val remove_x : 'a -> 'a list -> 'a list = <fun>
# remove_x 5 [5; 5; 2; 3; 5; 1] ;;
- : int list = [2; 3; 1]

remove_x x lst (octobre 2023 : supprimer toutes les occurrences de x) est un filter qui garde les éléments différents de x. Au partiel, filter n’existe pas d’avance : pour t’en servir, écris-la d’abord et dis ce qu’elle fait.

partition p lst rend un couple de listes : les éléments qui vérifient p, puis les autres (TD, exercice 2.7). Le bonus du TD demande de garder l’ordre de départ.

# let rec partition p = function
      [] -> ([], [])
    | e :: l ->
        let (yes, no) = partition p l in
          if p e then
            (e :: yes, no)
          else
            (yes, e :: no) ;;
val partition : ('a -> bool) -> 'a list -> 'a list * 'a list = <fun>
# partition (function x -> x mod 2 = 0) [1; 2; 3; 4; 5; 6] ;;
- : int list * int list = ([2; 4; 6], [1; 3; 5])
# partition (function x -> x > 0) [] ;;
- : int list * int list = ([], [])

let (yes, no) = partition p l in récupère les deux listes du reste, en un seul appel. La tête se place ensuite devant l’une des deux. Les éléments sont ajoutés au retour des appels, du dernier au premier : chacun arrive devant ceux qui le suivaient, et l’ordre est gardé.

Piège : un accumulateur renverse l’ordre 
# let partition_acc p lst =
    let rec part yes no = function
        [] -> (yes, no)
      | e :: l ->
          if p e then
            part (e :: yes) no l
          else
            part yes (e :: no) l
    in
      part [] [] lst ;;
val partition_acc : ('a -> bool) -> 'a list -> 'a list * 'a list = <fun>
# partition_acc (function x -> x mod 2 = 0) [1; 2; 3; 4; 5; 6] ;;
- : int list * int list = ([6; 4; 2], [5; 3; 1])

Même type, mais chaque élément est ajouté en tête d’un accumulateur à l’aller : le dernier vu se retrouve devant. En octobre 2023 (Split), une copie a perdu 2 points sur 8 pour des sous-listes rendues dans l’ordre inverse, comme l’énoncé le prévenait. Écris d’abord la récursion simple, sans accumulateur (page Moodle « Conseils pour les listes »).

Une fonction d’ordre en paramètre : trier

Une fonction de comparaison à deux paramètres, comme function x -> function y -> x < y, décrit un ordre. Passée en paramètre, elle rend une même fonction valable pour l’ordre croissant, l’ordre décroissant, ou tout autre ordre.

Liste triée TD · ex. 2.4 Il faut comparer deux éléments voisins : trois cas, la liste vide, un seul élément, et e1 :: e2 :: l (chapitre 3).

# let rec is_sorted order = function
      [] | [_] -> true
    | e1 :: e2 :: l -> order e1 e2 && is_sorted order (e2 :: l) ;;
val is_sorted : ('a -> 'a -> bool) -> 'a list -> bool = <fun>
# is_sorted (function x -> function y -> x < y) [1; 2; 3; 4; 5] ;;
- : bool = true
# is_sorted (function x -> function y -> x > y) [5; 4; 3; 2; 1] ;;
- : bool = true
# is_sorted (function x -> function y -> x < y) [1; 3; 2; 4; 5] ;;
- : bool = false
# is_sorted (function x -> function y -> x = y) [7; 7; 7; 7] ;;
- : bool = true
# is_sorted (<=) ["Caml"; "algo"; "rec"] ;;
- : bool = true

L’appel récursif repart de e2 :: l, pas de l : sinon la paire formée par e2 et l’élément suivant ne serait jamais comparée. Le dernier exemple passe l’opérateur (<=) directement ; les majuscules viennent avant les minuscules.

Exemple de sujet octobre 2024 · ex. 2 · 9 points « Écrire la fonction insert_x x order lst qui prend en paramètres : un élément x, une fonction à deux paramètres order retournant une valeur booléenne, une liste lst triée selon l’ordre induit par la fonction order, et qui insère l’élément x dans la liste lst triée selon l’ordre induit par la fonction order. » Puis insertion_sort order lst, qui trie la liste et « doit utiliser la fonction précédente ».

Fonction Caml : 
# let rec insert_x x order = function
      [] -> [x]
    | e :: l ->
        if order x e then
          x :: e :: l
        else
          e :: insert_x x order l ;;
val insert_x : 'a -> ('a -> 'a -> bool) -> 'a list -> 'a list = <fun>
# insert_x 7 (function x -> function y -> x < y) [1; 3; 5; 9] ;;
- : int list = [1; 3; 5; 7; 9]
# insert_x 'c' (function x -> function y -> x > y) ['e'] ;;
- : char list = ['e'; 'c']
# let rec insertion_sort order = function
      [] -> []
    | e :: l -> insert_x e order (insertion_sort order l) ;;
val insertion_sort : ('a -> 'a -> bool) -> 'a list -> 'a list = <fun>
# insertion_sort (function x -> function y -> x > y) [10; 20; 15; 5; 30] ;;
- : int list = [30; 20; 15; 10; 5]
# insertion_sort (function x -> function y -> x < y) [1.1; 3.3; 2.2; 5.5; 4.4] ;;

Le sujet n’a pas de corrigé officiel ; celui-ci donne les dix réponses des exemples. insert_x s’arrête dès que order x e est vrai : x se place devant e, et la suite l, déjà triée, ne bouge pas. insertion_sort trie le reste, puis y insère la tête. Aucune des deux ne suppose un type d’éléments : les exemples trient des entiers, des caractères et des flottants, et la liste vide donne 'a list.

Piège : l’ordre des paramètres change d’un sujet à l’autre

Deux listes : for_all2

for_all2 est le for_all de deux listes : un prédicat à deux paramètres, appliqué aux paires d’éléments de même rang. L’exercice 2.8 du TD reprend le sujet d’octobre 2019 mot pour mot :

TD · ex. 2.8 = octobre 2019, ex. 4 (5 points)

1. Écrire la fonction Caml for_all2 dont les spécifications sont les suivantes : elle prend en paramètre une fonction booléenne (un prédicat) à deux paramètres : p ainsi que deux listes : [a1; a2; …; an] et [b1; b2; …; bn]. Elle vérifie si toutes les paires ai bi vérifient le prédicat p. Si elle trouve une paire telle que p ai bi est faux, elle retourne faux. Sinon, elle déclenche une exception Invalid_argument si les deux listes sont de longueurs différentes.

2. Utiliser la fonction for_all2 pour définir une fonction qui vérifie si deux listes d’entiers sont « quasi-identiques » : la différence entre deux valeurs à la même place ne peut dépasser 1. Si aucune paire dont la différence dépasse 1 n’a été trouvée et si les deux listes sont de longueurs différentes, elle déclenche une exception.

# let rec for_all2 p l1 l2 =
    match (l1, l2) with
        ([], []) -> true
      | (e1 :: r1, e2 :: r2) -> p e1 e2 && for_all2 p r1 r2
      | _ -> invalid_arg "for_all2: different lengths" ;;
val for_all2 : ('a -> 'b -> bool) -> 'a list -> 'b list -> bool = <fun>
# let almost l1 l2 =
    let near x y = x - y <= 1 && y - x <= 1 in
      for_all2 near l1 l2 ;;
val almost : int list -> int list -> bool = <fun>
# almost [1; 2; 3; 4; 5] [1; 3; 2; 4; 6] ;;
- : bool = true
# almost [1; 2; 3; 4; 5] [1; 4; 3; 4; 5] ;;
- : bool = false
# almost [1; 2; 3] [1; 2] ;;
Exception: Invalid_argument "for_all2: different lengths".
# almost [1; 9; 3] [1; 2] ;;
- : bool = false

Les quatre cas de deux listes (chapitre 3) se réduisent ici à trois : les deux vides, les deux non vides, et _ pour les deux cas où une seule est vide. « Si elle trouve une paire fausse, elle retourne faux. Sinon… » : grâce à &&, une paire fausse arrête le parcours avant la fin de la liste la plus courte. almost [1; 9; 3] [1; 2] rend donc false, sans exception.

Pourquoi ('a -> 'b -> bool) ?

Rien n’oblige les deux listes à contenir le même type : p reçoit un élément de chacune. almost, elle, soustrait les éléments : ses deux listes sont des int list. La fonction locale near est le prédicat ; une fonction anonyme convient aussi.

Les schémas généraux : process_list et fold_left

La plupart des fonctions des parties 4 et 5 suivent le même plan : une valeur pour la liste vide, et une façon de combiner la tête avec le résultat de l’appel sur le reste. Le bonus du TD (exercice 3.1) en fait une seule fonction, process_list :

# let rec process_list f init =
    function
        [] -> init
      | e :: lst -> f e (process_list f init lst) ;;
val process_list : ('a -> 'b -> 'b) -> 'b -> 'a list -> 'b = <fun>
# let length lst = process_list (function e -> function call -> 1 + call) 0 lst ;;
val length : 'a list -> int = <fun>
# length [5; 6; 7] ;;
- : int = 3
# let sum lst = process_list (function e -> function call -> e + call) 0 lst ;;
val sum : int list -> int = <fun>
# let concatenate lst = process_list (function s -> function call -> s ^ call) "" lst ;;
val concatenate : string list -> string = <fun>
# concatenate ["Caml"; " et "; "récursivité"] ;;
- : string = "Caml et récursivité"
# let map f lst = process_list (function e -> function call -> f e :: call) [] lst ;;
val map : ('a -> 'b) -> 'a list -> 'b list = <fun>
# let for_all p lst = process_list (function e -> function call -> p e && call) true lst ;;
val for_all : ('a -> bool) -> 'a list -> bool = <fun>

process_list f init [e1; …; en] calcule f e1 (f e2 (… (f en init))). init est la valeur d’arrêt, call le résultat du traitement du reste. Chaque fonction s’écrit alors sans récursivité : il suffit de dire quoi faire de e et de call.

      lst ;;

# let g = sum_list [(function x -> x); (function x -> x *. x); (function x -> 1.)] ;;
val g : float -> float = <fun>
# g 4. ;;
- : float = 21.

g 4. vaut 4 + 4² + 1 = 21. Le type le dit : sum_list prend une liste de fonctions et rend une fonction 'a -> float.

De gauche à droite : fold_left TD · ex. 3.2 Le TD donne le type, ('a -> 'b -> 'a) -> 'a -> 'b list -> 'a, et le calcul : fold_left f a [b1; …; bn] vaut f (… (f (f a b1) b2) …) bn. Le paramètre a est un accumulateur : il reçoit le résultat partiel à chaque appel.

# let rec fold_left f a = function
      [] -> a
    | b :: l -> fold_left f (f a b) l ;;
val fold_left : ('a -> 'b -> 'a) -> 'a -> 'b list -> 'a = <fun>
# fold_left (function acc -> function x -> acc + x) 0 [1; 2; 3; 4] ;;
- : int = 10
# fold_left (function acc -> function x -> x :: acc) [] [1; 2; 3] ;;
- : int list = [3; 2; 1]
# fold_left (function a -> function b -> a - b) 10 [1; 2; 3] ;;
- : int = 4
# process_list (function a -> function b -> a - b) 10 [1; 2; 3] ;;
- : int = -8

Mêmes arguments, deux résultats différents. Déroule fold_left : l’accumulateur est le deuxième argument de chaque appel, et il vaut 10, puis 9, 7 et 4.

Piège : process_list parcourt toujours tout 
# for_all (function x -> 100 / x > 1) [200; 0] ;;
Exception: Division_by_zero.

La for_all écrite avec process_list calcule call, le traitement du reste, avant d’appliquer f : elle descend jusqu’au bout, comme for_all_late (partie 4). Pour s’arrêter tôt, écris la récursion directement. De même, fold_left avec x :: acc renverse la liste : un accumulateur construit à l’envers (partie 5).

Au partiel
  • Aucun des neuf sujets (2017 à 2024) ne demande process_list, fold_left ou un autre schéma de ce genre. Ils servent à repérer ce qui change d’un parcours à l’autre : la valeur pour [] et la façon de combiner la tête avec le reste.
  • Aucune de ces fonctions n’est fournie à l’examen : List.map, List.filter ou List.fold_left sont des fonctions prédéfinies, donc interdites. Une fonction auxiliaire que tu écris doit être documentée (ce qu’elle fait, en une phrase), et la dernière fonction écrite est celle qui répond à la question (octobre 2024).
