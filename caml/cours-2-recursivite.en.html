Part 1

Recursive reasoning: base case, recursive case

A recursive function calls itself. The idea: to solve a problem, assume you can already solve the same problem, only smaller, and use it.

Example: the factorial, n! = 1 × 2 × … × n. If you know (n − 1)!, you only have to multiply by n: n! = n × (n − 1)!. And 0! = 1 is known without any computation. These are the two cases of every recursive function:

base case

The answer is known directly, without any new call: fact 0 is 1.

Also called the stopping case.

recursive case

The problem is expressed with the same problem, only smaller: fact n is n * fact (n-1).

This is the “recurrence equation”.

In Caml, a function that calls itself is defined with let rec:

# let rec fact n =
    if n = 0 then
      1
    else
      n * fact (n-1) ;;
val fact : int -> int = <fun>
# fact 5 ;;
- : int = 120

The Caml answer does not mention rec: it is val fact : int -> int = <fun>, as for any other function. This is what you copy under your function at the exam.

The Moodle method Moodle · advice on recursion In this order:

  1. The specifications. What exactly must the function do? Its parameters (their meaning, their type), the nature of the result, the calling conditions (n ≥ 0…): this is the “user manual”.

  2. The principle and the cases. “I have already seen something similar” gives the structure. Write it as a function with holes: the different cases, and the answer for each one.

  3. The recurrence equation. The base case is the stopping case; the recursive cases express the problem with the same, smaller problem (n-1, n/10, n/2…).

  4. The checks. Does every call get closer to a base case (part 8)? Are the special cases handled? Is a wrapper function needed (part 3)?

Example seminar · ex. 4.2 The sequence defined by u0 = 1 and un = 4un−1 + 2.

  • Specifications: seq n returns un, for an integer n ≥ 0. Expected type: int -> int.
  • Base case: n = 0, the answer is 1.
  • Recursive case: un is computed from un−1, that is 4 * seq (n-1) + 2.
# let rec seq n =
    if n = 0 then
      1
    else
      4 * seq (n-1) + 2 ;;
val seq : int -> int = <fun>
# seq 0 ;;
- : int = 1
# seq 3 ;;
- : int = 106

Check by hand: u1 = 6, u2 = 26, u3 = 4 × 26 + 2 = 106. Same pattern for the geometric sequence of exercise 4.3, with first term u0 and common ratio q:

# let rec geo u0 q n =
    if n = 0 then
      u0
    else
      q *. geo u0 q (n-1) ;;
val geo : float -> float -> int -> float = <fun>
# geo 3. 2. 4 ;;
- : float = 48.

u0 and q do not change from one call to the next; only n decreases. Part 3 shows how to avoid passing them again at every call.

Remember
  • Every recursive function has at least one base case and at least one recursive case. The base case is tested first.
  • The recursive case calls the function on a smaller piece of data, one that gets closer to the base case.
  • Both cases have the same type, like the two branches of an if: it is the type of the result.
Trap: the missing rec 
# let sum n =
    if n = 0 then
      0
    else
      n + sum (n-1) ;;
Error: Unbound value sum
Hint: If this is a recursive definition,
you should add the 'rec' keyword on line 1

Without rec, the name sum does not exist yet during its own definition. Worse: if a sum already existed, Caml would take it without a word, and your function would call the old one.

Part 2

Evaluating a recursive call: the call stack

What does Caml do when you ask for fact 4? It replaces the call with the body of the function: 4 * fact 3. It cannot multiply yet: it first needs fact 3. The call fact 4 waits, and so on down to the base case:

fact 4 = 4 * fact 3
       = 4 * (3 * fact 2)
       = 4 * (3 * (2 * fact 1))
       = 4 * (3 * (2 * (1 * fact 0)))
       = 4 * (3 * (2 * (1 * 1)))
       = 24

The waiting calls form a stack: the last call is on top. On the way down, the stack fills up, one call per level. At the base case, fact 0 returns 1 without any new call. On the way back up, each call receives the value of the one above it, finishes its multiplication and leaves the stack. Go step by step:

Remember
  • A call only ends after all the calls it started. The multiplications of fact are done on the way back up, in the reverse order of the calls: 1 × 1, then 2 × 1, 3 × 2, 4 × 6.
  • fact n makes n + 1 calls, and the stack holds up to n + 1 of them at once. Its size is limited: a recursion that never stops makes it overflow (part 8).
  • Each call has its own parameters: the n of fact 3 is 3, the one of fact 4 is still 4.

Before or after the call? seminar · ex. 4.1 The seminar shows it with a little imperative code: print_int displays an integer, print_char a character, e1; e2 evaluates e1 then e2 (a sequence, wrapped in begin … end), and () is the value “nothing”, of type unit. These predefined functions are not used at the exam; here, they show the order of the computations. Guess what is displayed:

# let rec print1 n =
    if n = 0 then
      ()
    else
      begin
        print_int n; print_char ' ';
        print1 (n-1)
      end ;;
val print1 : int -> unit = <fun>
# print1 5 ;;
5 4 3 2 1 - : unit = ()
# let rec print2 n =
    if n = 0 then
      ()
    else
      begin
        print2 (n-1);
        print_int n; print_char ' ';
      end ;;
val print2 : int -> unit = <fun>
# print2 5 ;;
1 2 3 4 5 - : unit = ()

In print1, the display comes before the recursive call: it happens on the way down, from 5 to 1. In print2, it comes after: each call waits until print2 (n-1) is over before displaying its n, so the display happens on the way back up, from 1 to 5. The Caml answer, - : unit = (), comes after what is displayed, on the same line.

Your turn seminar · ex. 4.1 What do these functions compute? Unfold one call by hand, like fact 4 above, then type the Caml answer. This is the “Mystery” exercise of the exam.

# let rec f3 d n =
    if n <= 1 then
      d
    else
      d * f3 (d - 1) (n - 1) ;;
val f3 : int -> int -> int = <fun>
# f3 5 3 ;;
- : int = 60
# let rec f4 n =
    if n <= 0 then 0
    else
      let r = f4 (n - 1) in
      if n mod 4 = 0 then r + n else r ;;
val f4 : int -> int = <fun>
# f4 12 ;;
- : int = 24

f3 d n multiplies n factors, starting from d and going down: f3 5 3 = 5 × 4 × 3 = 60. f4 n adds up the multiples of 4 up to n: 4 + 8 + 12 = 24. In f4, let r = f4 (n - 1) in makes the call first; adding n or not happens on the way back up.

Trap: the value of the base case is not the result

fact 0 returns 1, but fact 4 is 24: the value of the base case goes back to the call above, which transforms it, and so on up to the first call. For a “Mystery”, go down to the base case, then all the way back up: do not stop at the value of the base case. The only exception is the accumulator (part 4): its base case does return the final result.

Part 3

Wrapper functions: check only once

The factorial of part 1 assumes n ≥ 0. With a negative number, n goes from −1 to −2, −3… and is never 0: the recursion never stops, until the stack overflows.

# let rec fact n =
    if n = 0 then
      1
    else
      n * fact (n-1) ;;
val fact : int -> int = <fun>
# fact (-1) ;;
Stack overflow during evaluation (looping recursion?).

Invalid parameters must be rejected with invalid_arg (chapter 1, part 5). First idea Moodle · advice on recursion: test n < 0 inside the function.

# let rec fact n =
    if n < 0 then
      invalid_arg "fact: n is not a natural"
    else
      if n = 0 then
        1
      else
        n * fact (n-1) ;;
val fact : int -> int = <fun>

It is correct, but the test n < 0 is only useful at the first call: after that, n-1 comes from a strictly positive n, so it can no longer be negative. Yet the test is done again at every call: 2n tests instead of n, as the Moodle page notes.

The wrapper function checks the parameters only once, then calls a local recursive function, defined with let rec … in, which only does the computation:

# let fact n =
    if n < 0 then
      invalid_arg "fact: n is not a natural"
    else
      let rec fact_rec = function
          0 -> 1
        | n -> n * fact_rec (n-1)
      in
        fact_rec n ;;
val fact : int -> int = <fun>
# fact 5 ;;
- : int = 120
# fact (-3) ;;
Exception: Invalid_argument "fact: n is not a natural".
Remember: the shape of a wrapper function 
let f n =
  if n < 0 then                  (* the invalid parameters *)
    invalid_arg "f: n < 0"
  else
    let rec f_rec n =            (* the computation only *)
      …
    in
      f_rec n                    (* the call, with the starting values *)
  • The wrapper function is not recursive: let f, without rec. The local function is: let rec f_rec … in.
  • The local function sees the parameters of the wrapper function: those that do not change from one call to the next do not need to be passed again.
  • The Caml answer only shows the wrapper function, val fact : int -> int = <fun>: the local function does not exist outside it.

Getting rid of the special cases Moodle · advice on recursion The Moodle page computes x × y in ℤ with additions (seminar, exercise 4.6). Its local function mult_rec has only one parameter, y: x never changes, so it takes it from the wrapper function. It only works for y ≥ 0; rather than a second recursive function for negative numbers, the wrapper function calls it with -y and changes the sign of the result. But the page has a typo: copied as it is, its function is rejected.

# let multiply x y =
    let rec mult_rec = function
        0 -> 0
      | y -> x + mult_rec (x, y-1)
    in
    match x with
      0 -> 0
    | 1 -> y
    | x ->
        if y < 0 then
          -mult_rec (-y)
        else
          mult_rec y ;;
Error: This expression has type 'a * 'b
       but an expression was expected of type int

mult_rec takes a single integer, and the page gives it a pair, (x, y-1). Corrected: mult_rec (y-1).

# let multiply x y =
    let rec mult_rec = function
        0 -> 0
      | y -> x + mult_rec (y-1)
    in
    match x with
      0 -> 0
    | 1 -> y
    | x ->
        if y < 0 then
          -mult_rec (-y)
        else
          mult_rec y ;;
val multiply : int -> int -> int = <fun>
# multiply 7 (-3) ;;
- : int = -21
# multiply (-2) 6 ;;
- : int = -12

The cases x = 0 and x = 1 are settled without any recursive call, and the sign of y is tested only once. The function f2 of the seminar (exercise 4.1) tests n < 0 at every call: it too would gain from a wrapper function.

Part 4

Extra parameters: accumulator and counter

Sometimes the recursive function needs information that the requested function does not have as a parameter. The Moodle page lists three kinds: an accumulator, in which the result is built call after call; information carried along as the recursion moves forward (the largest value seen so far, for example); a counter or an index, often 0 or 1 at the first call. The wrapper function calls the recursive function with the right starting value.

An accumulator seminar · ex. 4.1 What does f compute?

# let f n =
    let rec g n acc =
      if n = 0 then
        acc
      else
        g (n-1) (acc * 10 + 1)
      in
        g n 0 ;;
val f : int -> int = <fun>
# f 4 ;;
- : int = 1111
# f 0 ;;
- : int = 0

g adds a digit 1 to the right of acc at each call: 0, 1, 11, 111, 1111. When n is 0, the result is already built: the base case returns acc. The computation happens on the way down, and the way back up changes nothing.

The mirror of an integer seminar · ex. 4.9 reverse_int 1234 must return 4321. With pure recursion, you would have to put the 4 in front of the mirror of 123, so you would need the number of digits. With an accumulator, it is direct: take the last digit off n (n mod 10) and push it to the right of the accumulator (acc * 10 + …).

# let reverse_int n =
    if n < 0 then
      invalid_arg "reverse_int: n < 0"
    else
      let rec rev acc n =
        if n = 0 then
          acc
        else
          rev (acc * 10 + n mod 10) (n / 10)
      in
        rev 0 n ;;
val reverse_int : int -> int = <fun>
# reverse_int 1234 ;;
- : int = 4321
# reverse_int 1200 ;;
- : int = 21

Compare with the stack of fact 4 (part 2): here, no call has a computation waiting. Each one returns, as it is, what the next one returns, and the last one returns the accumulator. reverse_int 1200 is 21: the leading zeros of an integer disappear (the seminar version that returns a string gives "0021").

A counter seminar · ex. 4.13 The sum of the divisors of n smaller than n. The local function tries each possible divisor d, from 1 to n − 1: d is a counter, which starts at 1.

# let sum_divisors n =
    if n <= 0 then
      invalid_arg "sum_divisors: n <= 0"
    else
      let rec sum d =
        if d >= n then
          0
        else
          if n mod d = 0 then
            d + sum (d + 1)
          else
            sum (d + 1)
      in
        sum 1 ;;
val sum_divisors : int -> int = <fun>
# sum_divisors 28 ;;
- : int = 28
# sum_divisors 12 ;;
- : int = 16
# let is_perfect n =
    n > 1 && sum_divisors n = n ;;
val is_perfect : int -> bool = <fun>
# is_perfect 28 ;;
- : bool = true
# is_perfect 0 ;;
- : bool = false

A number is perfect if it is greater than 1 and equal to the sum of its proper divisors: 28 = 1 + 2 + 4 + 7 + 14. is_perfect reuses sum_divisors, and && stops as soon as n > 1 is false: is_perfect 0 is false without raising the exception of sum_divisors.

Remember: pure recursion first

The Moodle page “Advice on lists” is clear: try pure recursion first. The accumulator? “Careful: most of the time, this method is not necessary. It only makes things more complicated, and you risk getting a result different from the one asked for.” In chapter 3, an accumulator reverses the order of a list.

At the exam

  • October 2023, split: a paper marked 6 out of 8 built its pieces with an accumulator, and they came out in reverse order. The statement had announced the penalty.
Trap: the starting value 
# let fact n =
    let rec f acc n =
      if n = 0 then
        acc
      else
        f (acc * n) (n-1)
    in
      f 0 n ;;
val fact : int -> int = <fun>
# fact 5 ;;
- : int = 0

A product that starts at 0 stays at 0. The starting value of an accumulator is the neutral element of the computation: 0 for a sum, 1 for a product. Check it on the smallest case: fact 0 must be 1, and that is exactly the starting value of acc. You need f 1 n.

Recursion on integers: digits, gcd, power

The seminar practises on integers (exercises 4.2 to 4.13). The reasoning is always the same; what changes is how the problem is made smaller:

The computation is aboutSmaller problemBase caseSeminar
n: sequence, sum, productn-1n = 04.2, 4.3

The digits of an integer. The last digit of n is n mod 10, and n / 10 removes this digit. The sum of the digits, then the digital root: start again as long as more than one digit is left.

# let rec sum_digits n =
    if n < 10 then
      n
    else
      n mod 10 + sum_digits (n / 10) ;;
val sum_digits : int -> int = <fun>
# sum_digits 2026 ;;
- : int = 10
# let rec digital_root n =
    if n < 10 then
      n
    else
      digital_root (sum_digits n) ;;
val digital_root : int -> int = <fun>
# digital_root 2026 ;;
- : int = 1

digital_root calls sum_digits, then calls itself on the result: 2026, then 10, then 1. It terminates, because the sum of the digits of a number with at least two digits is smaller than the number.

The gcd seminar · ex. 4.4 Euclid’s algorithm: if b divides a, the gcd is b; otherwise, it is the gcd of b and of the remainder a mod b. The exercise is about non-zero natural numbers: the wrapper function checks it.

# let gcd a b =
    if a <= 0 || b <= 0 then
      invalid_arg "gcd: a and b must be > 0"
    else
      let rec euclid a b =
        if a mod b = 0 then
          b
        else
          euclid b (a mod b)
      in
        euclid a b ;;
val gcd : int -> int -> int = <fun>
# gcd 150 45 ;;
- : int = 15
# gcd 45 150 ;;
- : int = 15
# gcd 0 5 ;;
Exception: Invalid_argument "gcd: a and b must be > 0".

No need to order a and b: if a < b, a mod b is a, and the first call swaps them. Without the wrapper function, euclid 5 0 would raise Exception: Division_by_zero.

Power and division seminar · ex. 4.10 and 4.7 xn = x × xn−1, for a real number x: mind the float operators. Then the quotient and the remainder of a by b, with subtractions and a single recursive function, which returns a pair:

# let rec power x n =
    if n = 0 then
      1.
    else
      x *. power x (n-1) ;;
val power : float -> int -> float = <fun>
# power 2. 10 ;;
- : float = 1024.
# let euclid_div a b =
    if a < 0 || b <= 0 then
      invalid_arg "euclid_div: a < 0 or b <= 0"
    else
      let rec div a =
        if a < b then
          (0, a)
        else
          let (q, r) = div (a - b) in
            (q + 1, r)
      in
        div a ;;
val euclid_div : int -> int -> int * int = <fun>
# euclid_div 17 5 ;;
- : int * int = (3, 2)
# euclid_div 3 5 ;;
- : int * int = (0, 3)

17 = 5 × 3 + 2: 5 is taken away three times before going below 5. Each call gets the pair of the next call with let (q, r) = … in and adds 1 to the quotient. Like mult_rec (part 3), the local function div only takes a: b does not change.

  • This chapter is used everywhere, though. A function on a list follows the same reasoning: base case, recursive case, wrapper function, accumulator. And the seminar MCQs (30% of the grade) are about recursion too: it is the topic of MCQ 5.
  • Seven subjects out of nine have a “Mystery” exercise (2 to 4 points): read recursive code and give the Caml answers, as in part 2.

Part 6

Several recursive calls: Fibonacci, Hanoi

A function can call itself several times in the same case. The Fibonacci sequence of the seminar seminar · ex. 4.8: F(n) = 1 if n ≤ 1, and F(n) = F(n − 1) + F(n − 2) otherwise. The definition translates word for word:

# let rec fibo n =
    if n <= 1 then
      1
    else
      fibo (n-1) + fibo (n-2) ;;
val fibo : int -> int = <fun>
# fibo 5 ;;
- : int = 8
# fibo 10 ;;
- : int = 89

Each call that is not a base case starts two more: the calls no longer form a chain, but a tree. A call ends completely, with all its sub-calls, before the other one starts. Unfold fibo 5:

15 calls for fibo 5, while there are only six different values, from fibo 0 to fibo 5. The dashed calls redo a computation already done: fibo 3 is computed twice, fibo 2 three times. Part 7 fixes this.

The unfolder evaluates fibo (n-1) before fibo (n-2), in reading order. OCaml does not fix the evaluation order of the two sides of a +, and in practice starts with the right one: the result and the number of calls are the same.

The towers of Hanoi Moodle · Hanoi Three pegs, numbered 1, 2 and 3; n disks of different sizes, stacked on peg 1, from the largest at the bottom to the smallest on top. They must be taken to peg 3, one disk at a time, without ever putting a disk on a smaller one.

Recursive reasoning gives the solution without looking for the moves one by one. To move n disks from source to destination:

  1. move the n − 1 top disks to the third peg: the same problem, only smaller;

  2. move the large disk, now alone, to destination;

  3. move the n − 1 disks from the third peg to destination: the same problem again, only smaller.

With 0 disks, there is nothing to do: this is the base case. The pegs are 1, 2 and 3, which add up to 6: the third peg is 6 - source - destination. The page gives move, which displays one move, and the wrapper function; play is left to write (the FIXME of the page):

# let move source destination =
    print_int source ;
    print_string " -> " ;
    print_int destination ;
    print_newline() ;;
val move : int -> int -> unit = <fun>
# let hanoi n =
    let rec play n source destination =
      if n > 0 then
        let other = 6 - source - destination in
          begin
            play (n-1) source other ;
            move source destination ;
            play (n-1) other destination
          end
    in
      if n <= 0 then
        invalid_arg "Hanoi: number of disks invalid"
      else
        play n 1 3 ;;
val hanoi : int -> unit = <fun>
# hanoi 3 ;;
1 -> 3
1 -> 2
3 -> 2
1 -> 3
2 -> 1
2 -> 3
1 -> 3
- : unit = ()

This is exactly the display of the page. The body of play is an if without else: it is allowed here, because the function returns nothing (unit), it displays (chapter 1, part 4). The three steps form a sequence between begin and end, evaluated in order.

How many moves? The page asks the question: 1 move for one disk, 3 for two. The reasoning directly gives a recursive function: n − 1 disks, then the large one, then n − 1 disks again.

# let rec moves n =
    if n = 0 then
      0
    else
      2 * moves (n-1) + 1 ;;
val moves : int -> int = <fun>
# moves 3 ;;
- : int = 7
# moves 10 ;;
- : int = 1023

The number of moves almost doubles with each extra disk: 2n − 1. With the 64 disks of Édouard Lucas’s legend, 264 − 1 would be needed, more than 18 billion billion.

Remember
  • With two calls per case, the number of calls is multiplied at each level: it grows exponentially with n.
  • For Hanoi, this cannot be avoided: each displayed move has to be made. For Fibonacci, it can: the same values are computed again, and part 7 computes them only once.
  • The order of a sequence e1; e2; e3 is guaranteed: from left to right. The order of the two sides of fibo (n-1) + fibo (n-2) is not.
Trap: two calls do not mean twice as long

Two calls per case do not make twice as many calls as fact: fibo 5 makes 15 calls, fibo 25 makes 242,785, fibo 40 more than 331 million (part 7). Each level multiplies the number of calls of the previous level.

Part 7

Optimising: never repeat a computation, stop as soon as possible

The course sheet sets three complexity rules: “avoid useless computations, do not repeat computations, stop as soon as an answer is given”. A function can give the right result and break all three: this part shows how to follow them.

Never repeat a computation. How many calls does fibo n make? A recursive function of the same shape tells you: one call, plus those of the two sub-calls.

# let rec calls n =
    if n <= 1 then
      1
    else
      1 + calls (n-1) + calls (n-2) ;;
val calls : int -> int = <fun>
# calls 5 ;;
- : int = 15
# calls 25 ;;
- : int = 242785
# calls 40 ;;
- : int = 331160281

More than 331 million calls for fibo 40, which only needs 41 values. The solution: compute each value only once, by carrying the last two terms of the sequence in extra parameters (part 4).

# let fibo n =
    if n < 0 then
      invalid_arg "fibo: n < 0"
    else
      let rec fib a b n =
        if n = 0 then
          a
        else
          fib b (a + b) (n-1)
      in
        fib 1 1 n ;;
val fibo : int -> int = <fun>
# fibo 10 ;;
- : int = 89
# fibo 50 ;;
- : int = 20365011074

a and b are two consecutive terms of the sequence; at each call, the sequence moves one term forward: (a, b) becomes (b, a + b). fibo 50 makes 51 calls and answers at once; the first version would make more than 40 billion.

A call repeated in an if. The largest digit of an integer: compare the last digit with the largest digit of the rest.

# let rec max_digit n =
    if n < 10 then
      n
    else
      if n mod 10 > max_digit (n / 10) then
        n mod 10
      else
        max_digit (n / 10) ;;
val max_digit : int -> int = <fun>
# max_digit 2026 ;;
- : int = 6
# let rec max_digit n =
    if n < 10 then
      n
    else
      let m = max_digit (n / 10) in
        if n mod 10 > m then
          n mod 10
        else
          m ;;
val max_digit : int -> int = <fun>
# max_digit 2026 ;;
- : int = 6

Both versions return 6. But the first one writes max_digit (n / 10) twice: when the test is false, the same call is made again in full, and each of them can split in two in turn. On a 10-digit integer such as 9876543210, this makes 1,023 calls instead of 10. A let … in names the result to reuse it. In chapter 3, the maximum of a list sets the same trap.

Fast exponentiation seminar · ex. 4.10 xn = (xn/2)² if n is even, and x × (xn/2)² otherwise, with n/2 an integer division. The square is computed with a single call, named p:

# let rec fast_power x n =
    if n = 0 then
      1.
    else
      let p = fast_power x (n / 2) in
        if n mod 2 = 0 then
          p *. p
        else
          x *. p *. p ;;
val fast_power : float -> int -> float = <fun>
# fast_power 2. 10 ;;
- : float = 1024.
# fast_power 1.5 3 ;;
- : float = 3.375

For n = 1,000: 11 calls, against 1,001 for power (part 5). Writing fast_power x (n / 2) *. fast_power x (n / 2) would do every computation twice: 2,047 calls, worse than the classic version.

Stop as soon as the answer is known seminar · ex. 4.12 An integer n > 1 is prime if it has no divisor between 2 and n − 1. Two savings: stop at the first divisor found, since the answer is then false; and do not look beyond √n, because if n = d × e with d ≤ e, then d × d ≤ n.

# let is_prime n =
    if n <= 1 then
      invalid_arg "is_prime: n <= 1"
    else
      let rec no_divisor d =
        if d * d > n then
          true
        else
          if n mod d = 0 then
            false
          else
            no_divisor (d + 1)
      in
        no_divisor 2 ;;
val is_prime : int -> bool = <fun>
# is_prime 97 ;;
- : bool = true
# is_prime 91 ;;
- : bool = false
# is_prime 1 ;;
Exception: Invalid_argument "is_prime: n <= 1".

For 1,000,003, which is prime, no_divisor makes 1,000 calls instead of a million; for 1,000,000, a single one. The two base cases come before the recursive case, and the test d * d > n avoids sqrt, a predefined function. With || and &&, which stop as soon as the result is known (chapter 1, part 1), the same function fits on one line:

# let is_prime n =
    if n <= 1 then
      invalid_arg "is_prime: n <= 1"
    else
      let rec no_divisor d =
        d * d > n || (n mod d <> 0 && no_divisor (d + 1))
      in
        no_divisor 2 ;;
val is_prime : int -> bool = <fun>
# is_prime 91 ;;
- : bool = false
Remember: the three rules
  • Avoid useless computations: test the parameters only once (wrapper function, part 3), settle the simple cases without any call (multiply).
  • Never repeat a computation: a result used twice is named with let … in; a value you would compute again is carried in a parameter.
  • Stop as soon as the answer is known: one more base case (found, property false), or && and ||.
At the exam

Eight subjects out of nine (2017 to 2024) ask for a function that can stop before the end of the list: look for an element, check a property, go through a sorted list. The Moodle page “Advice on lists” says so: a partial traversal has at least one base case other than the empty list. Chapter 3 applies it.

Trap: a let … in too early 
# let is_prime n =
    if n <= 1 then
      invalid_arg "is_prime: n <= 1"
    else
      let rec no_divisor d =
        if d * d > n then
          true
        else
          let rest = no_divisor (d + 1) in
            n mod d <> 0 && rest
      in
        no_divisor 2 ;;
val is_prime : int -> bool = <fun>
# is_prime 1000000 ;;
- : bool = false

The result is right, but rest is computed before the test: the function always goes up to √n, that is 1,000 calls for 1,000,000 instead of one. A let … in avoids repeating a computation; placed too early, it does a computation that may not be needed. Write the call where its value is used.

Part 8

Termination and frequent mistakes

A recursive function terminates if each call gets closer to a base case and finally reaches it, for every allowed parameter. “Smaller” is not enough: you have to land on the base case. The seminar asks for it: “study all the cases”. Do these calls terminate?

# let rec f1 n = match n with
      0 -> 0
    | n -> n + f1 (n-1) ;;
val f1 : int -> int = <fun>
# f1 (-1) ;;
Stack overflow during evaluation (looping recursion?).
# let rec halve n =
    if n = 0 then
      0
    else
      1 + halve (n - 2) ;;
val halve : int -> int = <fun>
# halve 6 ;;
- : int = 3
# halve 7 ;;
Stack overflow during evaluation (looping recursion?).

When a recursion does not stop, the call stack grows until it overflows: Caml answers Stack overflow during evaluation (looping recursion?). With f1 (-1), n goes down without ever being 0. With halve 7, n is 7, 5, 3, 1, −1…: it jumps over 0. Two remedies: a base case that covers everything left (n <= 0, n < 2), or a wrapper function that rejects the parameters outside the domain.

The case of double · seminar, exercise 4.1 
# let rec double = function
      0 -> 0
    | n -> n / 2 + double (2*n) ;;
val double : int -> int = <fun>
# double 0 ;;
- : int = 0
# double 1 ;;
- : int = -1

For n ≠ 0, 2*n moves away from 0: mathematically, double n does not terminate, and this is the answer expected at the seminar. Yet Caml answers −1. Its integers are bounded (max_int is 262 − 1): by dint of doubling, 2*n goes past the bound, and the computation ends up giving 0, which stops the recursion. This −1 means nothing: only the reasoning counts.

# let rec f1 n = match n with
      n -> n + f1 (n-1)

# let rec power x n =
    if n = 0 then
      1
    else
      x *. power x (n-1) ;;
Error: This expression has type int but an expression was expected of type
         float
# let rec count_digits n =
    if n = 0 then
      0
    else
      1 + count_digits (n / 10) ;;
val count_digits : int -> int = <fun>
# count_digits 0 ;;
- : int = 0
  • Patterns are tried in order: n matches everything, the case 0 placed after it is never used, and f1 3 does not stop. The warning says so: the base case comes first.
  • The base case and the recursive case have the same type: 1., not 1, when the result is a float.
  • count_digits 0 returns 0, but 0 is written with one digit. Test the smallest case: the right base case is n < 10, which returns 1. This is mystery, at the top of the chapter.

Before handing in a recursive function:

  1. The specifications come from the statement and the examples: name, order and type of the parameters, type of the result, exception and its message.

  2. The base case is tested first, and checked on the smallest example.

  3. The recursive case calls the function on a smaller piece of data, in brackets.

  4. Termination is ensured for every allowed parameter; the others are rejected by the wrapper function.

  5. No repeated or useless computation, and a stop as soon as the answer is known.

  6. The Caml answer follows the function: val fact : int -> int = <fun>, without rec.
